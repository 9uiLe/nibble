# nibbleの検証とレビュー

規約は[開発ガイド](../../../CONTRIBUTING.md)、自動検査の使い方と限界は[証跡とPRの検査](../../../docs/review-evidence.md)を読む。依頼された作業に必要な部分だけ適用する。PR作成の依頼はマージやリポジトリ権限の変更を含まない。

## 対象と期待結果を決める

- 製品は`app/project.json`と[製品手順](../../../docs/mvp.md)、基盤は`validation/project.json`と[共通手順](../../../docs/ios-verification.md)、比較実験は`validation/research-project.json`と[研究手順](../../../validation/RESEARCH.md)。fixtureや比較実験の成功を製品の成功として報告しない。
- 操作APIは直接awaitし、戻った時点の状態と永続化を検査する。タスクの重複・キャンセル・寿命は所有者を対象に検査する。View比較は各入力の変更と復元に加え、入力が同一でも外観・Dynamic Typeが更新されることを確認する。
- 設計文書は目的、採用構成、責務、契約、制約から説明する。候補・採用・検証済みを区別し、run IDと失敗経過は検証記録へ置く。過去の会話や「変更前の設計」を知らなくても実装判断できる記述にする。

## ローカルで検証する

共通手順のApple CLIとNixのsim-useを使用し、明示したiOS 26.5のUDIDを直列に操作する。作業中のソースと撮影したバイナリがずれるため、runの途中で製品・テスト・driver・ツール設定を編集しない。

- `sim-use ui`の新しい結果から対象を選ぶ。識別には`uniqueId`、原文比較には`value`を使う。outlineの見た目だけでコピーの一致を判定しない。
- 作成した項目は一意なダミー検索語とUUIDで追跡する。画面内の行数や「新しく見えた行」に依存しない。編集後のコピーは空白・改行・結合文字を含むUTF-8、削除取り消しは同じUUIDで照合する。
- 日本語ペーストとIME変換の検証を区別する。`paste --replace`の日本語メニュー問題は製品driverの限定的なfallbackを使う。任意の非ゼロ終了を無視しない。
- Simulatorが応答しない場合はログを残し、Apple CLIの端末状態とSettings等のhost操作で製品固有か切り分ける。同じ失敗を繰り返さず、必要なら専用Simulatorを新規作成する。ユーザーの端末をeraseしない。
- Xcodeのマクロ未承認は固定revisionを確認して対象パッケージを承認する手順へ進む。一括でマクロ検証を無効にしない。
- DerivedDataはコンパイルcacheとして使い、対象destinationでビルドする。別runのアプリをinstallしただけでは現ソースの検証にならない。現行driverには任意のビルドを再利用して成功認定する入口を設けていない。

## 証跡を確認して公開する

1. `check_evidence.py --integrity-only`でrunの成否・ソース・媒体の一致を調べる。失敗runは残し、別runの成功で上書きしない。
2. 画像を開き、録画は必要な範囲を再生またはフレーム抽出で確認する。`--init-review`で作った`review.json`に、実際の観測、抽出時刻、未確認条件を記録する。抽出3フレームの確認を全編再生と記載しない。
3. アップロード前に媒体がダミーデータであることを確認する。`nix develop --command gh pr create --help`で`--attach`の有無を確認し、利用可能なら原本を添付する。対応しない場合はGitHubのブラウザー添付を使う。
4. アップロード後の本文をGitHubから取得する。ローカルパスの本文で編集し直すと添付先を失うため、取得した本文を編集元にする。画像は読込サイズ、動画はプレーヤーの読込状態もブラウザーで確認し、閲覧範囲を記録する。未認証HEADの403だけで添付失敗と判定しない。
5. 安定した添付URLを`review.json`に記載し、`check_evidence.py`で照合・`REVIEW.md`生成を行う。ブラウザー用の一時署名URLは保存しない。原本とブラウザーで動画時間が異なる場合はそれぞれの観測として扱う。

## PRを整える

- `check_pr.py commits --base origin/main`で全コミット表を生成し、説明を目的に沿って編集する。本文はファイルに保存し、`gh pr create/edit --body-file`で実際の改行を保持する。
- `check_pr.py local`で本文を検査してから作成・更新する。pushや本文編集後は`remote --complete --check-ci`で現在のheadと全コミットを確認する。実行中のCI自身から`--check-ci`を呼ばない。
- 性能改善は同条件の測定結果に基づいて述べる。操作driverの待機を含む録画時間、比較コードの存在、画像一致だけで高速化を主張しない。UX・アクセシビリティ・性能の未完了事項は明記し、完了チェックを付けない。
