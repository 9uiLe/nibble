# nibbleの検証とレビュー

このSkillは、nibbleの実行結果を対象ソースと対応付け、レビューやPRに必要な証跡を用意するための入口である。エージェント間・モデル間で同じ手順を使う。開発規約は[開発ガイド](../../../CONTRIBUTING.md)、コマンドと合格条件は[証跡とPRの検査](../../../docs/review-evidence.md)を正本とする。

runは、1回のiOS検証で記録するソース・端末・コマンド・成否・媒体のまとまりを指す。実行条件は`manifest.json`、確認者の観測と閲覧条件は`review.json`、共有用の説明は`REVIEW.md`に記録する。

## 工程と適用範囲

依頼された成果物に対応する工程を選ぶ。ローカル検証、媒体公開、PR作成は独立した作業範囲であり、PR作成の依頼にマージやリポジトリ権限変更は含まれない。承認済みの範囲では工程ごとの確認を挟まず進める。

| 作業 | 必要な入力 | 読む手順と成果物 |
| --- | --- | --- |
| iOSのビルド・テスト・画面操作 | 対象project、期待結果、iOS 26.5の専用UDID | [対象選択と実行](references/local-ios.md)。ソース・実行結果を持つrunを`artifacts/`へ保存。画面確認時は画像・録画も記録 |
| runの確認・再利用 | runディレクトリ、照合先のGit revision | [ソースと結果の照合](../../../docs/review-evidence.md#runのソースと結果)。`check_evidence.py --integrity-only`の結果 |
| 画像・録画のレビューと共有 | 照合済みrun、確認範囲、公開が依頼されている場合は保存先 | [媒体のレビュー記録](../../../docs/review-evidence.md#画像動画のレビュー記録)。実際の観測を`review.json`へ記録し、公開・閲覧確認後の証跡検査で`REVIEW.md`を生成 |
| PR作成・更新 | base/head、全コミット、検証結果、UIに影響する場合は証跡 | [PR本文の作成と照合](../../../docs/review-evidence.md#pr本文の作成と照合)と[PRテンプレート](../../../.github/pull_request_template.md)。本文と最終headの検査結果 |

文書だけのPRは共通検査と本文の照合を行い、証跡欄にiOS実行・撮影が対象外である理由を記載する。runを再利用する場合は文書変更でもファイル照合が必要となる。TestFlightのアップロードは[配布手順](../../../docs/testflight.md)が担当し、PR・媒体公開はそれぞれ依頼がある場合に行う。

## 証跡の記録と公開

- 自動実行の成功、動画デコード、抽出フレーム確認、全編再生、アップロード、ブラウザーでの閲覧は別の確認。観測・抽出時刻・未確認条件を記録し、未実施を完了へ変えない。失敗runは保存し、成功runで上書きしない。
- `--init-review`は記入欄の生成だけであり、合格判定ではない。ローカル確認のみなら公開・閲覧欄を未完了として残し、公開用の完全な証跡検査を通したと報告しない。
- 媒体公開時はダミーデータであることを確認する。CLI添付の可否、ブラウザー添付、安定したURL、画像・動画の読込確認は「証跡とPRの検査」の媒体公開手順に従う。未認証HEADの403だけで添付失敗と判定しない。
- アップロード後の本文をGitHubから取得し、それを編集元にして添付URLを保持する。原本とブラウザーの動画時間が異なる場合はそれぞれの観測として扱う。

## PRの整合性

- `check_pr.py commits --base origin/main`で全コミット表を生成し、目的に沿って説明する。本文はファイルに保存し、`gh pr create/edit --body-file`で改行を保持する。
- コミット済みの差分を`check_pr.py local --complete`、push・本文編集後を`remote --complete --check-ci`で照合する。実行中のCI自身から`--check-ci`を呼ばない。
- 性能改善は同条件の測定結果に基づいて述べる。driverの待機を含む録画時間、比較コードの存在、画像一致だけで高速化を主張しない。UX・アクセシビリティ・性能の未完了事項を明記し、完了チェックを付けない。

## 完了条件

選んだ工程の成果物をそろえ、成否と未実施条件を報告する。自動検査は記録の整合性と申告の形式を確認し、レビューは影響する導線の検証、媒体の内容、実際の閲覧、変更目的の一貫性を判断する。未確認の条件を検証済みと扱わず、マージ条件に不足があればマージ可能と報告しない。
