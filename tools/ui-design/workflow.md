# UI/UXの設計と評価

この手順は、利用者の目的から画面・部品・配置を決め、その理由と成立条件を継続して確認するためのものである。対象は製品のUIを設計・実装・レビューする人。設計資料、製品コード、検証記録を一つの変更単位として扱う。

## 記録の役割

| 記録 | 答える問い |
| --- | --- |
| [共通原則](templates/foundations.md) | 色、文字、寸法、状態、動きは何を意味し、どこで使うか |
| [画面構成](templates/screen.md) | 利用者は何を達成し、どの順に読み、操作し、どこへ戻るか |
| [部品台帳](templates/components.md) | 各要素は何を担い、なぜその位置・形・順序なのか |
| [根拠資料](templates/evidence.md) | どの指針を読み、どの条件で製品へ適用するか |
| [判断記録](templates/decision.md) | どの候補を比較し、何を優先して採用したか |
| [監査](templates/audit.md) | 対象実装にどの不足・未評価条件があり、何を確かめるか |

設計IDは意味と責務を識別する。実装の型を分割・改名しても、利用者にとっての責務が同じなら同じIDを使う。テンプレートは記載項目のひな形であり、採用仕様は製品の台帳で管理する。

## 判断の根拠

各画面・部品には、目的、構成、配置理由、代替案の利点と負担、評価条件を記す。根拠は次の4種類に分ける。

| 種類 | 必要な情報 |
| --- | --- |
| 外部指針 | 発行主体、出典、確認日、読んだ範囲、適用する環境と限界 |
| 製品判断 | 利用場面と制約、選んだ案、優先した価値、代替案との負担の比較 |
| 仮説 | 期待する効果、その効果を確かめる条件、再検討の条件 |
| 観測 | 対象ソース、環境、データ、手順、結果、未実施項目 |

外部指針は製品の採用判断を支える資料である。寸法や待ち時間などの値は、操作の意味・到達性・可読性・保存や回復の制約に結び付けて選ぶ。効果を観測するまでは仮説として扱う。

## 設計から評価まで

```mermaid
flowchart LR
    A[利用場面と達成条件] --> B[画面と部品の責務]
    B --> C[根拠と候補の比較]
    C --> D[対象環境での試作・実装]
    D --> E[操作・表示・回復の評価]
    E --> F[仕様・観測・照合記録]
```

| 段階 | 作業 | 次へ進む条件 |
| --- | --- | --- |
| 利用場面 | 利用者、目的、対象データ、利用環境、操作後の復帰先を定める | 成功と失敗を観測できる達成条件がある |
| 構成 | 現在地、対象選択、内容、操作、結果を画面と部品へ割り当てる | 入力・待機・失敗・中断・復旧の状態と責務が明確 |
| 比較 | 根拠と制約を使い、配置・遷移・表現の候補を比較する | 採否と理由、未確認の仮説、評価条件を説明できる |
| 実装 | 状態の所有者、操作の完了、共通表現、実行環境の制約をコードへ反映する | 対象ソースと検証手順が特定できる |
| 評価 | 対象の識別、到達、入力保持、失敗からの回復、表示・入力条件への適応を確認する | 結果と未実施条件を実装状況と分けて記録できる |
| 照合 | 採用仕様、観測、未解決事項を資料へ反映し、実装との対応を確認する | 判断要約付きの照合記録と必須検査が成立する |

情報構造や操作の意味を決める選択には判断記録を作る。台帳で定めた契約内の調整は、対象の部品や共通原則へ理由を記す。

## 試作と比較の条件

情報の順序は構成図で整理し、入力・スクロール・素材・支援技術の挙動は対象環境の試作で確認する。補助的なデザインツールを使う場合は、比較目的と、採用結果を製品資料へ反映する担当を定める。

比較する案には同じデータ、表示条件、入力方法を使う。利用者の学習や試行順の影響を記録し、少数の観測はその参加者と利用場面の範囲で解釈する。性能は対象実装、指標、測定回数、集計方法を定めて評価する。

## 変更をレビューする手順

1. 対象のソース・設定・アセット・文書を、画面・部品・共通原則のIDへ対応させる。
2. 採用仕様と実装を照合する。仕様を変更する場合は台帳へ反映し、仕様を維持する場合もその根拠を要約する。未解決の不足は監査に残す。
3. 必要な実操作・テストを行い、対象ソースと条件を持つ検証記録を作る。
4. 確認文書と判断要約を指定して照合記録の候補を生成し、差分をレビューして反映する。
5. 必須CIで`check`を実行する。設定の追加・除外・対象変更もレビューに含める。

照合の操作と設定形式は[ツールキットのInterface](README.md#interface)に定める。機械検査は未確認のファイル変更とIDの不整合を扱い、理由の妥当性と使いやすさはレビュー・実操作・利用者評価が担当する。
