# 製品の検証計画

製品MVPの採用構成は[ADR 0002](../docs/decisions/0002-mvp-app.md)、実装と操作は[MVP手順](../docs/mvp.md)に記録する。この研究資料は各選択肢の根拠と評価条件を管理し、MVPの範囲を超える入口・同期・配布等の判断にも使う。

この計画は、nibbleの利用場面に合う呼び出し・保存・検索・表示・保護・配布の構成を選ぶための評価条件を定める。製品の価値基準は、必要な本文を素早く使えること、作成・編集・削除を迷わず行えること、入力と描画を待たせないことである。

最低対応OSは**iOS 26.0**、実行検証は**iOS 26.5のみ**。26.0への適合はdeployment targetと個別APIのavailabilityで点検する。

## 評価の構成

検証計画の各領域をV0〜V8、[ResearchProbeの実行結果](experiments/ios-26-5-validation.md)をE01〜E25、[一次資料の確認](experiments/primary-source-validation.md)をP01〜P13で識別する。採用判断は、文書上の契約、比較試作の観測、対象シーンでの体験を照合して行う。

| 対象 | 評価すること | 実行方法 |
| --- | --- | --- |
| VerificationApp | 検証コマンド・文字列照合・撮影の成立 | [共通driverのtest / smoke](../docs/ios-verification.md) |
| ResearchProbe | 同じダミーデータによる保存3案、検索、移行・復旧、UI、OS連携の比較 | [研究用の構成と手順](../validation/RESEARCH.md) |
| 製品の本体・extension | 採用するhost・権限・データでの動作、実機の使いやすさ・性能、配布と運用 | 以下のV0〜V8に対応するtarget・設定・操作を定義 |

ResearchProbeのUIKit画面、明示保存、MainActorでの全件処理、1件の削除復元は比較条件である。製品の構成を決める際は、実機・権限・入力・復旧・保守の要件を満たすかを評価する。

## 製品として決めること

| 問い | 比較する選択肢 | 判断に必要な情報 |
| --- | --- | --- |
| 最初に解決する利用場面は何か | メッセージの定型文、メール、Web フォーム、コード等 | 実際に使う入力先、頻度、短文／長文、片手利用、既存の手順で困る点 |
| 「利用完了」はどこか | コピー完了、相手欄への挿入・ペースト、元の作業への復帰 | 利用者の目的に合う終点。コピー成功だけで挿入成功とは扱わない |
| 何をスニペットとして保存するか | plain text、書式付き、画像・ファイル、変数展開 | 原文維持、検索、共有形式、サイズと編集部品への影響 |
| 何から呼び出すか | 本体、Shortcuts / Controls、Share / Action、Keyboard、Widget | 対象シーンでの成功率と、初期設定・切り替え・保守の負担 |
| どう探すか | 本文／タイトル検索、固定項目、最近使った項目、分類 | 思い出せる情報、件数、日本語の短い検索、並び順の安定性 |
| どのように編集・削除を確定するか | 明示保存／自動保存、Undo／復元、下書き | 中断・保存失敗・誤削除から回復する体験とデータ保持 |
| 何を機密として守るか | 全項目同じ扱い／機密項目を区別 | ロック画面・キーボード・システム検索・コピー・export の露出範囲 |
| 同期は初期版に必要か | 端末内のみ／任意の端末間同期 | 複数端末の具体的な需要、アカウントと競合対応の運用負担 |

## 評価領域と依存関係

V0の利用場面が、V1の基本操作とV2の入口比較の条件になる。V2で必要となる権限とプロセス構成を、V3の保存・共有方式へ反映する。V4の日本語検索、V5の保護と復旧、V6の使いやすさと性能は、本体と各入口に共通の受け入れ条件とする。V7は同期の採用を検討する場合、V8は配布する構成に対して実施する。

| ID / 順序 | 確かめる問い | 最小の実験と条件 | 残す証拠・判断すること | 根拠 |
| --- | --- | --- | --- | --- |
| **V0：利用場面** | どの往復を短くすると価値があるか | 代表的な入力先を 2〜3 個選び、ダミーの定型文を現在の方法で利用する。初回設定と日常の利用を分け、作成・修正・誤削除からの復帰も観察する | タスク定義、操作列、総完了時間、迷い・失敗。初期版で解く場面と「利用完了」の終点 | [01](01-invocation-and-platform.md)、[03](03-ux-and-performance.md) |
| **V1：基本の往復** | 本体だけで気持ちよく作成・検索・コピー・復帰できるか | 本体でローカル CRUD と検索・コピーを通し、Notes / Safari 等の選んだ欄へ利用者がペーストする。空・少量・長文、cold / warm、オフライン、日本語変換、保存失敗を確認する | 動画、画面、区間別の測定値、本文一致、保存失敗時の下書き。追加導線を比較する基準と最初の性能予算案 | [02](02-data-and-architecture.md)、[03](03-ux-and-performance.md) |
| **V2：システムの入口** | 設定と切り替えの負担を含めても V1 より役立つか | 選んだシーンに合う入口を一つずつ試す。Shortcuts / Control の一覧・作成、Share / Action の取り込み、Full Access なし Keyboard の挿入を候補とする。未起動、ロック、権限拒否、非対応 host・入力型、削除済み ID、元の日本語キーボードへの復帰を確認する | host・入力欄ごとの成否、設定手順、成功率、往復時間と誤り。初期版の入口と必要な権限。失敗時の代替手順 | [01](01-invocation-and-platform.md)、[04](04-security-distribution-and-operations.md) |

| **V4：日本語と検索** | 原文を変えず、想定した結果を入力に追従して出せるか | 正規化・表記揺れの期待結果を先に記す。1〜2 文字、結合濁点、半角カナ、絵文字、記号・改行を含める。変換途中の入力、連続検索、古い結果の遅着、更新・削除・import 後の index を確認する | 期待／実際の検索結果、コピー・export 後の本文一致、入力動画、検索と描画の測定。検索仕様、index の必要性、世代管理 | [02](02-data-and-architecture.md)、[03](03-ux-and-performance.md) |

| **V7：任意の同期** | 同期の便益が競合と運用負担に見合うか | 採用を検討する場合のみ、2 端末でオフライン編集、同時編集、削除対編集、長期不在、アカウント変更、同期の無効化・再開を試す。V1 の操作を通信待ちにしない | 競合した本文の保持、両端末の収束、アカウント別データの分離、回復手順。同期の要否と方式。即時同期を前提にしない UI | [02](02-data-and-architecture.md)、[04](04-security-distribution-and-operations.md) |
| **V8：配布と更新** | 初期設定・移行・プライバシーを含め配布可能か | 実在する target で archive と検証を行い、選んだ配布方法で更新を試す。Keyboard を含む場合は入力機能・切替・Full Access 不要の動作を確認する。manifest、SDK、privacy policy、依存 license、サポート先を点検する | 配布物、更新結果、審査担当者向け手順、宣言内容の対応表。初期リリース範囲と保守担当。自動検証成功を審査承認とは扱わない | [04](04-security-distribution-and-operations.md) |

## ResearchProbeの評価範囲

| 評価領域 | 観測できる範囲 | 製品の採用に必要な条件 |
| --- | --- | --- |
| V0・V1・V2 | 本体CRUD、Safariへのペーストと一覧復帰、URL入力の判定。Shortcutsは登録成功・実行失敗 | 代表タスク、全対象host、入口の実装と権限、初回設定と日常利用、失敗時の代替手順 |
| V3・V4 | 保存3案、単純な移行・履歴、SQLite別プロセス、短い日本語検索、世代管理、日本語かな入力 | 実extensionの共有・通知・移行競合、長文と変換中の検索更新、製品の検索仕様 |
| V5 | 不正importの拒否、atomic snapshot、注入した保存失敗からの下書き復元、同一アプリ内のコピー期限 | 実際の容量不足・終了、実機ロック時の保護、全入口の本文露出、別アプリ・Handoff・復元 |
| V6 | Simulatorの保存・取得・検索の計測、通常表示と最大文字・小画面。小画面の文字切れは不合格 | 実機性能と性能予算、支援技術、利用者の完了率・迷い・誤操作 |
| V7・V8 | 関連APIの型検査、unsigned archiveとmanifest配置 | 2端末の同期、署名・配布更新、実用途に合うプライバシー宣言と運用 |

期待条件に一致した観測を「成功」、一致しなかった観測を「失敗」、環境・実装・仕様がそろわず試していない条件を「未実施」とする。未実施条件の具体的な一覧は[実行結果の採用条件](experiments/ios-26-5-validation.md#製品採用に必要な検証)で管理する。利用シーン・検索仕様・同期の採否などの「未決定」は、テストの成功だけでは決まらない製品判断を指す。

## 実験の共通条件

### 実装・OS・データ

- 実在する本体・extension の deployment target を **26.0** にそろえる。選んだ Xcode・Swift language mode・isolation 設定・SDK と、使う型／member の availability を記録する。
- 実行検証は **iOS 26.5のみ** を対象とする。最低対応OS 26.0への適合はdeployment targetと個別APIのavailabilityで点検する。26.5の環境を用意できない場合は、その条件を未実施と明記する。
- OS 連携は実際の host と入力欄を記録する。アプリ本体で成功したことを extension の成功とみなさない。Full Access、ロック、Handoff、言語、Action Button 対応の有無も残す。
- 比較用のデータ件数は **0・20・1,000・10,000 件**。件数は比較のための仮定で、製品の上限や利用実態ではない。本文の長さ・文字構成・検索結果件数もそろえ、必要に応じて仮定を更新する。
- 実データ、秘密情報、第三者の入力文を証跡に使わない。画面と復旧の検証には再生成可能なダミーデータを使う。

### 時間・正しさ・体験

**呼び出し操作 → 選択可能 → コピー／挿入完了 → 元の作業を再開**の区間を分ける。初回設定時間と日常操作、利用者の探索時間とアプリの処理時間も別に残す。検索や保存が速くても、誤った本文や古い結果を出す状態は成功にしない。

性能は同じ実機・OS・Release 構成・データ・操作で比較する。測定回数、cold / warm、熱・電源状態、集計方法を残す。[03 の測定案](03-ux-and-performance.md)を開始点にするが、原著の係数、Apple の大まかな時間目安、少数試行の最大値をそのまま製品保証へ転用しない。

UI/UX は対象コミット・端末・OS・到達手順を付けたスクリーンショットと画面録画で確認し、変更時は PR に閲覧可能な形で添付する。性能の改善を主張する場合は対応する測定値も添える。録画だけでは処理時間や原因の証明にならない。

### ローカルとクラウド

iOSビルド、SDK統合、権限、UI、性能、署名・配布はローカルMac / Xcode / Simulator / 実機が担当する。Ubuntu CIはworkflow方針・Nix書式・検証スクリプトのテストを担当し、macOS runnerは使用しない。補助ツールはNixで宣言・固定する。

Simulatorでのビルド・テスト・画面記録は [共通コマンド](../docs/ios-verification.md) を使う。試作のproject・shared schemeを設定ファイルへ登録し、`--project-config` と対象UDIDを指定する。fixture専用のsmokeを製品の検証に転用せず、試作の操作と期待結果を定義する。実機の署名・配布・計測は対象端末に合わせて構成する。

## 採用条件と設計判断

製品の採用条件は、対象シーンでの正しい動作、iOS 26.0のAPI・extension・権限への適合、原文と保存結果の保持、実機での使いやすさ・性能、保守・復旧の負担を比較できることとする。APIの存在や試作のビルド成功だけでは採用を決めない。

本体の操作と対象hostでの利用を成立させ、比較した入口・保存・共有方式について、必要な検証結果と未実施条件を確認する。小画面の表示失敗やShortcutsの実行失敗は、採用条件を満たしていない観測として扱う。未評価の構成を製品の保証に含めない。

ADRは導線、保存・共有、検索規則、保護・認証、同期、主要依存など独立して判断できる単位で記録する。各判断に対象シーン、比較候補、観測、採用理由、代替案、長期の保守・運用、見直す条件を付ける。必要な条件を満たしていない案は「提案」とする。

開発規約は[CONTRIBUTING.md](../CONTRIBUTING.md)、検証基盤の採用構成は[ADR 0001](../docs/decisions/0001-local-ios-verification.md)を正とする。製品のUI・保存・extension・同期・アカウント・AI・課金・配布運用は、この計画で評価して決定する。
