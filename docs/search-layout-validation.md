## 検索の表示と操作

| 状態・操作 | 観測 |
| --- | --- |
| 検索開始 | 上部左側に「検索」、中央に入力の案内を表示。保存済みの行は表示しない |
| 入力中 | 検索欄と閉じるボタンはキーボードの直上。新規作成ボタンを隠す |
| 結果表示・確定 | 見出しを保ち、日本語検索に一致する項目を表示。検索確定でキーボードが閉じ、新規作成ボタンが戻る |
| 検索語の消去・終了 | 消去すると案内へ戻る。閉じる操作で一覧へ戻る |
| 大きな文字と外観 | 最大Dynamic Type・ダーク・コントラスト強調で見出し、案内、検索欄と閉じる操作を確認 |

通常文字の入力中は、AXで見出しがx20 / y72 / 38×24 pt、検索欄がx8 / y483 / 330×48 pt、閉じるボタンがx346 / y483 / 48×48 ptだった。最大文字では案内が折り返され、標準検索欄のプレースホルダーは省略される。表示設定は実行前後でlight / large / contrast disabledに一致した。

入力前・結果表示・確定・消去の4枚について、見出し領域のRGB画素は一致した。確認領域は原本1206×2622 pxのx60 / y216 / 114×72 pxで、読み取り結果を`artifacts/search-title-pixels.json`へ保存した。この一致は静止画像の見出し領域に限る。

標準UI driverでは作成・下書き再開・保存・編集・検索・コピー・ピン・削除・Undo・下書き破棄・削除一覧の検索と復元が成功した。コピー本文のUTF-8完全一致、復元時のUUID一致、3フィルターの表示対象、左右配置と再起動後の設定保持も検査した。

## 評価から除外した実行

`20260917T011631Z-search-layout-f40006`は、最大Dynamic Typeで案内のAX表現が複数のテキスト要素へ変わり、補足driverが案内を認識できず停止した。案内の実際のラベルも判定するdriverで上記runを実行した。

表示の切り分けに使った別ソースの試行runは保持し、最終ソースの評価には使わない。原本の見出しは各状態で確認できたため、試行したView構造・色指定・modifier順序の変更は採用していない。

## 確認範囲の限界

この変更は画面表示を対象とし、製品単体テストは再実行していない。47件の成功は[一覧フィルターの検証](library-filters-validation.md)に記した対象ソースに対する結果である。速度・描画・メモリの定量比較は行っておらず、性能改善は主張しない。

Releaseでの評価であり、Debugの診断、IME変換、VoiceOver、Reduce Motion切り替え、RTL、小画面、横向き、iPad、実機、共有拡張の操作は未評価。PRへの媒体添付とブラウザー閲覧は未実施。TestFlightの配信状態と実機での動作は配布担当者が確認する。
