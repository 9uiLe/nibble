# nibbleの製品仕様・要件

nibbleは、繰り返し使う文章を端末内に用意し、必要な場面で意図した内容を再利用するiOSアプリである。入力負担、探す時間、操作の迷い、取り違え、途中作業の損失を減らす。文章を用意するところから他アプリで使って作業を続けるところまでを、一連の利用として設計する。

本書は採用する操作と状態の契約を定める。実装の存在、対象OSでの観測、製品全体の受入完了は区別する。検証結果は[実行手順](ios-verification.md)と[証跡手順](review-evidence.md)に従う対象ソース付きrunで確認する。文書に採用仕様を書いたことを、受入済みの証拠にしない。

本体の通常導線は指定された `a-ios-polish-v1` の一覧・詳細・新規作成・本文編集で構成する。[本体の入力・保存・削除の契約](design/ios-polish.md#確定した入力保存削除の契約)に、新構成と既存の共有・Keyboardの境界を示す。ピン・作業中・設定は新しい一覧へ表示せず、以下の旧構成の説明だけを根拠に追加しない。変更がある場合の破棄確認、削除直後の取り消し、タイトル・本文の必須条件は利用者の回答により採用した。以下の従来構成の作業保持・差し替え・ごみ箱画面は、既存入口の契約として区別し、本体の新しい通常導線へ追加しない。

## 目的と提供範囲

本体の通常導線はプロンプトの作成・検索・全文確認・本文編集・タイトル変更・削除とコピーを担う。コピー後は利用者が使いたいアプリへ戻り、入力欄を選んでOSのペーストを行う。共有拡張は他アプリから渡された文章・URLの取り込み、任意で追加するKeyboardはピン留めした固定文の確認・挿入を担う。

最低対応はiOS 26.0、実行評価はiOS 26.5の専用Simulatorとする。製品の受入に実機は含めない。本体でのコピー経路はKeyboardの追加やFull Access許可を前提にしない。

保存先は端末内のApp Groupで、nibble自身のサーバー、アカウント、通信同期、独自export/importは持たない。OSのバックアップに含まれる可能性はあるが、nibble独自の復元機能として保証しない。アプリ削除後の復旧、旧保存形式からの移行は提供範囲に含めない。[データ保護と配布](#データ保護と配布)も参照する。

## 利用者と主要な利用場面

自分のiPhoneで、定型文・連絡文・URL・メモなどを繰り返し使う人を対象とする。固定文をそのまま使う場合と、相手や用件を毎回変える場合を扱う。チーム共有やクラウド管理は対象にしない。

本体の検索とコピーは全対象の既定経路である。Keyboardは利用者が選んだ頻用固定文への追加経路とする。Keyboardに未掲載の文章を探すために、狭い領域へ独自の日本語入力方式を追加しない。

## 機能要件と受け入れ条件

| 能力と軽減する負担 | 成功条件 | 取消・失敗・再試行 |
| --- | --- | --- |
| 作成 | タイトルと本文がともに空白以外を含む場合だけ保存できる。入力した原文を保持する | 変更がある×は破棄確認。保存失敗は入力を残して同じ画面で再試行 |
| 発見 | 全保存済み対象のタイトル・本文を検索し、行のタイトルと抜粋で識別する | 古い検索結果を現在の条件へ適用しない。失敗と0件を区別 |
| 確認・コピー | 詳細で文字どおりの全文をスクロールできる。行または詳細から本文を明示コピー | 表示versionの失効・削除時はコピーしない。貼付・送信済みと呼ばない |
| 編集・名前変更 | 本文編集は本文だけ、標準Alertのタイトル変更はタイトルだけを同じUUIDへ保存する | キャンセルは元の保存内容を変えない。失敗は入力を保持し、競合を無言で上書きしない |
| 削除・回復 | 対象名付き確認後に一覧から除外し、直後の通知から同じUUID・原文を戻す | 確認のキャンセルは無作用。専用ごみ箱・完全消去の画面を追加しない |

共有拡張・Keyboard・差し替えの既存コードの契約は以下で明示して残すが、採用デザインにない入口を本体へ追加する要件にはしない。特に旧作業の本体再開、ピン管理、説明・設定画面は現在の通常導線にない。

## データの意味と永続化

| 概念 | 意味 |
| --- | --- |
| 保存済み文章 `TextCard` | UUIDとversionを持つ確定済みの名前・本文・差し替え指定・ピン・削除状態。UIが受け取る値は一つの版のsnapshotであり、入力のBindingとして更新しない |
| 作業 `WorkDraft` | 独立したUUIDを持つ、新規作成・既存編集・差し替え準備のセッション。原文、明示的な差し替え指定、入力値、sequenceを保持する |
| 既存編集・準備の対象 | 元文章のUUIDと開始version。元の文章の更新・削除を、無言の上書きや古い本文のコピーで乗り越えないために照合する |
| 完成文の保存 | 差し替え結果を明示操作で別の固定文にすること。元のひな型名は由来のsnapshotで、追随するリンクではない |
| 一覧要求 | 検索語、ピン留め条件、ごみ箱条件、取得位置・件数。古い要求の遅延結果で現在の一覧を置き換えない |

### 原文と検索用の値

名前・本文・差し替え値の空白、改行、タブ、NUL、Unicodeを原文として保持する。同一性はUTF-8で比較し、正規化して等価な文字列を同じ入力と決めつけない。OS標準の選択・訂正・ペーストは利用者が操作した位置へ適用する。アプリはクリップボードを先読みしない。

検索用の値だけを別に正規化する。現行検索はNFC、大小文字・文字幅のfoldingを行い、名前と本文の部分一致を使う。原文へ逆反映しない。`%`や`_`を検索用のワイルドカードにはしない。保存済み本文は空白・改行だけでは確定できないが、その入力も作業には保持する。

完成文は文字列のまま表示する。Markdownの見出し、リンク、装飾記号も保存・確認・コピーの対象に含め、描画用の本文へ変換しない。表示上の折返しを保存本文の改行へ書き戻さない。

### 保存形式と接続

`WorkspaceRepository`がApp Group内の`Library/workspace.sqlite`を扱う。schema 2を使い、schema 1と旧DBを暗黙に移行・上書きしない。未対応schema・破損をデータ消去と再初期化で解消しない。

操作ごとの短いSQLite接続とtransaction、WAL、有限の競合待機、versionとsequenceの照合で本体・拡張を調停する。transaction内でawaitしない。Keyboardは既存のDBを読取専用で使い、DB作成・schema変更・ピン更新を行わない。詳細は[構成](architecture/README.md)と[Keyboard](architecture/keyboard.md)に定める。

## 検索と一覧の性能

本体の検索は全保存済み対象へ適用する。ピン集合の切替と作業一覧は表示しない。一覧はピン優先、更新日時降順、UUID昇順で、50件ずつ追加取得する。使用回数・利用日時を保存して順位を変える方式は採用しない。

要求IDで読込結果を照合し、古い検索結果を現在の検索へ適用しない。件数と一つのページは同じ読取transactionから得る。再読込・追加取得・失敗時に、現在の要求、表示内容、次の操作を理解できるようにする。

ページ件数の制限だけで大量・長文時の応答とメモリを保証しない。部分一致検索の全件走査、ページ内の本文保持、全文表示、下書き一覧の費用を[性能検証](performance-verification.md)で測る。前版より速いという主張には同条件の比較を必要とする。

## 編集の開始と再開

新規作成は独立した作業、本文編集は対象UUIDとversionを固定した作業を作る。行選択は詳細、編集は本文入力、その他の操作はタイトル変更と削除へ進む。外部呼出しは現在の作業を上書きしない。

本体の×は作業を終了して破棄する。背景化・プロセス終了後の作業再開画面は今回設けていない。共有拡張の旧エディターは作業を保持するが、旧「作業中」一覧を本体へ再導入する契約ではない。

## 入力の保存と編集の終了

入力変更はメモリ上の作業とsequenceを更新し、自動checkpointを行う。確定保存と作業保持を分ける。未確定の日本語入力がある間は本文エディターの保存・×を受け付けず、変換確定を案内する。標準入力の変換中にUI側から本文を差し替えない。

| 本体の操作 | 成功時の確定 |
| --- | --- |
| 新規保存 | タイトル・本文を検証し、最新checkpointから新規項目を保存、当該作業を除去して一覧へ戻る |
| 本文保存 | 対象versionへ本文だけを反映し、当該作業を除去、同じ詳細へ戻る |
| × | 変更があれば確認後に当該作業だけを除去。変更なしは直接終了。保存済み項目は変更しない |
| タイトル変更 | 非空白のタイトルだけを対象versionへ反映し、本文・UUIDを維持 |

全キーストロークや異常終了直前の未確定入力の永続化は保証しない。保存・破棄の障害では画面と入力を残す。checkpointは読み込んだ／最後に保持したsequenceを照合し、別画面の入力を古い作業から上書きしない。重なるcheckpointは順に完了を待ち、除去済み作業を再生成しない。

共有拡張の旧エディターでは「閉じる」が最新作業の保持を待ち、競合時の独立保存など既存の回復を使う。[編集設計](architecture/editing.md)にその境界を定める。これらを本体の×の動作へ読み替えない。

## 変数と完成文

以下は残存する旧利用セッションと拡張の契約である。通常の本体詳細は常に保存本文をそのままコピーし、変数入力や完成文保存の画面を開かない。

「差し替えを使う」は既定でオフとする。オンにして保存した文章だけ、本文の`{{宛名}}`のような印を差し替え対象とする。オフなら有効な印の形でも原文をそのまま表示・コピー・挿入する。本文の構文から設定を自動推論しない。設定の変更も作業として保持し、明示保存で利用対象へ反映する。名前は前後の空白を除き、空・改行・波括弧を含む印は変数として解釈しない。有効でない印は原文のまま表示・出力する。同名の印は一つの値で全箇所を置換する。値は空白・改行だけでは完了としない。

差し替えは本体のOS標準入力を使う。必要な値が揃うまでコピーできず、揃ったら完成文の全文を示す。今回の値を原文へ反映したり、入力先へ未完成の印を先に挿入したりしない。

閉じると準備作業を保持し、明示破棄は今回の準備だけを除く。完成文を再利用カードとして保存しなくても中断・再開・コピーできる。繰り返し同じ相手・用件へ使う場合だけ、名前を確認して完成文を別文章として保存する。名前は任意で、未入力なら本文から表示名を作る。保存された完成文は元のひな型から独立し、ひな型更新や削除で変わらない。競合時の独立救出は通常の新規文章として保存し、由来の関係を保証しない。[変数の設計](architecture/variables.md)に責務を定める。

## 非同期操作の完了契約

本体の行・詳細コピーは、対象の未削除・version照合と取消確認を経て本文のUTF-8を`localOnly`でOS pasteboardへ渡す。OS書込呼出しの戻りをコピー完了とし、貼付・送信の完了とは呼ばない。再度の明示タップは新しいコピーで、自動再コピーをしない。

旧利用セッションはcheckpointと完成文照合を行い、コピー後に準備作業を片付ける。片付け失敗でもコピー完了を失敗へ変えない。OS作用とDB更新は同一transactionではないため、プロセス終了をまたぐ厳密なexactly-once配送は保証しない。

ピン・ごみ箱移動・復元は対象UUIDとversionを照合し、成功後だけ結果を表示する。削除は本文・ピンを残して通常一覧とKeyboardから除外し、復元は同じUUIDを戻す。関連する作業は残す。処理済み状態を再試行しても別の対象への作用へ変えない。

取消は外部作用前の停止要求である。確定済みの書込やコピーを取消で巻き戻したと表示しない。失敗の再試行は対象の処理だけを行い、完了済みの外部作用を繰り返さない。

## 呼び出しと共有の契約

共有拡張は対応providerが渡したテキストまたはURLを原文として読み、作業を保持して共通エディターへ接続する。Webページ本文を勝手に取得せず、他アプリの任意の選択範囲や入力欄を読み書きしない。共有内では既存エディターで保存できる。本体の新しい通常導線には保持作業の再開入口を置かない。

外部URLは一覧、入力を用意した作成、指定UUIDの確認への入口である。保存・コピー・挿入・削除を自動実行しない。不正な形式や、別作業を表示中の要求は理由を示し、現在入力を維持する。custom schemeの所有や呼出元の正当性は保証できないため、秘密の文章をURLへ載せることを案内しない。

Keyboardは未削除・ピン留め済みで、差し替える値が不要な固定文だけを最大50件読む。差し替えが有効かつ有効な印がある文章は対象外とし、オフなら`{{…}}`を含む原文も固定文として扱う。一覧は要約だけ、選択時は全文を読み直す。本文の全文確認から明示挿入し、入力先や可視性が変わった確認を使い回さない。検索・差し替え・編集・コピー・ピン更新・通信は持たない。Full Accessを利用者に要求しない読取構成の成立と入力先の保護は、[Keyboard設計](architecture/keyboard.md)の対象環境で確認する。

## 画面とフィードバック

画面構成は[S台帳](design/screens.md)、部品の理由は[C台帳](design/components.md)、評価課題は[G台帳](design/audit.md)に定める。標準の文字スタイル、Dynamic Type、ライト／ダーク、safe areaを使う。OS入力と本文の可読性を優先し、表示設定を製品側で一律に固定しない。

結果は作業した画面で伝え、保存・コピー・挿入を演出終了まで待たせない。Rive、課金、広告、独自かな漢字入力は製品の構成に含めない。制作資産の保持は製品での使用を意味しない。

## 技術選定と配布容量

SwiftUI/Observationが画面と操作状態、UIKitの`UITextView`接続がOS標準入力、SQLiteが別プロセスの保存とrevision照合を担う。TaskingはViewが開始する有限操作の寿命と重複を扱う。AppMacrosは表示の比較境界に使う。

外部入力はOS標準IMEへ任せ、出力は文字どおりの完成文を使う。独自変換器、Markdown描画切替、課金状態、広告、Riveの再生状態を同時に保守する負担を増やさない。依存と製品targetの実際の構成は[実装規約](library-policy.md)とprojectを照合する。容量・応答の改善は測定するまで断定しない。

## データ保護と配布

私的な文章と準備値を端末内に保持し、保存領域・DB・WAL・SHMにData Protectionのcompleteを指定する。本文・検索語・入力値をアプリのログ、analytics、システム検索へ送らない。OS入力、共有、pasteboard、OSバックアップへ渡る範囲とnibble内部の保存を区別する。

本体sceneの非active・background時は、提示中のsheetを含む本文を同じsceneの別windowで覆い、復帰後に元の入力へ戻す。共有拡張とKeyboardへ本体のscene状態を適用しない。スクリーンショット・録画の防止や拡張のsnapshot保護は保証しない。端末保護属性の設定と本体の覆いを、ロック中のデータ保護や実際の切替表示の検証済み証拠としない。

プライバシーポリシーとサポートへのリンクは旧「使い方と管理」に残存するが、新しい通常導線にはその入口を追加しない。アプリ内にサーバー通信を持たないことは、利用者がリンクを開いた先の通信を禁止する意味ではない。

TestFlightは[配布手順](testflight.md)に従う。エージェントの署名・アップロードと、Apple側の処理・配布・実機確認を分け、秘密情報の直接読取を行わない。旧データの互換性、Simulatorでの成立、Appleへの送信を同じ完了条件にしない。
