# スニペットキーボードの設計

Keyboardは、利用者がピン留めした固定文を入力先から離れずに確認・挿入する任意の入口である。本体の検索・準備・コピーを置き換えず、すべての文章を狭い領域へ集めない。採用構成と受入完了を分け、[検証手順](../ios-verification.md)の対象ソース付きrunで読取・挿入の成立を確認する。

## レイアウトと操作の意味

未削除・ピン留め済みで差し替える値が不要な固定文だけを表示する。差し替え指定がオフなら`{{…}}`も文字どおりの固定文で、指定がオンかつ有効な印があるものは対象外とする。取得範囲は更新日時降順・UUID昇順の最大50件で、本体の全件一覧ではない。行から文字どおりの全文を開き、スクロールで内容を確認して「挿入」を選ぶ。一覧を選んだだけでは入力先を変えない。

名前、要約、由来がある場合の元ひな型名で対象を識別する。完成文から保存した固定文は元ひな型へ自動追随しない。本文を変えず、Markdown記号も文字として表示・挿入する。

検索、日本語入力、値の差し替え、本文編集、コピー、ピン更新をKeyboardへ置かない。未掲載・差し替え対象・多数の対象からの探索は、本体で探して準備し、コピー後に入力先へ戻りOSでペーストする。空表示を、本体の保存データがないことと同一視しない。

## 操作結果と失敗

挿入確認は一度の実行資格を持つ。実行時に対象の未削除状態と版、入力先の同一性、Keyboardの可視性を照合する。確認中の入力先変更・離脱・再表示では古い確認を失効し、もう一度対象を選んで確認する。

連打で挿入を繰り返さず、取消では挿入しない。挿入後の表示更新や読込失敗を理由に自動挿入しない。利用者が改めて対象を開いて実行する場合は、新しい利用として扱う。

OSの挿入APIの呼出しとホスト側の実際の文字列を別に観測する。入力先の拒否・文字数制限・独自編集挙動を一律に検出したと主張せず、送信完了とも呼ばない。表示する結果の根拠と、利用者が入力欄で確認する範囲を分ける。

## 構成と責務

本体が固定文の編集・ピン・DB初期化を所有し、Keyboardは`WorkspaceRepository`の読取専用モードを使う。入力先の文書同一性と、一度の挿入資格の照合はOS接続側で所有する。行や全文の再表示から挿入を発火しない。

表示開始時の読込は`KeyboardViewController`が所有し、`viewWillAppear`で入力先と可視性を有効にしてからTask ownerへ再読込を依頼する。初回のSwiftUI表示taskに依存させず、再表示も同じ開始経路を通す。離脱は資格と画面寿命のtaskを取り消す。明示的な再読込は失敗からの再試行にも使う。

本体の編集中・差し替え中の作業はKeyboardの利用候補にしない。差し替えが有効で、有効な印が残るひな型の本文も渡さない。完成文を利用者が別文章として保存し、ピン留めした場合だけ、独立した固定文として候補になる。

## 共有データと読み取りの契約

App Groupの`Library/workspace.sqlite`、schema 2を使う。一覧は要約投影だけを読み、選択時と実行前に必要な全文と版を読み直す。Keyboardは既存DBを読取り、schema作成・移行・索引作成・書込を行わない。未初期化・未対応schema・破損・ロック等の失敗を空の成功結果へ変えず、本体を開くなどの回復方法を示す。

SQLiteの短い読取接続とWALを用いる。本体書込後の読取、Writer終了後の読取、更新・ごみ箱移動・復元後の再取得を対象環境で確認する。設定宣言やコンパイル成功を、共有領域の読取成功とみなさない。

## 状態と操作の寿命

一覧要求・選択した本文の版・入力先context・可視性・実行済み状態を区別する。古い読込結果で新しい選択を上書きしない。入力先変更時には完成文の確認資格も取り消し、別の欄へ古い選択を持ち越さない。

入力先の同一性が観測できない条件、Keyboard切替やホスト再表示の条件を検証に含める。識別できない状態で安全を保証したとしない。OSが所有する入力欄へ未完成文を挿入してから、標準Keyboardへ切り替えて編集させる経路は採用しない。

## 権限とOSの境界

読取専用App Group利用のためにextension側の`RequestsOpenAccess`宣言を持つ場合でも、利用者のFull Access許可を必須にしない構成とする。宣言の有無、OS上の許可状態、共有領域の読取可否を別々に照合する。Full Accessの有無を本文の安全性や挿入の成功へ読み替えない。

ネットワーク、pasteboard読取・書込、入力履歴の収集、DB書込をKeyboardへ追加しない。地球儀で標準Keyboardへ戻れるようにする。secure入力、一部の入力欄、第三者Keyboardを拒否するホストでは利用できないため、本体コピーとOSの貼付へ接続する。全ホストの成立は保証しない。

## ビルドと評価

標準UITextFieldをKeyboard内部へ置いても自然な日本語入力が成立しなかったP1観測を、今回の担当限定の根拠にする。[根拠と適用限界](../design/evidence.md#r04-keyboard内部の標準入力試作)を参照する。独自IME一般が不可能とする判断ではない。

読取権限と一度の挿入の試作、本体でピン留めしてから外部入力欄で使う一連の操作、入力先A/Bの変更、連打・取消・再表示を確認する。大量のピン、長文・Unicode、狭い表示、標準Keyboardへ戻る操作も含める。製品全体の受入はKeyboard単体の成功だけでは完了しない。

## 外部仕様

OSの能力と制限は[OS境界の参照](../reference/platform.md)を確認する。公式APIの契約、対象SDKでのコンパイル、iOS 26.5 Simulatorでの観測、利用者の理解は別の根拠として扱う。
