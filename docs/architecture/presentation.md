# 保存・入力を伝える説明イラスト

nibbleの説明イラストは、文章を保存する操作と、保存した本文を入力先で利用する操作を伝える。元の文章が残ることと操作の順序を自動ループで示す。利用者は図と本文を一緒にスクロールして読める。図を見なくても操作を理解できるよう、説明と読み上げは隣接する文章に持たせる。

| 画面・部品 | 伝える操作 | 配置 |
| --- | --- | --- |
| S05「nibbleについて」・C44 | 他アプリの文章を選択してコピーし、nibbleへ保存する | 導入文の直後。元の文章と保存先を二つのモバイル画面で示す |
| S10「nibbleキーボード」・C49 | 入力先でキーボードを切り替え、保存済みの行をタップして本文を挿入する | 導入文と追加手順の間。入力欄とキーボードを一つの画面内で上下に示す |

本書は製品の表現と再生方針を定義する。ファイル名・接続名・制作手順は[アセット手順](../../app/Animations/README.md)、汎用APIの契約は[RivePresentation](../../app/Packages/RivePresentation/README.md)、測定条件と補助予算は[性能手順](../performance-verification.md)を参照する。

## 表現と配置の理由

保存の図は、文章選択、コピーメニュー、複製の移動、保存、完了を一周期で示す。元の文章を残し、保存先に項目が増えることで、複製を保存する関係を表す。

入力の図は360×320の描画面に、入力欄を上、キーボードを下として同時に配置する。入力に必要な領域を大きく見せ、小画面でも入力結果と保存済み本文を見比べられる構図とする。入力先とキーボードを同じ端末内に大きく描き、移動先と挿入内容の関係を判別できるようにする。図は本文と一緒にスクロールし、標準の戻る操作を妨げない。

両図は紙の色、柔らかな輪郭、余白、控えめなタップ表示を共通にする。入力の図では、キーボードの選択状態と挿入結果に製品と同じ青を使う。キーボードの上部に表示対象の切替と更新、中段に単一リスト、下部に結果・キーボード切替・終了を配置する。操作と権限の意味は[キーボード設計](keyboard.md)に従う。

### 入力の図の時間構成

一周期は8.4秒とし、切替・行の選択・挿入・結果確認を順に示す。

| 時点 | 表示と動作 | 目的 |
| --- | --- | --- |
| 開始〜約2.7秒 | 地球儀を長押しし、切替候補からnibbleを選ぶ | 入力先の画面にとどまってキーボードを切り替えることを示す |
| 約3.3秒 | 保存済み行の主領域をタップする | 全文確認用の「…」と、直接入力する領域を区別する |
| 約3.6秒 | 本文を入力欄へ一度に表示する | 一回のタップで本文全体を挿入する関係を示す |
| 挿入後〜6.8秒 | 入力結果と保存済み行を同時に表示する | 約3秒間、同じ本文が入力先と保存元に残ることを見比べられるようにする |
| 6.8秒以降〜次の周期 | 内容全体をフェードし、初期状態へ戻す | 本文だけを消して削除操作に見せず、次の説明へ移る |

行のハイライトと「本文を送りました」は、製品の挿入結果と同じく2秒間表示する。始点と終点の値・静止期間を揃え、周期境界で位置が飛ばないようにする。図の挿入操作は、コピー・ドラッグ・フルアクセスの許可を前提にしない。

自動ループにより、途中から見た場合にも説明の始点へ戻れる。静止図は描画負荷と注意の分散を抑えられる一方、操作の順序を別の表現で補う必要がある。自動再生による理解度と読書への干渉は利用者評価で確認する。

## 構成と責務

再生状態を持つSessionと、それを画面に描くCanvasを分ける。Sessionは一つの説明画面が保持する再生位置とData Binding値の組である。Canvasの表示用Viewは、Sessionを保持したまま取り外しや再生成ができる。

| 構成要素 | 責務 |
| --- | --- |
| RML | 図形、タイムライン、状態遷移、型付きData Bindingを定義する編集の正本 |
| 生成物とmanifest | Bundleへ同梱する `.riv` と、制作ソース・生成物・接続名・型の対応 |
| RivePresentation | 読込済みアセットのFileと処理を実行するWorkerを扱うResource、独立したSessionの生成、Canvasの停止・再描画・表示用Viewの解放 |
| IllustrationPlayback | 説明画面ごとの読込処理、Session、失敗状態、読込結果の採否 |
| AboutIllustration / KeyboardIllustration | 読込taskの所有、配色、図の可視性、代替表示、説明文、再読み込みボタン |
| AppRootView | 選択タブと全面シートの状態から、説明画面の再生を許可するかを伝える |

図形と時間はRML、画面状態はSwiftUI、値の受け渡しはData Bindingが担当する。フレーム進行には[R20の固定runtimeの時計](../design/evidence.md#r20-riveの停止と復帰)を使い、フレームごとの状態をSwiftUIへ転送しない。RivePresentationは製品固有のパスや型を持たず、ホストがアセットと表示方針を渡す。

## 読込と画面の寿命

説明画面は `IllustrationPlayback` をStateに保持し、Viewの `.task(id: attempt)` からファイル読込とSession生成をawaitする。生成済みのSessionがあれば再利用する。処理が取り消された場合や新しい読込要求に置き換わった場合は、その結果を表示へ採用しない。

Sessionの寿命は説明画面を開いている期間とする。スクロール、タブ移動、全面シート、バックグラウンド移行では再生位置とData Binding値を保持する。ナビゲーションの戻る操作で説明画面を閉じると、表示用ViewとSessionを解放する。再訪時は独立したSessionを生成し、先頭から再生する。同時に存在する説明画面同士でSessionを共有しない。

FileとWorkerは画面ごとに読み込み、画面間のキャッシュを持たない。保持期間を画面の寿命に揃え、閉じた説明画面の資源を解放できる構成とする。再訪時の読込時間と保持量は[性能手順](../performance-verification.md)の条件で評価し、測定値を対象ソース付きのrunへ記録する。キャッシュの必要性は再訪時の読込予算と保持量で判断する。採用する場合は対象ファイル・容量上限・所有者・解放条件を定める。

## 停止と復帰

演出の選択とフレームの停止を区別する。`motionAllowed` はループと完成静止図を選ぶData Bindingであり、nibbleでは[表示固定方針](../design/rationale/fixed-interface.md)に従ってtrueに固定する。再生を一時停止するときはCanvasの `paused` を使い、演出の状態を切り替えない。

| 判定する場所 | 停止条件 |
| --- | --- |
| 説明イラストのホスト | 図の可視性がまだ通知されていない、または可視部分が10%未満 |
| 画面の所有者 | 別タブを選択している、または全面シートが説明画面を覆っている |
| Canvas | Viewが表示から離脱している、または所属sceneがactive以外 |

Canvasはホストから渡された停止要求と自身の条件をORで合成する。一つでも条件が残る間は周期的なフレーム進行を止める。すべて解除された最初のフレームは時間差0で評価し、保持した位置から再生する。停止していた実時間を演出へ加算しない。図が表示されている間のドラッグや減速は停止条件に含めない。

表示用Viewを取り外す際は、同期的に停止し、表示用Viewが持つRive参照を外す。取り外されたViewがSwiftUI内部に一時的に残っても、再生時計やFileを保持し続けないためである。

## 描画先の取得

Metalの描画先はGPU処理が終わっても提示完了まで再利用できず、`CAMetalLayer.nextDrawable()`の呼出元を待たせる場合がある。スクロールを処理するメインスレッドと描画先の取得を分離するため、nibbleは[Rive描画基盤](../../runtime/rive/README.md)を使う。画面が見えている間も演出を継続し、描画先の取得待ちを画面操作へ持ち込まない構成である。

基盤はRiveRuntime 6.27.0の固定ソースへ`drawable-acquisition.patch`を適用し、取得を専用serial queueで実行する。同時取得数、フレーム進行、結果の世代・可視性・寸法照合、参照解放のスレッドは[基盤のフレーム契約](../../runtime/rive/README.md#フレームの契約)に定める。画面側はSessionと可視性を渡し、Metalの待機やキューを管理しない。ビルドと再利用の入力は同じディレクトリに定義する。

## 配色と寸法

ライト／ダークの配色は、Sessionが利用可能になった時点の画面設定から決める。ホストは配色をData Bindingへ渡してから初めてCanvasを表示する。読込中に外観が変わった場合も、完了時の設定を使う。

外観の変更時は同じSessionへ配色を渡し、描画更新番号を進める。Canvasは表示用Viewを一度生成し直し、再生位置を進めずに現在の配色を描く。同じ配色でのタブ復帰や通常の再評価では更新番号を変えない。寸法変更は同じ表示用Viewへ反映し、runtimeが時間差0で単発描画する。配色・寸法の単発描画によって停止中の周期再生を開始しない。

## 説明と失敗回復

図はタッチ操作を受けず、保存・コピー・入力を行う製品モデルへ接続しない。演出状態の `active` は図の状態を表し、製品操作の成否には使わない。図自体は読み上げ対象から外し、隣接するTextが操作順、原文保持、入力先への反映確認を伝える。

読込中は静止した代替表示を使う。失敗時には代替表示と説明文に加えて再読み込みボタンを表示する。本文の閲覧と標準の戻る操作は、読込状態にかかわらず利用できる。再読み込みボタンは `attempt` を更新して読込taskを開始し、成功時は現在の配色で図を表示する。操作領域は[F05](../design/foundations.md#f05-操作領域と形)の基準に従う。

## 保守と受け入れ

制作ソース・生成物・manifestを一組で管理し、CLIのviewport指定と実際の出力寸法を照合する。接続名・型の構造検査に加え、実バイナリを使って独立した再生状態、停止理由の合成、時間差0での復帰、配色、読込の取消・再試行、反復開閉後の解放を確認する。

[製品の検証手順](../ios-verification.md#説明イラストの検証)で本文への到達、複数周期、スクロール、タブ、全面シート、背景復帰、故障時の表示と実ボタンでの回復を評価する。理解度と読書への干渉は[G15](../design/audit.md#g15-c--キーボード説明の順序と原文保持)などの利用者評価、描画と応答性能は[G16](../design/audit.md#g16-c--説明画面の再生とスクロールの性能)の対象とする。

依存は互換性・ライセンス・toolchain・runtime容量を確認して固定する。[性能手順](../performance-verification.md)に従い、フレーム評価の時刻、画面への表示完了、スクロールの引っかかり、CPU・メモリをそれぞれ測る。設計値や生成成功を描画性能の証明に使わない。観測と未評価条件は、対象ソースを明示した検証記録へ残す。
