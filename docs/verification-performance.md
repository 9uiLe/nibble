# 検証実行方式の評価記録

この記録は、ローカルiOS検証の実行方式を、結果と媒体が確定するまでの所要時間で評価する。[検証基盤](decisions/0001-local-ios-verification.md)が採用方式と実行契約、[iOS手順](ios-verification.md#検証時間を比較する)が再現方法を定義する。アプリ自身の描画性能、人による修正・媒体レビュー・公開の時間は評価対象に含めない。

観測は以下の対象ソースと条件に限る。記録の存在を、異なるソースや最新headの検証済み状態として扱わない。

## 比較方式・対象ソース・環境

| 方式 | ビルドと実行の条件 | 対象実装 |
| --- | --- | --- |
| 標準方式 | 実行Macのarchitectureに限定し、testability等のビルド条件ごとにDerivedDataを分離。各工程で通常のxcodebuildを実行 | `19d1f0b`とrunの入力hashを照合 |
| 比較方式 | UDID単位でDerivedDataを共用し、testとUIのビルド条件を交互に使用。architectureの明示的な限定なし | `c7d0e40` |

標準方式の`ios.py`のSHA-256は`5d276cc8c5c6a8a26d9899aa258b1b4517aa34d8b7f8799aa34c0ba0b6a74ef0`。共通のNix lockは`6e96a91669e23afe13e9f8827cbcb7a0423b72b8aac15b36a673e75916a08365`、製品の共有Package lockは`b0bb1df2b6a012410ec0cdaa15ea64110608961fa016f9996a7dd01b24f7c381`。実行入力は各manifestの開始・終了hashで特定する。

測定日は2026-09-20。Apple M1 Pro・16 GiB、macOS 26.2 (25C56)、Xcode 26.5 (17F42)、Swift 6.3.2、iOS 26.5 (23F77)の専用iPhone 17 Proを使った。通常の専用UDIDは`F0B5BD34-93F2-4B33-BEC7-3D5F6893440E`、未起動端末の標準方式には別の専用UDID `D0B51E58-95EA-4CA4-954E-796448121C59`を使った。

製品の一巡はReleaseの101テストとMVP操作、fixtureの一巡はReleaseのtestとsmokeである。テストだけtestabilityを有効にする。製品ソースと依存lockは共通とし、代表編集の条件では指定した入力だけを一時変更する。

各比較系列の前に専用端末のダミーNibbleだけをuninstallし、同じシナリオを使う。MVPは一巡ごとに項目を1件残す。checkoutごとのDerivedDataは別で、初回は新規、反復は同じキャッシュを使う。依存repositoryのグローバルキャッシュは取得済みであり、依存取得やネットワーク速度の比較ではない。

ホストは専有せず、各試行のload averageを記録した。製品反復は比較方式2回・標準方式3回、fixture反復は各3回、初回と代表編集は各条件1回である。中央値・最小・最大・rangeを使い、この試行数からp95を推定しない。

## 評価基準

比較方式の基準値に対し、製品反復の中央値は50%以上短縮する585.620秒以下、fixture反復の中央値は10%超悪化させない28.656秒以下を目標とする。代表編集は各条件の比較方式の50%以下を目標とする。標準方式の反復3回が連続成功し、ソースと媒体を照合できることを安定性の条件とする。

失敗した検証全体の自動再試行は行わない。UI driver内の既定の限定的な回復は別に数える。成功速度の分布には、意図的な不正入力や中断による失敗を混ぜない。

## サイクル時間と完了数

単位は秒。初回と反復、異なる検証範囲は分けて評価する。

| 条件 | 比較方式 | 標準方式 | 判定 |
| --- | --- | --- | --- |
| 製品、起動済み端末・新規DerivedData | 997.188 | 784.906 | 約21%短縮。各1回でばらつきは未評価 |
| 製品、反復の中央値 | 1171.239 | 223.687 | 約81%短縮、目標達成 |
| 製品、反復の最小〜最大 / range | 1166.652〜1175.826 / 9.174 | 222.707〜233.487 / 10.780 | 短縮幅は観測したばらつきより大きい |
| fixture、反復の中央値 | 26.051 | 21.576 | 約17%短縮、目標達成 |
| fixture、反復の最小〜最大 / range | 25.928〜35.554 / 9.626 | 21.158〜22.183 / 1.025 | 標準方式の3回すべて成功 |
| fixture、未起動端末・新規キャッシュのtest | 62.519 | 62.597 | 短縮を確認できず |
| fixture、起動済み端末・新規キャッシュの一巡 | 未測定 | 30.831 | 同条件の比較値がないため改善率を算出しない |

製品反復の連続測定窓は、比較方式2巡で2342.410秒、標準方式3巡で679.924秒だった。完了数は3.074巡/時と15.884巡/時である。最速の一巡から換算した値ではなく、各測定窓の成功数を用いる。開発者の編集時間を含む生産性とは区別する。

未起動fixtureのtestでは、起動待ちが31.995秒と31.971秒、xcodebuildが27.808秒と27.874秒だった。比較方式の初回smokeはAX接続で11.074秒後に失敗し、Simulatorウィンドウを表示する手作業1回と別runの21.231秒で復旧した。標準方式はウィンドウ表示を事前手順として1回実行し、smokeは25.929秒で成功した。この条件差を初回サイクルの短縮率に使わない。

製品の速度比較の各MVPには、編集メニューの既定の回復が2件ずつ記録されている。理由・終了コード・入力結果の照合をmanifestに保持する。比較方式の反復testには意図的なSIGINTによる1.805秒の中断記録があり、成功時間の分布には含めていない。

## 時間内訳と実行方式の比較

共用DerivedDataでは、testabilityの切り替えに伴ってSwiftSyntax・SwiftParserのコンパイルが繰り返された。Macで動くmacro依存には、このApple Silicon環境の実行に不要なx86_64も含まれていた。標準方式はarchitecture限定とキャッシュ分離を組み合わせる。

| 製品反復の工程 | 比較方式 | 標準方式 |
| --- | --- | --- |
| xcodebuild test全体 | 494.961 / 499.626秒 | 21.652 / 13.486 / 13.482秒 |
| UI用xcodebuild build | 449.255 / 453.551秒 | 6.153 / 3.767 / 3.781秒 |
| install・launch | 再ビルドに比べ小さい | MVP内5コマンドで1.486〜1.542秒 |
| sim-use | 操作前後のprocess確認を実行 | 192コマンドで171.482〜172.814秒 |
| PID確認 | 各確認を個別表示 | 384コマンドで2.557〜2.775秒。ログは保持し、表示をUI工程へ集約 |
| manifest書込 | 個別記録を保持 | 1243回で1.732〜1.863秒 |
| run終了処理 | ソース・媒体を照合 | 0.123〜0.145秒 |

内訳には入れ子の時間があるため合算しない。xcresultの初回buildは比較方式285.569秒、標準方式267.380秒だった。SwiftSyntaxは比較方式の各architectureで約139秒、標準方式で127.089秒、SwiftParserは約66秒と64.928秒。並行区間があるため、これらも単純合算しない。標準方式の反復testのbuildは6.500秒で、開始時刻から新しく実行されたSwift compile sectionは0件だった。続くUI buildは3.893秒。xcresult内の過去のcached sectionは開始時刻で区別した。

| 比較対象 | 観測 | 評価 |
| --- | --- | --- |
| 通常testとbuild-for-testing→test-without-building | 同じwarm cacheで交互に各3回。通常testは20.386 / 14.923 / 15.087秒、分割は17.398 / 17.313 / 17.531秒 | 中央値15.087秒と17.398秒。分割の優位性は認められない |
| native architectureでのキャッシュ共用 | test 15.025秒→UI build 234.650秒→test 261.571秒 | architectureの限定だけでは構成切り替えの費用を解消しない |
| native architectureでのキャッシュ分離 | test→buildが15.161→7.226秒、14.781→5.212秒 | 構成ごとのキャッシュが反復に有効 |
| 静的検査とfixture testの直列・並行 | 直列11.111 / 8.010秒、並行6.199 / 5.875秒 | warm条件の後半の差は約2.1秒。最初の静的検査は4.490秒、以後は2.086〜2.206秒で、全試行を同条件として一般化しない |
| revisionのソースhash読取 | ファイル別のGit起動は2.793〜4.580秒、128 blob単位の読取は196ファイルで0.083 / 0.052 / 0.053秒 | binaryとファイル境界を保持したbatch読取で照合の固定費を抑えられる |

build-for-testingの比較では各回101テストが成功した。比較用wrapperとそのhashを保存し、そのrunを通常の証跡契約へ読み替えない。Swift Testingの独立したDBテストは一時DBを使い、共有UI状態はserialized suiteで扱う。複数Simulator・Xcode runnerの比較は未実施である。

## 代表編集と成果物の反映

本体条件は`app/Nibble/LibraryNotice.swift`へのコメント追加、混合条件は`app/Shared/LibraryRequest.swift`・両extension controllerへのコメント追加と、全targetの`CURRENT_PROJECT_VERSION`の1から2への変更である。コンパイル入力の変化を測るもので、製品機能の意味的な変更の評価ではない。各条件の終了時に元のbytesへの復元を照合した。

| 条件 | 比較方式の一巡 | 標準方式のtest / MVP / 一巡 | 目標と判定 |
| --- | --- | --- | --- |
| 本体 | 1163.864秒 | 27.799 / 215.216 / 243.086秒 | 581.932秒以下。約79%短縮 |
| 共通コード・両拡張・設定 | 1151.133秒 | 27.941 / 221.367 / 249.363秒 | 575.567秒以下。約78%短縮 |

一巡には生成物の確認等も含むため工程時間の和とはわずかに異なる。前後各1回であり、反復と同じばらつきの保証はしない。本体→混合の連続測定窓は比較方式2314.921秒、標準方式492.271秒で、2巡の完了数は3.110巡/時と14.626巡/時だった。

標準方式の各工程で、本体・共有拡張・キーボードのbundle ID、ビルド番号、実行ファイルhashを記録し、両拡張がarm64であることを確認した。混合条件では両方式の全targetに番号2が反映された。ソースを復元した標準方式の成果物は、本体・両拡張とも番号1・arm64だった。

## 失敗・中断・復旧

各条件は1回ずつ測定した。失敗の終了コードと診断を保存し、復旧は別runで確認した。表はコマンド開始から診断を含む結果が返るまでの秒数であり、人の修正時間と最初のエラー行が出る時刻は未計測である。

| 条件 | 比較方式の失敗 / 復旧 | 標準方式の失敗 / 復旧 | 確認した結果 |
| --- | --- | --- | --- |
| compilerの#error | 4.431 / 8.365 | 4.065 / 6.635 | 意図した診断と非ゼロ終了 |
| テストの期待bundle ID不一致 | 30.848 / 11.387 | 32.244 / 11.682 | 1テストの失敗。検出時間の短縮は認められない |
| UI出力の期待値不一致 | 15.891 / 17.221 | 13.083 / 15.975 | 原文の不一致、失敗結果、録画 |
| 3秒timeout | 同条件は未測定 | 3.444 / 17.712 | process groupの停止・回収、失敗保存、別runでの復旧 |

製品の通知driverをUI準備中に40秒で中断した条件では、40.271秒でfailed記録が確定した。録画中断の測定ではない。テスト期待値の不一致そのものは約0.02秒で判定されたが、Xcodeのセッション準備・終了を含む固定費が残る。

## 適用限界と記録の所在

製品反復と代表編集の目標を満たし、標準方式の反復3回と代表編集は初回成功した。未起動端末の約32秒の起動待ち、テスト失敗時のセッション固定費、sim-use操作の時間は残る。追加の評価では、初回起動とビルドの重なり、テストセッションの起動・終了・xcresult確定を分けて測る必要がある。

標準の計画実行では、共通静的検査・3対象のテスト・6つのUI導線を含む一式が587.861秒、文書だけの差分に対する共通静的検査が4.117秒だった。範囲の異なる実行時間を製品のtest→MVPの一巡と混ぜない。

試行のargv・時間・負荷・run対応は`artifacts/issue37/`の`native-*/results.json`、`experiments/results.json`、`overlap/results.json`、`edits/results.json`、`failures/results.json`、`cold-start.json`に保存する。計画実行は`final-verification/result.json`、文書のみの実行は`docs-verification/result.json`。比較方式の記録は対象ソースのcheckoutの`artifacts/issue37/baseline.json`等に保存する。各runのmanifest・xcresult・ログ・画像・録画は`artifacts/ios/<run ID>/`にあり、生成物はGit管理対象外である。

媒体の確認範囲はローカル画像と録画の抽出フレームで、観測時刻と内容は各runの`review.json`に記録する。全編連続再生・媒体公開・ブラウザー閲覧、Safariへのペースト・Shortcuts・保存方式間の比較実験・extensionのOS導線の再評価は含まない。
