この文書は、nibbleの一覧取得、下書き再開、編集終了、原文保持に関する実行結果を記録する。設計上の契約は[製品設計](decisions/0002-mvp-app.md)、操作手順は[MVP手順](mvp.md)、他の対象コミットに対する結果は[製品検証の索引](mvp-validation.md)を参照する。

## 対象と結論

対象実装は `888dec0aaee636277bb7ac8ac758bf6fcb7eb74d`。本体アプリ`Nibble`と共有拡張`NibbleShare`をRelease構成でビルドし、製品テスト41件が成功した。失敗・skipはない。Nix共通検査はaarch64-darwinの全5項目が成功した。

製品テストの開始・終了時の入力と対象コミットのファイルhashを照合した。文書コミット `8f280dfca4e0f255a4021ffa8d24d3266558aa82` に対しても同じ検証入力であることを確認した。保存形式はschema version 1、deployment targetはiOS 26.0。

画面操作には、成功した個別観測とツールの障害で停止した実行がある。標準UI driver全体が成功した証跡はない。検索測定には両方向の差があり、高速化や性能非劣化を示す結果とはしない。

### 製品テストが確認する契約

実際のSQLiteと製品のモデルAPIを使い、次の結果を検査した。

| 契約 | 検査した結果 |
| --- | --- |
| 原文と検索 | 空白・改行・Unicodeを保持し、日本語と記号を定義した条件で検索できる |
| 下書きの順序 | DBより小さい入力番号からの保存・閉じる・破棄を拒否し、DBの入力を残す |
| 同じ入力番号の競合 | Swift Stringとして等しくてもUTF-8が異なる原文を、同一の下書き内容として扱わない |
| 回復 | 別項目への保存が競合する下書きを消さない。下書きが除去済みでも画面の入力を保存できる |
| 再開 | 一覧取得後に別接続で更新・削除された下書きを、開く時点の状態で扱う |
| 同時再開 | 2接続が同じ保存済み項目を開いた際、同じ下書きを再利用する |
| 取得範囲 | 下書き要約に本文を含めず、開くと全文を取得できる。ページの続き、フィルタ、取得上限のリセットが成立する |
| 編集状態 | 終了失敗後は入力を変更でき、終了成功後は入力変更と二重保存を受け付けない |
| 遅延書込 | 保存・破棄後の下書きが自動保存で再生成されない |
| その他の境界 | 削除・復元、項目更新競合、未知schema、破損DB、URLの許可範囲、タスク所有、コピー、View比較 |

## 検索時間

同じ端末・Release構成・ダミー本文を使い、0・20・1,000・10,000件の保存データで検索を各30回実行した。値は保存層の検索時間の中央値（ms）。MainActorの状態更新、描画、日本語入力の変換を含む操作時間ではない。

| 件数 | 検索語 | 比較対象`8dfbb18` | 対象`888dec0` |

| 20 | 東 | 0.038 | 0.038 |
| 1,000 | 東 | 0.140 | 0.118 |
| 10,000 | 東 | 0.115 | 0.123 |
| 0 | 見つからない語句 | 0.020 | 0.020 |
| 20 | 見つからない語句 | 0.025 | 0.024 |
| 1,000 | 見つからない語句 | 0.407 | 0.325 |
| 10,000 | 見つからない語句 | 4.481 | 5.576 |

10,000件の不一致検索は対象ソースの測定で遅かった。比較するソースの検索SQL・検索キー・indexは同じだが、この2つの測定だけでは差の原因を特定できない。個別の値は `artifacts/refactor-baseline/search-timing.json` と `search-timing-after.json` に保存した。

一覧が下書き本文を転送・保持しないことはデータ構造とテストで確認している。処理時間やプロセス全体のメモリ削減量は測っていない。要約件数に比例するメモリ、部分一致検索の走査、1 MB本文の入力追従は別の測定が必要である。

## 画面操作の観測

操作にはダミーデータを使った。保存済み項目はUUID `9D9739C0-D5C0-4B58-B203-80A83CDC7EBF`、検索語は `日本語コピー face850f` で追跡した。アクセシビリティツリー（AX）は画面の要素を識別するために使い、原文の保持はコピー後のUTF-8で判定した。

| 導線 | 観測 | 記録 |
| --- | --- | --- |
| 作成 → 閉じる → 下書き再開 → 保存 | 再開後に保存した本文をコピーし、空白・改行・結合文字・絵文字を含む入力と完全一致 | `20260915T234100Z-mvp-ui-262307` |
| 日本語検索 → タイトル・本文編集 → 保存 | 同じUUIDを更新し、コピーが編集後の全文と完全一致 | 同上 |
| 再度開く → 変更せず閉じる → ピン → 削除 | ピン状態、削除後の行消失、取り消し通知の表示を確認 | 同上 |
| 削除済み一覧 → 復元 → 通常一覧 | 同じUUIDの項目を再表示 | `20260915T235201Z-refactor-ui-followup-6a523e` |
| 削除 → 取り消し | ボタン表示とタップを記録。直後の画面読取は失敗。別の読取で同じUUIDの復元を確認 | `20260915T235502Z-refactor-ui-final-a19552`、`artifacts/refactor-final-state.json` |
| 復元済み項目のコピー → 編集 → 下書き破棄 → コピー | 編集画面が閉じ、対応する下書きが一覧から消える。保存済み項目は残り、破棄前後のコピーが原文と完全一致 | `20260915T235808Z-refactor-ui-observation-8342c1` |

最終行のrunは、起動済みアプリの観測として成功した。run内にビルドを含まないため、単独ではソースを証明する証跡として扱わない。それ以外の表中runは、以下の理由で全体の結果が失敗である。

### ツールの失敗と保証範囲

| run | 停止した理由・条件 |
| --- | --- |
| `20260915T231759Z-mvp-ui-f096d6` / `20260915T232728Z-mvp-ui-bf83ac` / `20260915T233138Z-mvp-ui-d7d8ab` | 標準driverのsim-useプロセス一覧取得、またはApple CLIの起動タイムアウト |
| `20260915T233713Z-mvp-ui-7e5758` | Native TextFieldのAX valueが前後空白を省き、画面値と原文の完全一致判定が失敗 |
| `20260915T234100Z-mvp-ui-262307` | 削除取り消しの要素解決時には6秒の通知期限を過ぎていた |
| `20260915T235201Z-refactor-ui-followup-6a523e` | 表示済みの削除メニューに対するAX再取得がtranslation objectエラーで失敗 |
| `20260915T235502Z-refactor-ui-final-a19552` | 取り消しボタンをタップした直後のsim-use UI取得プロセスが終了コード`-11`で停止 |

補助driverは `artifacts/refactor-ui-v1.py`、`refactor-ui.py`、`refactor-ui-followup.py`、`refactor-ui-final.py`、`refactor-ui-observation.py` に保存し、各runに使用したファイルとSHA-256を記録した。AX valueの表示比較と原文の検査を分けるdriverでは、保存・コピー後のUTF-8を完全一致で照合した。

ビルドを含む補助driverはAppleの`launchctl list`で起動PIDとbundleを確認する。sim-useのcrash detectionの基準状態はリセットできていない。`followup`・`final`・`observation`は `SIM_USE_NO_CRASH_DETECT=1` と `SIM_USE_NO_DAEMON=1` を使い、`final`・`observation`のタップは直前のUI読取で得た要素aliasを指定した。これらの操作方法は標準driverの成功を意味しない。

失敗runのmanifestは失敗のまま保存している。個別の成功した観測を、run全体やソース照合の成功へ読み替えない。

## 未完了の検証条件

- 標準UI driverによる、ビルドから全導線までの一貫した成功run。プロセス取得とAX取得の障害を解消する必要がある。
- 実機、iOS 26.0での実行、VoiceOver、日本語IME変換、共有元アプリをまたぐ取り込み、1 MB入力の描画計測、長時間利用、署名配布。これらは本記録の対象ソースで確認していない。
- GitHubへのpush、PR作成、画像・動画のアップロードと外部閲覧確認。ローカル媒体の存在だけではPRの証跡添付は完了しない。

実機検証はMVPの受け入れ範囲外である。Simulatorで確認できる日常操作と、実機の性能・データ保護・配布条件を分けて評価する。
