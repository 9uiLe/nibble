# 利用者評価に使う研究と限界

以下の原著を2026-09-13に確認した。操作の少なさ、速さ、誤り、理解を分けて評価するために使い、論文の係数をnibbleの性能予算へ転用しない。採用UIは[F共通原則](../design/foundations.md)、評価対象は[G課題](../design/audit.md)、機械的な計測は[性能手順](../performance-verification.md)を正本とする。

| 根拠 | 製品の評価に使う知見 | 適用限界 |
| --- | --- | --- |
| [MacKenzie, KSPC, 2002](http://www.yorku.ca/mack/hcimobile02.html) | 打鍵の節約と候補探索・誤り修正を分ける。検索語入力から貼付先へ戻るまでを評価する | 英語コーパスと仮定した手順の分析。日本語IMEやnibbleの利用者実験ではない |
| [MacKenzie & Buxton, 1992](http://www.yorku.ca/mack/CHI92.html) | 横長の行でも高さ・接近方向・隣接操作を評価する | 12人のマウス/CRT実験。親指の選択時間へ係数を使わない |
| [Parhiほか, 2006](https://www.cs.umd.edu/hcil/trs/2006-11/2006-11.pdf) | 物理寸法・保持方法・単発/連続入力をそろえて比較する | 右利き20人、立位、特定PDA。9.2/9.6 mmの提案をiPhoneのptへ一律変換しない |
| [MacKenzie & Ware, 1993](http://www.yorku.ca/mack/CHI93b.html) | 応答遅延と誤りを同時に測り、重複操作と完了通知も確認する | 8人のマウス選択実験。75/225 msは普遍的な知覚境界ではない |

KSPC・2次元選択・遅延の文献は著者の大学公開HTMLの本文・方法・結果・限界、親指操作は原著PDFの本文と結果表を確認した。製品の予算は、製品のデータと操作条件で測定して定める。

## nibbleでの評価

コピーして元の作業へ戻る、目的の本文を探す、下書きを再開する、誤削除から復旧する、という完了地点を先に定める。操作回数と総時間、誤選択、やり直し、説明が必要だった箇所を記録し、初見と学習後を分ける。自動driverの待ち時間や録画長は人の完了時間ではない。

44 ptの主操作、下部配置、使用回数順は製品の選択であり、すべての利用者に最適と確認した結果ではない。片手・左右・小画面・支援技術で評価する。Appleの指針とOS対応は[R台帳](../design/evidence.md)を参照する。
