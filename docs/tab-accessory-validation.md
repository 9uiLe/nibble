# タブ通知の検証記録

## 対象と環境

Issue #26の一覧・検索タブの操作完了通知と削除取り消しを対象とする。採用契約は[タブに付随する操作完了通知](design/decisions/0004-tab-accessory.md)を参照する。検索中のシステム配置について未解決事項があるため、本機能の受け入れは未完了。

- 対象ソース: `ecacb21a8eaca320ef3927d92593f09ae44f9703`。比較元は`5d9d2fe651bfafe8eecb7a1c7b78a337f754acfb`。
- 確認日: 2026-09-19。Xcode 26.5 (17F42)、Swift 6.3.2、iOS 26.5 (23F77)。
- 専用Simulator: iPhone SE (第3世代)、375×667pt、UDID `A566331E-BF10-48B5-9A79-74D7177430EF`。
- Release / `-Osize`、テストと診断用UIのbuildは`ENABLE_TESTABILITY=YES`。通常の配布archiveとの同一性を示す検証ではない。
- UI操作はNixで固定したsim-useを使い、App Groupの既存DBをバックアップしてダミーデータへ置き換え、run終了時に復元する。

## 自動テストと共通検査

`ios.py test --project-config app/project.json --configuration Release --device <上記UDID>`のrun `20260919T083131Z-test-77c281`で115件・13 suiteが成功した。対象ソースとの`check_evidence.py --integrity-only`照合も成功した。

通知は表示開始前には読み上げ・触覚・期限を発生させず、同じIDの再表示では期限と効果を再利用する。新しいID、旧期限との競合、キャンセル後の再開、タブ・シート・非active化、遅れて完了するコピー・削除、現在のUUIDだけの復元、復元の重複防止と失敗表示をテストした。

UIKit接続のマウントテストは、26.5上でaccessoryの追加・除去、選択中の子コントローラーの同一性、非表示時のsafe areaの復帰を確認した。26.0 runtimeでの評価には代えない。

`nix flake check --no-update-lock-file --print-build-logs`は7項目すべて成功した。規約レビューで指摘された非キャンセル例外の握りつぶしと通知規約の更新漏れは修正し、読み取りで再確認した。

## 一覧の画面操作

run `20260919T083647Z-accessory-ui-6b1757`は12件のダミーデータで成功し、対象ソースとの証跡照合も成功した。コピー→消去、削除→取り消し→消去、ダークで長い対象名を持つ削除、削除直後のコピーを操作した。取り消したUUIDがDBで`deleted = 0`になったことを照合した。

- コピー通知は対象名・取り消しを持たず、削除通知は対象名と44pt高のボタンを持つ。削除直後にコピーすると復元対象とボタンが同時に消える。
- 意味情報は省略前の対象名と結果を持ち、取り消しは独立したButtonとして現れる。実際のVoiceOver操作は未実施。
- コピー前・表示中・消去後の先頭行はy=186ptを保つ。新規作成ボタンはy=520→464→520ptで、非表示時に元の下部領域へ戻る。
- ライト／ダークの画像とコピー・削除・復元・消去の画像を開いて確認した。動画は15.658秒の原本から1.202、8.047、13.378秒の3フレームを確認した。全編再生、アップロード、ブラウザー閲覧は未実施。
- 変更前の同じ12件の画像は比較元のrun `20260919T083305Z-accessory-ui-3c31b8`で取得し、比較元ソースとの照合と画像の目視を完了した。

システムが非表示にしている間に期限だけが進む現状は、Issueの「画面に通知を出した時点から計測する」「キーボード表示中も結果を読み取れる」を満たさない。検索中だけ別配置を許容するか確認中であり、検索を検証済みとして扱わない。

追加run `20260919T084308Z-accessory-ui-772779`では、削除通知から別タブへ移動して戻る、編集シートを開閉する、ホームへ移動して同じプロセスへ戻る操作を確認した。各復帰でnibbleのbundleと「一覧」の見出しを読み取り、終了した通知とUndoが再表示されないことを確認した。リスト末尾まで移動して最後の項目をコピーでき、コピー後も末尾付近の表示を保った。使用回数による並び替えでコピー対象自体は先頭へ移動するため、同一項目の位置の不変とは区別する。対象ソースとの照合は成功し、末尾の画像も目視した。

### 検証driverの失敗

`20260919T084005Z-accessory-ui-fff7b5`では、ホームへ移動した直後に`simctl launch`で復帰を試みたが、ホーム画面のままだった。通知がないという条件だけでは別アプリの画面も通過したため、このrunのバックグラウンド復帰は確認済みとしない。`20260919T084155Z-accessory-ui-d408d2`ではホームへのアニメーション中に画面を読み取り、中断した。

driverを、ホームへの遷移を待ってホーム画面のbundleを照合し、観測したnibbleアイコンから戻る手順に変更した。通知の不在を検査するときも、nibbleのbundleが前面にあることを要求する。

## 通知とスクロールの負荷

同じSimulator・Release / `ENABLE_TESTABILITY=YES`・1万件のダミーデータで、5回のコピー対象タップ、上下一組のスワイプを5回、通知の消去待ちを1試行とし、3回測定した。hostの`ps`が返すnibbleプロセスの累積CPU時間の差を使う。分解能は0.01秒で、描画以外のアプリ処理も含む。wall時間はdriverの待機やUI読取を含み、操作遅延やフレーム時間を示さない。

| 対象 | CPU秒（3試行） | 中央値 | wall秒（3試行） |
| --- | --- | --- | --- |
| 比較元 `5d9d2fe` | 2.03 / 1.93 / 1.92 | 1.93 | 22.304 / 22.837 / 22.816 |
| 実装 `ecacb21` | 2.30 / 2.06 / 1.95 | 2.06 | 22.840 / 22.629 / 22.312 |

中央値は+0.13 CPU秒（約6.7%）。3試行の限定的な比較であり、高速化、実機の負荷、FPSやhitchの許容値達成を主張しない。runは比較元`20260919T083417Z-notice-cpu-686e78`、実装`20260919T083807Z-notice-cpu-2ec0f9`で、両方の対象ソースとの照合が成功した。
