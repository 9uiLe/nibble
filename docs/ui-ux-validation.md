## 確認中に検出した問題

- 回復・復元などでButtonの外側に最小寸法を指定しても、AXに報告されるボタン本体は20×18 ptや151×34 ptだった。反復操作はラベル内部で領域を確保し、回復と空状態は標準のlargeサイズを採用した。確認対象の実寸を補助driverの合格条件に加えた。
- run `20260917T085114Z-ux-adaptation-2f783b`では親のエラー識別子が回復ボタンに引き継がれた。識別子を見出しとボタンに分け、空白検索でも回復操作を独立して参照できる構成にした。
- 補助driverのメッセージなし例外が失敗理由を空にするケースを検出した。製品driverは例外の表現を保存し、空の例外でも失敗終了する回帰テストを追加した。exit 1のrun `20260917T084434Z-ux-adaptation-9a9e8d`は成功した証跡に使用しない。
- 小型画面でシートや確認を閉じる途中に、画面読取が一時的に空になるケースがあった。補助driverは対象アプリの生存を確認したまま、対象アプリの空の成功応答に限り最大5回の読取を行う。非ゼロ終了や別のエラーを無視しない。


- run `20260917T082515Z-mvp-ui-71d910`で、見出しの固有幅を確保しない変更により「一覧」が省略された。短いルート見出しの幅を確保する実装を採用した。
- run `20260917T083058Z-ux-adaptation-a33019`は、simctlのApp Group直接指定が失敗した。列挙されたGroup IDとパスの対応を使うdriverへ修正した。製品の保存失敗ではない。
- `d6b0b27c9882e239d56edf9ddefcd45a1ccddbda`のSE run `20260917T083658Z-ux-adaptation-98f1c0`は、最大文字で画面外のメニューを待つ確認が失敗した。ピン留め集合の重複見出しを省く実装と、スクロールして操作へ到達する確認を採用した。

失敗runは成功runで上書きせず保存する。最終ソースの実行結果と、途中の観測を区別する。
