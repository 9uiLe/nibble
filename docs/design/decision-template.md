# UI判断記録

情報構造、操作の意味、主要な配置の選択を記録するためのひな形。対象の部品・画面・共通原則は[UI設計](README.md)のIDで指定する。契約内の小さな調整は[部品台帳](components.md)で管理する。

## 目的と適用範囲

- 判断名、基準日、判断者。
- 状態：提案 / 採用 / 廃止。
- 対象：部品・画面・共通原則のIDと利用場面。
- 達成条件：利用者が何を行い、どこへ戻れるか。
- 制約：原文保持、保存の契約、対象OS、データ保護。

## 採用する構成

画面の読み順、操作対象、固定・スクロール、遷移、復帰先を記す。入力中、待機、失敗、中断、復旧の状態を含める。

標準API、共通部品、状態の所有者を示す。標準操作と異なる挙動には、その必要性と利用者への説明を記す。

## 判断理由

| 候補 | 利用者の利点 | 不利益・実装運用の負担 | 採否と理由 |
| --- | --- | --- | --- |
| 案A | 具体的に記載 | 具体的に記載 | 採用 / 不採用 / 評価中 |
| 案B | 具体的に記載 | 具体的に記載 | 採用 / 不採用 / 評価中 |

- 出典：根拠資料のR番号、該当する指針、適用限界。
- 製品判断：利用場面と制約に対して採用案が適する理由。
- 仮説：期待する効果と未確認の条件。
- API適合性：最低対応OSでのavailabilityと確認方法。

## 評価条件

- 比較条件：データ、端末、文字、外観、操作をそろえる。
- 観測対象：目的への到達、取り違え、戻り、必要だった補助説明。
- 操作の成立：入力保持、対象の同一性、成功・失敗・復旧。
- 表示と入力：長文、狭幅、大きな文字、キーボード、支援技術。
- 性能：影響する指標、同条件の基準値、測定方法。
- 見直し条件：どの観測や制約の変化で再検討するか。

## 実装と検証の参照

対象コミット、ソース、run、画像・録画の閲覧先、実施した条件と結果を記す。実装状況と評価状況は別に記録する。未実施項目には理由を付ける。

利用者の感想は参加者と利用場面に結び付ける。採用した構成は部品台帳・画面構成へ反映し、実験条件と観測は検証文書へ残す。
