# 共通原則と寸法

nibbleの視覚表現は、読む内容、現在地と対象、実行する操作、操作の結果を区別するために使う。共通原則はすべての画面へ適用し、部品ごとの責務は[部品台帳](components.md)、配置は[画面構成](screens.md)に定める。

寸法の単位はiOSのpt。数値は製品の設計値であり、利用者の全条件に対する最適値を示すものではない。実装値は参照先のSwiftが正本となる。R番号は[根拠資料](../../research/06-interface-design-evidence.md)、実装との適合状況は[設計監査](audit.md)を参照する。

## F01 表示の層

| 層 | 内容 | 表現と理由 |
| --- | --- | --- |
| 内容 | スニペット、下書き、説明文 | 連続した背景面で読み比べられるようにする |
| 構造 | 画面タイトル、フィルター、区分見出し、区切り線 | 現在地、集合、項目の関係を示す |
| 操作 | タブ、ツールバー、新規作成 | 内容から分離した操作として識別する |
| 結果 | 読込、完了、失敗、復元 | 内容との関係を保ち、次の行動を判断できるようにする |

Liquid Glassは標準ナビゲーションと浮く新規作成に使う。本文は共通の一覧面に置き、一時的な通知のまとまりには標準の半透明素材を使う。操作を見つけやすくしながら、文字の読み比べを優先する構成である。（R15・R18）

評価では、重なり、強調の数、透明度の変更、コントラストの強調によって内容と操作の区別が失われないことを確認する。

## F02 色の意味

| 色 | 意味 | 主な用途 |
| --- | --- | --- |
| `nibbleCanvas` | 文字を載せる連続した面 | 行、見出し周囲、画面の余白 |
| `nibbleAccent` | 製品の識別、操作と選択の補助 | 主な操作、ピン、選択フィルター |
| `.primary` | 読むべき名前と本文 | 行タイトル、入力、説明 |
| `.secondary` | 主情報を補う内容 | 要約、フィールドラベル、補足 |
| システムの破壊的操作色 | 破棄、完全削除 | 破壊的なボタン。失敗の説明は記号・見出し・primary文字で識別する |
| システムの区切り線 | 隣接項目の境界 | Listの行、フィルターの下 |

ライト外観はクリーム色と錆色、ダーク外観は暗いグレーとオレンジを用いる。温かい色と抑えた背景で、文字を中心にした道具としての表情を作る。この配色による印象はブランド上の仮説として評価する。コントラスト設定には追従せず、各外観で同じ配色を使う。RGBは[NibbleTheme.swift](../../app/Shared/NibbleTheme.swift)で管理する。

S09のキーボードは、入力先とシステムキーボードの一部として使うため、OSの`UIInputView`のkeyboard背景とニュートラルな前景色で構成する。本体のブランド色は適用しない。背景を覆わないホストView、標準の選択コントロール、独立した入力キーとコピーキーで構成する。公開システム色のキー面と隙間が操作単位を示し、主文字・補助文字で情報を階層化する。具体的な余白と操作領域は[キーボード設計](../decisions/0005-snippet-keyboard.md#レイアウトと操作の意味)に定義する。

文字のコントラストは4.5:1以上を目標とする。識別に必要なアイコンや選択状態は3:1以上を目安とし、文字、形、読み上げる状態を併用する。C04の視覚的な選択は文字・塗り・枠の配色で示し、チェック記号は置かない。読み上げには選択状態を付与する。補助文字も読むための情報として扱う。（R15〜R17）

評価対象は前景と背景の組合せである。独自背景とシステム色、半透明素材、スクロール下の内容、ライト・ダーク、コントラストを上げる設定、透明度を下げる設定を確認する。単色RGBの計算結果は[監査記録](audit.md#単色のコントラスト計算)にある。

## F03 文字と図記号

| 役割 | 表現 | 判断理由 |
| --- | --- | --- |
| ルート画面の現在地 | `title3`、太字、標準バー内 | 短い見出しで現在地を示し、内容の表示面積を確保する |
| 保存済み項目の識別 | `headline`、最大2行 | 項目を選ぶ手掛かりを最も強く示す |
| 本文の要約 | `subheadline`、secondary、最大2行 | 名前だけで不足する文脈を補う |
| 編集タイトル | `title2`、semibold、縦に伸びる入力欄 | 任意の識別名を本文と区別する |
| 編集本文・説明 | `body` | 日本語、改行、Unicodeを読みやすく表示する |
| フィルター・操作 | `subheadline`、semibold | 短い選択肢を同じ尺度で提示する |
| 補足 | `footnote` / `caption` | 主情報との階層を示す |
| ピン・コピー・作成 | SF Symbols | 操作・状態の標準的な記号を使う |

システムの文字スタイルをDynamic Typeのlargeで固定し、見出し・本文・補足の階層を維持する。端末の文字サイズと太字設定には追従しない。行や入力欄の高さ、折返し、配置は内容に応じて調整する。意味を担うアイコンは文字とともに識別できる大きさで表示する。（R14・R16）

省略した内容には全文を読む手段を設ける。同じ先頭の本文や長い名前は、行数制限によって対象を取り違えないかを評価する。1行のルートタイトルは狭幅と端末の文字設定変更で配置が変わらないことを確認する。

ピンは状態、コピーは実行、見出しは構造を表す。読み上げでは役割と操作対象を伝え、装飾記号を重複して読ませない。実装は[行](../../app/Nibble/SnippetRowContent.swift)、[画面タイトル](../../app/Nibble/LibraryView.swift)、[編集](../../app/Shared/SnippetEditor.swift)を参照する。

## F04 余白と整列

余白には、同じ情報を結び付ける、異なる項目を区切る、操作同士の誤接触を避ける、という役割がある。標準Listとツールバーの余白を基礎に、内容の関係に必要な間隔を加える。（R03・R04・R07）

| 関係 | 寸法 | 判断理由と評価条件 |
| --- | --- | --- |
| 同じ項目内 | 下書きの文字間4、ピンと名前6、名前と要約7 pt | 隣の項目より近く配置し、一つの情報として読む |
| 独立した操作間 | 行の内容とコピー8、フィルター間8 pt | 操作の境界を見分け、操作領域の重なりを防ぐ |
| 部品のまとまり | 通知と作成12、本文ラベル周囲12、通知内16 pt | 読む領域と押す領域を分ける |
| 左右の余白 | フィルター・作成16、通知内20、編集24 pt | 一覧の密度、通知の操作、長文の読みやすさに合わせる |
| 入力グループ間 | 24 ptと標準Divider | タイトルと本文を別の意味の入力として示す |
| 上下の余白 | 行4、フィルター4、通知8、作成下8 pt | 内容と操作を離し、標準部品との接触を防ぐ |
| 空状態 | 上下30 pt | 案内と次の行動を一つのまとまりとして示す |
| Listの内容上端 | スクロール内容の上余白0 | バーやフィルターの下に内容を続ける |

行の上下余白は標準行の余白への追加値であり、行全体の高さではない。内容上端の0 ptも、端末のセーフエリアを除く指定である。実装は[LibraryScreen](../../app/Nibble/LibraryScreen.swift)、[SnippetRowContent](../../app/Nibble/SnippetRowContent.swift)、[SnippetEditor](../../app/Shared/SnippetEditor.swift)が所有する。

寸法の変更は、識別性、操作領域、本文の見える量を同じ条件で比較して判断する。共通定数を設ける場合は、数値の一致よりも変更理由の一致を基準にする。

## F05 操作領域と形

| 部品 | 見た目と操作領域 | 判断理由 |
| --- | --- | --- |
| コピー・その他 | `body`の記号、コピーには8 ptの内余白、最小44×44 ptの操作領域 | 多数の行で本文の幅と反復操作の領域を両立する |
| 新規作成 | `title3`の記号、最小56 ptの円と同じ操作領域 | 画面内の作成入口を独立して識別する |
| フィルター | 高さ36 pt以上の面、44 pt以上の操作領域 | 同じ役割の選択肢を同じ尺度で扱う |
| 空状態の作成・対象変更 | 標準のlargeサイズのボタン | 初回や集合変更の次の行動を、押しやすい文言付きの入口で示す |
| 復元・追加取得 | 標準部品、44 pt以上の操作領域 | 短いラベルや記号でも操作しやすい領域を確保する |
| 保存済み行の内容 | 最低60 pt、内容に応じて伸長、外側に余白 | 複数行の識別と一覧の密度を両立する |
| フィルター・コピー背景 | 角丸10 pt | 小さい操作部品のまとまりを示す |
| 通知背景 | 角丸20 pt | メッセージと復元操作をまとめる |
| 標準タブ・検索・キーボード・シート | システムが寸法と外形を管理 | OSによる適応と操作の一貫性を保つ |

44×44 ptは独自の反復操作へ適用するnibbleの基準である。表の独自フィルターはC04を指す。C45の標準segmented Pickerは標準部品の寸法・操作領域を使い、下段の更新・終了や独立したコピーには44pt以上を確保する。Appleの数値の適用範囲はR07・R16に記載する。表示する形と操作領域の関係を確認し、隣接要素へのタップやスクロールを奪わないようにする。

最小56 ptの作成、コピーの内余白、角丸の値は、識別性と占有面積を調整する設計値である。文字設定を変えた場合の固定表示、狭幅、片手操作で評価する。

## F06 固定領域と可変領域

| 領域 | 配置の契約 | 理由 |
| --- | --- | --- |
| 画面タイトルとタブ | 移動先と現在地を保持する | 画面内の位置を見失わずに移動できる |
| 一覧フィルター | タイトル直下に固定する | 表示集合を確認・変更できる |
| 本文と説明 | 縦スクロールし、文字に応じて伸びる | 件数や長文を限られた高さへ押し込まない |
| 作成と通知 | `safeAreaInset`で下部領域を確保する | 最終行まで操作でき、OSのバーと重ならない |
| 検索入力中 | 標準検索欄とキーボードを優先する | 入力・修正・終了を一つの文脈で扱う |
| 左右設定 | 作成とコピーの物理的な側へ適用する | 利用者が持ち方に合わせて操作位置を選べる |

文章の読み順とシステム検索の配置は、左右設定の対象に含めない。本体の入力欄はキーボードやタブの高さをシステムから受け取り、推測した固定値で内容を配置しない。S09は入力面そのものを提供するため内容高を提案するが、OSの必須制約を優先する。

固定領域には本文の面積を使う負担がある。部品の追加時は、狭幅、固定した標準文字、キーボード併用で内容末尾と必要な操作へ到達できることを確認する。

## F07 状態と結果

| 状態 | 伝える内容 | 成立条件 |
| --- | --- | --- |
| 初期読込 | 内容を取得している | 空であると確定する前に読込を終える |
| 更新中 | 表示中の内容と取得要求の関係 | 選択変更の時点で未取得と判定し、古い取得の終了で新しい要求を完了にしない |
| 完了 | 何の処理が終わったか | 永続化・コピーの完了後に示す |
| 空 | 空である理由と次の行動 | フィルター・検索・削除一覧で文脈を分ける |
| 失敗 | 失敗した操作、保持される内容、回復方法 | 入力と操作対象を失わず、回復手段を見つけられる |
| 削除 | 取り消し対象と復元方法 | 通知の期限後も削除一覧から復元できる |

取得結果はフィルター・検索語・取得上限と一組で保持する。集合を変更するときは取得済みの一覧をその区分のまま保ち、先頭で新しい集合の読込を伝える。表示中と選択中の集合が異なる間は行の操作を無効にし、結果と区分を同時に置き換える。空表示は選択中の集合を取得し終えた場合だけ成立する。読込失敗では別の集合の内容を隠して回復操作を示す。同じ集合の更新・追加取得では既存の行と操作を維持する。

検索前案内と失敗は同じListに置き、失敗の説明を先に読む。取得の失敗と操作の失敗を別々に保持し、取得成功で無関係な操作失敗を消さない。明示的な再取得は確認済みの操作失敗を閉じるが、その操作を再実行しない。

本体の通常の通知は2秒、削除取り消し付きは6秒表示する。削除・復元の対象名と取り消すUUIDは同じ通知に保持する。通知は視覚表示と読み上げで伝え、コピーには触覚も用いる。読み取りや操作に必要な時間は利用者・条件により異なるため、通知期限に依存しない復元経路を維持する。（R10〜R13）

S09の結果文は、入力先とキーボードを見比べてから確認できるよう、次の操作まで保持する。期限付き通知や本体の触覚を共通仕様として移植せず、キーボードの操作と寿命に従う。

## F08 動き

画面遷移、検索、キーボードの動きは標準部品が担当する。独自の通知は透明度の変化で出入りを表し、Reduce Motionの設定にかかわらずease-out 160 msとする。作成ボタンの位置と本文の操作を安定させながら、状態変化を伝えるためである。

動きの管理は用途で分ける。SwiftUIの通知はScopedAnimationで範囲を定め、無関係な本文やフィルターへ変化を広げない。C44の説明イラストはRMLのタイムラインと状態遷移を使い、ホストが表示環境を渡す。

説明イラストはコピー元・複製・保存先の関係を自動ループで示し、Reduce Motionの設定にかかわらず同じ動きを使う。文章による説明を併設し、表示範囲外とバックグラウンドではフレーム進行を止める。動きが意味を伝える効果、読書への注意の影響、描画負荷は別々に評価する。具体的な構成と契約は[演出設計](../decisions/0004-rive-presentation.md)に定義する。（R11・R16）

## F09 文言とデータ

操作名は結果を表す。「保存」は利用対象への確定、「閉じる」は下書き保持による中断、「下書きを破棄」は編集内容の除去、「完全に削除」は復元不能な除去を意味する。

タイトルと本文の原文を保持し、コピーには本文全体を使う。要約・省略は表示だけに適用する。本文が空または空白・改行だけなら保存できない理由を入力欄で説明する。ペーストは末尾への追加と明示する。失敗や確認の文言は、対象と結果、利用者が取れる行動を伝える。（R13、[データ契約](../decisions/0002-mvp-app.md#データの意味と永続化)）

## F10 表示設定の境界

文字サイズはlarge、太字設定はregular、コントラストはnormalで固定する。Reduce Motionは独自の通知・説明イラストへ接続しない。ライト・ダーク、画面幅による折返し、操作の左右設定はそれぞれの目的に従う。本体と共有拡張の入口で適用し、画面ごとにOS設定による分岐を追加しない。

OSが所有するズーム・色フィルタ・標準素材などの範囲、読み上げ情報の扱い、採用理由と評価条件は[表示設定の固定](decisions/0002-fixed-interface.md)に定義する。
