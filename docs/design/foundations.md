# 共通原則

全画面へ適用する意味と評価基準を定める。F番号は共通原則、R番号は[外部根拠](../../research/06-interface-design-evidence.md)である。操作導線は[画面](screens.md)、個別の責務と代替案は[部品](components.md)に置く。

## F01 表示の層

内容は連続した面、操作は対象の近く、短時間の結果は内容を動かさない別層へ置く。カードを増やして境界を強めるより、文字と区切りで一覧を読み比べられることを優先する。通知・キーボード・シートを重ねても主要な入力と操作を妨げない。（R03・R04）

## F02 色の意味

本体のcanvasは読む面、accentは操作と選択の補助、primary/secondaryは情報の主従を表す。ライトはクリーム/錆色、ダークはグレー/オレンジを用いる。温かい印象は製品の仮説であり、可読性の実証と区別する。集合の選択にはニュートラルな濃淡反転、再開帯と行のコピーには淡いaccent、独立した作成にはaccentの塗りを使う。Liquid GlassはOS標準タブに任せ、内容面へ広げない。RGBは[Theme](../../app/Shared/NibbleTheme.swift)を正本とする。

KeyboardはOSの背景とニュートラルな文字を使い、青を主操作と挿入結果に限定する。意味を色だけへ依存させず、文字・形・読み上げ状態を併用する。文字4.5:1、識別に必要な非文字3:1を目安に、ライト/ダークと半透明素材の実画面で評価する。単色計算だけでは合格にしない。（R15〜R17）

## F03 文字と図記号

見出し、項目名、本文、補足の順に強さを付ける。一覧・編集・説明画面の本文は共通のFont.nibbleBody、項目名・入力タイトル・説明内の見出しはFont.nibbleTitleを使う。書体・サイズ・太さ・標準行間を揃え、文字色は各画面の意味を維持する。定義は[Theme](../../app/Shared/NibbleTheme.swift)を正本とする。システムの文字スタイルをlargeで固定し、本文の高さと折返しは内容に合わせる。長い名前や同じ先頭の項目を省略表示だけで取り違えないよう、全文への入口を持つ。

SF Symbolsはピン=状態、コピー=実行、見出し=構造という意味を支える。装飾の重複読み上げを避け、対象名と操作名を伝える。個別の文字値は各View、設定の境界はF10に従う。（R14・R16）

## F04 余白と整列

同じ項目の情報は近接させ、項目間と独立操作の間は区切る。標準List/toolbarを基礎に、safe areaと内容幅に合わせる。余白の実値は実装を参照し、同じ数値を台帳に転記しない。狭幅・長文・最終行で、情報のまとまりと操作間の誤接触を評価する。（R03・R04・R07）

## F05 操作領域と形

操作領域は44×44pt以上を基準とし、記号の見た目と分けて確保する。paddingがボタン外側だけにあると空間が増えても押せる範囲は増えないため、実際のhit領域で確認する。

主操作、対象に従属する操作、破壊的操作を形・名前・配置で区別する。密度を上げる場合も、隣の編集とコピー、挿入と全文表示が同時に動かないことを確認する。（R07・R16）

## F06 固定領域と可変領域

対象集合の選択と終了操作は見失わない位置へ、長い内容はスクロール可能な領域へ置く。一時通知の出入りで一覧・タブ・作成位置を動かさない。キーボード併用時の表示と操作は各画面の契約に従う。具体的な読み順はS台帳、通知層は[通知設計](decisions/0004-result-notices.md)に定める。（R03・R05）

## F07 状態と結果

未取得・処理中・0件・失敗・中断・成功を区別する。進行割合を測れなければ割合を表示しない。失敗は対象と回復手段を持ち、入力/検索語を保持する。成功は短く伝え、確認を閉じる追加操作を要求しない。取消可能性と完全削除の確認を分ける。（R10〜R13）

## F08 動き

動きは操作結果や内容の関係を説明する範囲に限定する。SwiftUIはScopedAnimation、説明図はRML、標準部品はOSが所有する。[演出設計](../decisions/0004-rive-presentation.md)に従い、文章だけでも意味を理解できるようにする。効果は理解度と読書への影響で評価する。（R18・R19）

## F09 文言とデータ

文言は、利用者が操作する対象、操作後の結果、必要な条件、次の行動を理解するために使う。判断の優先順は正確さ、意味の理解、馴染みのある語彙、簡潔さ、一貫性とする。保存・削除・権限の条件は、短い表現に収める場合も明示する。

説明は落ち着いた「です・ます」調で書く。平常時は用途と手順を簡潔に伝え、失敗時は完了した処理、失敗した処理、残っている入力やデータ、回復方法を具体的に伝える。再試行は表示中のボタンか到達できる設定先へ結び付ける。入力が画面に残っていることと、保存が成功したことを区別する。操作説明には比喩・冗談・擬人化を使わない。

### 語彙と操作の意味

「項目」は一覧で選ぶ一件、「本文」はその項目からコピー・挿入する内容である。内部の型名を知らなくても、保存・編集・利用の関係が分かる語を使う。

| 語彙 | 意味と使い分け |
| --- | --- |
| 文章やURL／項目／本文 | 保存できる対象は「文章やURL」、一覧の一件は「項目」、入力欄とコピー・挿入する内容は「本文」と呼ぶ。UIでは内部のSnippet型を説明するための「スニペット」という語を使わない |
| コピー／ペースト／入力・挿入 | コピーは本文をクリップボードへ置く。ペーストはiOSの標準操作名を使い、編集画面のボタンには本文末尾への追加だと補足する。キーボードの「入力する」は入力先への挿入要求を表す。入力先での反映・保存は利用者が確認する |
| 保存／下書き／閉じる | 保存済み項目は一覧やキーボードから利用する内容、下書きは編集を再開する内容。「閉じる」は下書き保存の成功を待って戻る。空の新規入力・未変更の保存済み編集では下書きを残さない |
| 破棄／削除／完全に削除／復元 | 破棄は編集中の下書きを除去する。削除は項目を復元可能な状態へ移す。完全削除は項目と関連下書きを除去し、元に戻せない。削除済みから戻す操作は「復元」、直前の削除通知からの取り消しは「元に戻す」と呼ぶ |
| 回数と日時／最後のコピー | 本体のコピー回数と最終コピー日時を表す。閲覧・編集・キーボードの使用は含めない。「回数と日時を記録し直す」は記録の再試行であり、本文をコピーし直さない |
| フルアクセス | キーボードのコピーとピン留めの変更に必要なiOSの許可。全文確認と入力は許可なしで使える。設定先、許可が必要な操作、許可なしで使える操作をそれぞれ説明する |

### 文言の役割と表記

見出しは対象・状態、ボタンは操作を表す。保存・コピー・編集・削除などの短い操作名では「する」を省略できる。「ピン留めを解除」のように対象が必要な操作名は対象を含める。説明文には句点、確認文には疑問符を付け、見出し・ボタン・短い完了通知には句点を付けない。操作名は「」で引用し、順路は→で示す。

iOSの設定と標準編集メニューは実際の名称で案内する。アイコンの読み上げには対象と操作を補い、可視文言と同じ意味を伝える。許可によって操作が設定案内へ変わる場合も、そのタップで起きる結果を読み上げる。

入力条件は常設ラベルと補足で伝える。プレースホルダーは入力例に使い、任意・必須・長さ制限の唯一の説明にはしない。UTF-8のバイト数を固定の文字数へ換算せず、表示用の省略や検索用の正規化を原文へ逆反映しない。

具体的な文言と理由は[日本語UIの文言設計](copy.md)、外部指針の確認範囲は[R13](../../research/06-interface-design-evidence.md#r13-文言)を参照する。語彙・文体・優先順位は製品の判断であり、理解度はG05・G07〜G09・G11の利用者評価で確かめる。

## F10 表示設定の境界

[表示固定方針](decisions/0002-fixed-interface.md)を全入口へ適用する。文字large・通常の太さ設定・通常contrast・独自演出を固定し、ライト/ダークには追従する。VoiceOverの意味情報やOS所有UIの内部挙動は別の契約として維持する。（R14〜R19）
