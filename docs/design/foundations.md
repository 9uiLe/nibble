# 共通原則と寸法

この文書は、画面全体に適用する視覚・操作の意味を定める。個別部品は[部品台帳](components.md)、配置は[画面構成](screens.md)を参照する。R番号は[一次資料](../../research/06-interface-design-evidence.md)に対応する。

## F01 情報と操作の層

- **内容**：スニペット、下書き、説明文。連続した`nibbleCanvas`の面へ置き、文字を読むことを主役にする。
- **構造**：画面タイトル、フィルター、区分見出し、区切り線。現在地と内容の関係を示す。
- **操作**：標準タブ、toolbar、新規作成。内容の上にある操作として区別する。
- **結果**：進行、完了、失敗。対象の近く、または継続して見つけられる位置に出す。

Liquid Glassは標準ナビゲーションと浮く新規作成へ限定する。本文行をガラスのカードにしない。通常のmaterialは一時的な通知のまとまりに使う。これはR15・R18を内容中心のアプリへ適用した判断である。

見直す条件：内容と操作が重なって読めない、強調が多く選択に迷う、Reduce TransparencyやIncrease Contrastで識別できない。

## F02 意味のある色

| 役割 | 指定する意味 | 使用先 | 使用しない意味 |
| --- | --- | --- | --- |
| `nibbleCanvas` | 文字を載せる連続した面 | 行、見出しの周囲、画面の余白 | 選択、失敗、操作可能性 |
| `nibbleAccent` | 製品の識別、操作と選択の補助 | 主な操作、ピン、選択フィルター | エラーや警告の代用 |
| `.primary` | 読むべき本文・名前 | 行タイトル、入力、説明本文 | 状態ごとの独自な色分け |
| `.secondary` | 主情報を補うもの | 要約、フィールドラベル、補足 | 読めなくてもよい文字という意味 |
| system destructive / error | 破棄・完全削除・失敗 | destructive role、エラーのラベル | 通常の強調 |
| system separator | 隣接項目の境界 | Listの行、固定フィルターの下 | 情報の階層をすべて代替する装飾 |

lightのクリーム・錆色、darkの暗いグレー・オレンジは「静かな道具」の表情を作るブランド仮説である。普遍的に安心感や可読性を高める配色とは断定しない。RGBの定義は[NibbleTheme.swift](../../app/Shared/NibbleTheme.swift)を正とし、デザイン用の別ファイルへ複製しない。

R15・R16・R17に基づき、本文・補助文の文字コントラストは4.5:1以上を目標にする。識別に必要なアイコンや選択状態は3:1以上を目安とし、背景の塗りだけでなく文字、形、選択traitでも伝える。装飾用の淡い枠を一律3:1へ濃くするのではなく、その枠だけで操作・状態を識別していないかを判断する。

system色を使っていても独自背景との組み合わせは確認する。透明度、material、スクロール下の内容を含む実画面の確認と、単色RGBの計算を区別する。色の状態は[設計監査](audit.md)へ記録する。

## F03 文字と図記号

| 役割 | 現行の表現 | 理由と制約 |
| --- | --- | --- |
| ルートの現在地 | `title3`、bold、標準バー内 | 一覧の内容を圧迫せず短い現在地を示す。1行固定は狭幅・最大文字で監査する |
| 保存済み項目の識別 | `headline`、最大2行 | コピー対象を選ぶため最も先に読む。長い名前・同じ先頭の本文は2行で区別できるか確認する |
| 本文の要約 | `subheadline`、secondary、最大2行 | 項目選びに必要な文脈を足す。全文は編集画面で読む |
| 編集タイトル | `title2`、semibold、縦に伸長 | 入力欄を内容の見出しとして扱う。必須入力にはしない |
| 編集本文・説明 | `body` | 日本語・改行・Unicodeを無理に縮小せず読む |
| フィルター・操作 | `subheadline`、semibold | 短い選択肢を見分ける。横幅が不足したら到達方法を維持する |
| 補足 | `footnote` / `caption` | 主情報との階層を示す。失敗からの回復に必要な情報を小さな補足だけに置かない |
| ピン・コピー・作成等 | SF Symbols | 標準的な意味を使う。アイコンだけの場合も操作名と対象を読み上げる |

システムのtext styleを使い、文字サイズを固定してレイアウトを守らない。大きな文字では行の高さ・折返し・配置を変える。意味を伝えるアイコンは文字拡大に合わせて検討する。`SF Symbolsを使う`だけでは、固定ptで指定したアイコンの自動拡大を保証しない。（R14・R16）

ピン印は状態、コピー印は実行、区分見出しは読むためのラベルである。形が似ていても同じ操作領域として扱わない。装飾シンボルの読み上げ重複を避け、操作・状態が分かるアクセシビリティ要素にする。

## F04 余白と整列

余白は、同じ項目の内容を結び付け、異なる項目を区切り、操作同士の誤接触を避けるために置く。標準Listとtoolbarが管理する余白は、独自の固定値で全面的に上書きしない。（R03・R04・R07）

| 関係 | 現行値の位置付け | 採用理由・調整方法 |
| --- | --- | --- |
| 同じ情報内 | 下書きの文字間4、ピンと名前6、名前と要約7 pt | 異なる行より近く見せる。7 ptそのものの優位性は未実証。共通化時は8 ptとの比較対象 |
| 隣接する部品 | 行の内容とコピー8、フィルター間8 pt | 独立した操作を区別する。操作領域同士の重なりを確認する |
| 操作・通知のまとまり | 通知と作成12、本文ラベル周囲12、通知内16 pt | 読む領域と押す領域を分離し、内容が増えても詰め込まない |
| 画面の左右 | フィルター・作成16、通知内20、編集24 pt | 一覧は密度、通知は操作の分離、編集は長文の読みやすさを優先する。各面で同じ意味の要素を整列する |
| 編集の入力グループ間 | 24 pt＋標準Divider | タイトルと本文の意味を分ける。単一欄へ統合する場合は任意タイトルの契約を再検討する |
| 行とフィルターの上下 | 行4、フィルター4、通知6、作成下8 pt | 内容と操作領域の接触を防ぐ。標準行の余白に追加される値であり、行全高ではない |
| 空状態 | 上下30 pt | 少数の案内をまとまりとして読むための調整値。小画面・キーボードで操作が隠れたら減らす |
| 内容上端 | Listのscroll content margin 0 | 固定バー・フィルターの下に余分な空白を重ねない。端末のsafe areaは0にしない |

単位はiOSのpt。数値は[実装](../../app/Nibble/LibraryScreen.swift)・[行](../../app/Nibble/SnippetRowContent.swift)・[編集](../../app/Shared/SnippetEditor.swift)の監査時の値であり、黄金比などから導いた最適値ではない。

共通化する場合は「小・中・大」だけでなく、`rowContentGap`のように関係を表す名前を選ぶ。同じ数値でも変更理由が違う余白は、一つの定数へ結び付けない。すべての数値を巨大なtoken enumへ移すこと自体を改善としない。

## F05 操作領域と形

| 要素 | 見える部分 / 操作領域 | 理由・比較する条件 |
| --- | --- | --- |
| コピー | 16 ptシンボル、32 pt背景 / 44×44 pt | 多数の行で本文を圧迫せず、反復操作の領域を確保する |
| 新規作成 | 18 ptシンボル、56 pt円 / 同じ円 | 画面に一つの作成入口を識別する。56 ptは到達性と占有面積の仮説 |
| フィルター | 36 pt以上の面 / 44 pt以上の高さ | 同じ意味の選択肢は同じ尺度で提示する。選択をサイズ差で表さない |
| 復元・追加取得 | 標準部品 / 44 pt以上 | 小さい記号や短い文言でも操作領域を縮めない |
| 保存済み行の内容 | 最低60 pt＋外側の余白、内容により伸長 | 読み比べる密度と複数行の識別を両立する。固定高にはしない |
| フィルター・コピー背景 | 角丸10 pt | 小さな部品のまとまりを示す。意味や選択を角丸だけで表さない |
| 通知背景 | 角丸20 pt | 一時的なメッセージと操作を一つのまとまりにする。標準のalertの外観は変更しない |
| 標準タブ・検索・keyboard・sheet | システム管理 | OSの適応と操作の一貫性を維持する。別アプリのスクリーンショットのpxを固定寸法へ転記しない |

44 ptはnibbleが独自の反復操作へ採用する基準であり、Appleの全コントロールの絶対最小値という説明はしない（R07・R16）。見える円・角丸とhit regionを混同せず、隣接要素へのタップやスクロールが奪われないことを確認する。

## F06 固定領域と可変領域

- 画面タイトルとタブは現在地を保持する。一覧のフィルターは表示対象を保持する。
- 内容は縦にスクロールし、長文・大きな文字に応じて行と入力欄が伸びる。
- 新規作成と通知は`safeAreaInset`で領域を確保する。固定座標で最終行へ重ねない。
- 入力中は標準検索欄・キーボードを優先する。キーボード高やタブ高の推測値をレイアウトへ埋め込まない。
- 左右設定は新規作成とコピーの**物理的な側**。文章の読み順やシステム検索の位置とは別の設定である。

固定領域は便利な一方、狭い画面と大きな文字で本文の面積を減らす。固定する部品を増やす場合は、文字の見える量、末尾への到達、キーボード併用を比較する。スクロールしている間も全操作を常時表示することを目的にはしない。

## F07 状態とフィードバック

| 状態 | 表現すること | 避けること |
| --- | --- | --- |
| 初期読込 | 処理が進行している | 空データと断定する |
| 更新中 | 現在の内容と処理状態の関係 | 古い結果を新しい検索の成功として表示する |
| 完了 | 何が完了したか | 永続化・コピー前の成功表示 |
| 空 | なぜ空か、次にできること | ネットワーク不要のアプリで通信待ちと説明する |
| 失敗 | 何が失敗し、入力・保存済み内容はどうなり、何ができるか | エラーコードだけ、時間で消える唯一の回復手段 |
| 削除 | 対象、復元方法、完全削除との違い | 取り消し通知を失うと回復不能になる設計 |

通知の現行表示時間は通常2秒、削除取り消し付き6秒。これを「誰でも読める時間」とはしない。操作の読み上げ、連打、長い名前で評価し、期限後も削除一覧から復元できることを維持する。（R10〜R13）

## F08 動き

標準の遷移・検索・keyboardはOSへ任せる。アプリ独自の通知はopacityのみ、ease-out 160 ms、Reduce Motionでは0 msとする。動きは状態変化を示すために使い、本文やフィルターを無関係に移動させない。

160 msは製品の調整値であり、普遍的な知覚境界ではない。ScopedAnimationの範囲を使い、通知の出入りで作成ボタンが跳ねないことを確認する。アニメーションの滑らかさと、処理の応答時間は別に測る。（R11・R16）

## F09 文言とデータ

「スニペット」は保存済みの再利用対象、「下書き」は未完了の編集、「削除した項目」は復元できる保存済み項目を指す。見た目をそろえるためにこれらを同じ操作へまとめない。

本文・タイトルに独自の整形を加えず、コピーには原文を使う。要約・省略は表示だけに適用する。文言は対象＋結果を基本とし、エラーや確認では処理名だけでなく利用者が判断できる結果を示す。（R13、[データ契約](../decisions/0002-mvp-app.md#データの意味と永続化)）
