# UI部品台帳

nibbleのUI部品は、内容を選ぶ、操作する、結果を理解するという利用者の行動を単位に定義する。同じ責務を複数画面で使う場合はIDを共有する。SwiftのViewと設計上の部品は一対一である必要はない。

表のC番号は部品ID、F番号は[共通原則](foundations.md)、R番号は[根拠資料](../../research/06-interface-design-evidence.md)を示す。画面全体の配置は[画面構成](screens.md)に定める。確認条件は設計の評価基準であり、対象ソースの実装状況と未解決事項は[設計監査](audit.md)に記録する。

| C03 背景と区切り | 共通背景のListに文字を並べ、区切り線で項目を分ける | 連続した文字を読み比べやすくする。カードは独立性を示せるが境界と余白が増える | R04・R15、F01・F02。行・見出し周囲・余白を統一し、文字と境界を識別できる |
| C04 フィルター | すべて・ピン留め・下書きから一つの集合を選ぶ | タイトル直下に固定し、表示対象を見失わないようにする。横スクロールは文字幅を保てるが、端の項目と選択状態の発見性が必要 | R03・R06・R16。全選択肢へ到達でき、見た目と選択状態の読み上げが一致する |
| C05 区分見出し | 下書き、ピン留め済み、その他の順で内容を区分する | 未完了の再開、利用者が固定した内容、残りの項目を区別する。一律の更新順よりピンの意味を優先する | R03・R04。空区分を省き、多数の下書きが利用対象への到達を妨げないか評価する |
| C06 保存済み行 | 項目名と要約を示し、内容部分のタップで編集する。無題は本文から表示名を作る | 名前から要約の順で対象を識別する。行全体をコピーに使う案は編集への入口が別途必要 | R04・R14。同名・無題・長文を区別でき、全文へ到達できる |
| C07 下書き行 | 編集記号と再開のラベルで下書きを開く。コピーは置かない | 保存済みと未完了の内容を区別する。同じ行形式と操作にすると利用対象を取り違えやすい | R04・R13。複数の下書きを識別し、選んだ編集を再開できる |
| C08 追加取得 | List末尾の「さらに表示」で続きの保存済み項目を取得する | 続きの存在と読込の開始を明示する。無限スクロールより終端と取得の制御を優先する | R12、F07。100件単位で取得し、表示済みの対象とフォーカスを保つ |
| C09 新規作成 | 一覧・検索の下部に＋を置き、左右設定を反映する | 項目内の操作から独立させ、片手で届く範囲を確保する。全タブ共通の操作にすると設定にも現れる | R07・R18、F05・F06。最終行を隠さず、検索入力中は表示しない |
| C10 コピー | 対象行の横で本文をコピーする | 対象を開かずに利用できる。詳細画面への移動が必要な構成より操作を減らす | R07・R11、F05。行の編集と誤って同時実行せず、対象名と操作を読み上げる |
| C11 整理操作 | 行の長押し・スワイプからピン留めと削除を選ぶ。スワイプし切るだけでは更新しない | 対象に従属する操作をまとめる。常設ボタンは発見しやすい一方、本文の幅を使う | R08・R16。ジェスチャーの代替、ピン状態の識別、誤削除からの回復を評価する |

## 検索と状態表示

| ID・部品 | 責務と構成 | 配置理由と代替案の評価 | 根拠・確認条件 |
| --- | --- | --- | --- |
| C12 標準検索欄 | 検索タブから入力し、語句の消去・確定・検索終了を行う | 覚えている言葉をすぐ入力できる。上部常設の検索は内容との関係を示しやすいが、到達性と面積に負担がある | R02・R19。タイトル・本文が対象と分かり、日本語変換と検索確定を区別できる |
| C13 検索前案内 | 語句が空白のみのとき、検索対象と入力方法を示す | 未検索と0件を区別する。履歴や候補の表示にはデータ保持と探索の設計が必要 | R02・R13。入力開始を妨げず、失敗や必要な進行表示を隠さない |
| C14 検索0件 | 語句に一致する項目がないことと修正方法を伝える | 保存データ全体が空である状態から区別する。自動の作成誘導は重複作成を促す可能性がある | R13。検索語を保持し、修正・消去・終了で回復できる |
| C15 空状態 | 一覧の集合ごとに空の意味と次の操作を示す | 初回作成、対象変更、下書き再開、復元は異なる文脈を持つ | R13、F07。読込中と失敗を空状態と取り違えず、作成・対象変更・閉じるへ進める |
| C16 読込表示 | List内で初期・更新・追加取得の進行を伝える | 内容の文脈を保つ。全面の進行表示は更新ごとに内容を隠す負担がある | R12。実際の処理と表示が一致し、測定できない進捗割合を示さない |
| C17 失敗と再試行 | 失敗の理由と回復操作を内容の面に示す | 探索や入力を保持したまま回復する。短時間通知だけでは必要な行動を読み逃しやすい | R10・R13。失敗した対象が分かり、ラベルと再実行する処理が一致する |
| C18 完了通知 | 下部の通知、読み上げ、コピーの触覚で処理完了を伝える | 一覧を維持して入力先への復帰を支える。毎回の確認ダイアログは操作を中断する | R11、F07・F08。成功後に通知し、連続操作で古い状態を残さない |
| C19 削除取り消し | 削除通知と「元に戻す」を一つのまとまりに置く | 直前の誤操作から短い手順で回復する。期限後の復元は削除一覧が担当する | R10・R11。取り消し対象を予測でき、連続削除と通知消去後も復元できる |

| ID・部品 | 責務と構成 | 配置理由と代替案の評価 | 根拠・確認条件 |

| C21 タイトル入力 | 本文の前に任意の識別名を入力する | 内容の名前を先に読み取れる。必須にすると短い定型文にも命名の負担が加わる | R13・R14。空でも本文を保存でき、長い名前は折り返す |
| C22 本文入力 | 縦に伸びる標準入力欄とページスクロールで原文を編集する | 固定高の内側と外側でスクロールが競合する構成を避ける | R14、F09。変換、選択、末尾編集、空白・改行・Unicodeの保持を確認する |
| C23 ペースト | 本文ラベル横のPasteButtonでテキストを末尾へ追記する | 本文へ加える操作をその対象の近くに置き、明示的な入力を入口にする | R13、F09。選択位置への挿入と追記を取り違えないか評価する |
| C24 保存 | 上部バーの末尾側で保存済み項目への反映を確定する | 標準の完了位置を使う。自動保持は下書き、保存は利用対象への確定という意味を保つ | R05・R09。本文が空白のみなら無効。成功時だけ閉じ、重複保存しない |
| C25 閉じる | 上部バーの先頭側で下書きを保持して戻る | 中断と確定保存を分ける。入力を捨てる意味に受け取られないよう補足する | R09・R13。最新入力の保持成功を待ち、失敗時は画面に残す |
| C26 その他メニュー | 下部バーに本文共有と下書き破棄をまとめる | 低頻度の操作を可視の入口へ収め、入力面積を確保する | R05・R08。必要な操作を発見でき、保存済み項目の削除と下書き破棄を区別できる |
| C27 本文共有 | ShareLinkで編集中の本文をOSの共有先選択へ渡す | 標準の共有先と操作を使い、独自の共有先管理を持たない | R08、F09。本文が空なら無効。共有から入力を保持して戻れる |
| C28 下書き破棄 | 確認ダイアログで編集内容の除去を確定する | 保存済みを残すことを明示し、中断との意味を分ける | R10・R13。取消で入力を保ち、確定時だけ下書きを除く |
| C29 終了処理 | 入力を固定し、進行を示して保存・保持・破棄を一度だけ完了させる | 処理中の入力変更による確定対象の曖昧さを防ぐ | R12、F07。状態の説明が実行中の操作に合い、失敗時に操作可能へ戻る |
| C30 編集の失敗 | 入力の近くに理由を残し、対応可能な競合には別項目として保存する入口を示す | 入力と回復の関係を保つ。自動上書きは別の編集を失わせる可能性がある | R10・R13。入力を保ち、利用者が選んだ場合だけ別項目を作る |
| C31 保持の補足 | 入力欄の後で下書き保持と原文の扱いを説明する | 必要なときに参照でき、入力開始を妨げない位置に置く | R13、F09。主要操作名との意味が一致し、保持失敗を説明とともに判断できる |
| C32 キーボード操作 | 標準入力と専用のキーボード終了操作を使う | 日本語変換・選択・支援技術を尊重し、画面外のタップ以外の終了手段を持つ | R16・R19。本文の改行を保存に割り当てず、終了後も入力を保つ |

## 共通表現の対応

行内のピン、本文の省略、区切り線、背景、余白はC03・C06・C11とF01〜F05が定義する。C15は集合別の空状態、C20は新規・保存済みの編集・再開・共有の入口を共有する。

アプリは要素の意味、内容、配置、操作を管理し、標準部品の内部寸法と光学効果はOSへ委ねる。責務が増える場合は該当する台帳項目を更新し、独立した意味を持つ部品にはIDを追加する。
