# UI部品台帳

各部品は、利用者に伝える意味、配置理由、代替案、評価条件を持つ。この台帳は[共通原則](foundations.md)と[画面構成](screens.md)を具体化する。R番号の根拠は[一次資料](../../research/06-interface-design-evidence.md)、未解決事項は[設計監査](audit.md)を参照する。

以下は現行構成を評価する基準であり、理由を記載しただけで妥当性を実証したものではない。特に「仮説」「例外」は比較が必要である。標準部品の内部寸法・光学効果はOSが管理し、アプリが意味と配置を決める範囲に限って記録する。

## 台帳の粒度

同じ部品が複数画面に現れる場合はIDを再利用し、異なる状態・意味は画面側へ記す。たとえばC15には4種類の空状態、C20には新規・既存・再開・共有の入口がある。

行内のピン印、本文の省略、Divider、背景、paddingの意味はC06・C11とF01〜F05が所有する。OSが描くガラスの反射や影の各ピクセルまで別の理由を捏造しない。新しくアプリが制御する要素を追加したら、既存IDの責務に含めるか、新しいIDと理由を作る。
