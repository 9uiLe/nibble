# UI部品台帳

nibbleのUI部品は、内容を選ぶ、操作する、結果を理解するという利用者の行動を単位に定義する。同じ責務を複数画面で使う場合はIDを共有する。SwiftのViewと設計上の部品は一対一である必要はない。

表のC番号は部品ID、F番号は[共通原則](foundations.md)、R番号は[根拠資料](../../research/06-interface-design-evidence.md)を示す。画面全体の配置は[画面構成](screens.md)に定める。確認条件は設計の評価基準であり、対象ソースの実装状況と未解決事項は[設計監査](audit.md)に記録する。

| C09 新規作成 | 内容がある一覧・検索の下部に＋を置き、左右設定を反映する。作成可能な空一覧では文言付きの作成入口に集約する | 項目内の操作から独立させ、片手で届く範囲を確保する。全タブ共通の操作にすると設定にも現れる | R07・R18、F05・F06。最終行を隠さず、検索入力中は表示しない |
| C10 コピー | 対象行の横で本文をコピーする | 対象を開かずに利用できる。詳細画面への移動が必要な構成より操作を減らす | R07・R11、F05。行の編集と誤って同時実行せず、対象名と操作を読み上げる |

## 共通表現の対応

行内のピン、本文の省略、区切り線、背景、余白はC03・C06・C11とF01〜F05が定義する。C15は集合別の空状態、C20は新規・保存済みの編集・再開・共有の入口を共有する。

アプリは要素の意味、内容、配置、操作を管理し、標準部品の内部寸法と光学効果はOSへ委ねる。責務が増える場合は該当する台帳項目を更新し、独立した意味を持つ部品にはIDを追加する。

| C46 キーボードの項目 | 一列の入力キーにタイトル・要約を各1行、小さいピンと青い「入力」の動作名を表示する。44pt幅のコピーキーを6pt離して並べ、48pt高・8pt角丸の面で入力対象を示す | 内容だけでは押した結果が伝わらないため、動作名を常設する。内容と「入力」を一つのButtonとし、広いタップ領域を保つ。始点を揃え、ピンの有無で文字を動かさない。二列タイルは長い内容の識別を妨げるため採らない | S09。主文字と補助文字、ライト／ダークのキー面・押下状態、長文・無題・原文・権限・連打を確認 |
| C47 キーボードの下部操作 | 結果文と待機時の製品名を同じ領域に表示。複数ページ時だけ前後移動と番号、末尾に更新・終了を置く。OSが要求する場合だけ地球儀を置く | 一覧の面積を確保し、短い結果で一覧を上下させない。補助操作は固定位置から実行できる。50件のページで保持量を制限し、結果は次の操作まで残す | S09。長い結果の折り返し、ページ境界、地球儀の長押し、狭幅・横向き、権限変更と画面離脱を確認 |
| C48 キーボード利用案内 | 設定内の入口と、追加・権限・利用制約の文章 | 設定作業と入力作業を分け、長い説明を小さなキーボード面へ詰め込まない | S10。全段落の可読性、標準戻る、挿入にはフルアクセス不要であることの理解 |

C45〜C47の色・記号・寸法・状態表示は[キーボードの視覚的な契約](../decisions/0005-snippet-keyboard.md#レイアウトと操作の意味)に集約する。各要素が伝える意味、代替案、評価条件を実装と照合し、色を装飾だけの理由で追加しない。
