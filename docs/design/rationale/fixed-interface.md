# 表示設定とOSの境界

## 判断

本体と共有の本文入力にはOS標準のUITextView、画面には標準文字スタイル・List・Form・NavigationStackを使う。Dynamic Type、ライト／ダーク、safe areaを尊重する。文字サイズ・太字・コントラストを製品側で一律に固定しない。

## 理由と負担

標準入力は日本語の新規入力・訂正・確定をOSへ任せられ、独自のかな漢字変換と編集手順を保守する負担を避ける。標準部品の採用だけで操作性を保証するものではない。拡大文字や狭幅で本文と確認操作の領域が競合するため、折返し・スクロール・safe areaを実画面で確認する。

Markdownを描画する切替は設けず、確認する全文と出力を文字列として揃える。読みやすさのために原文を自動整形しない。全文確認にはTextKit 2の読取専用UITextViewを高さの限られた領域へ配置する。単一のSwiftUI Textを全文の高さへ展開する案は、約200KBの実測で巨大な描画層を作り表示の安定に失敗したため採用しない。枠内スクロールは操作の負担を増やすため、案内と末尾への到達を実画面で確認する。

## OSが所有する範囲

ソフトウェアキーボード、変換候補、標準編集メニュー、ホストが与えるKeyboard表示領域、secure入力での切替はOSやホストが所有する。本体の標準入力での成功をKeyboard内部の入力能力へ一般化しない。

## 検証

日本語変換・訂正・確定、選択とペースト、Dynamic Type、狭幅、長文末尾、ライト／ダーク、キーボード表示を評価する。対象は[F03〜F10](../foundations.md)、問いは[G04・G06](../audit.md)に置く。
