# 対象の識別、操作、回復

保存済み本文の利用、項目の整理、下書きの再開、編集の終了を扱う。画面の構成はS01〜S07、部品の契約は[C台帳](../components.md)に定める。

## 一覧と主要操作

保存済み項目は、名前・本文要約・ピン状態・必要な使用情報で識別する。一覧全体を使用回数順に並べ、よくコピーする内容へ到達しやすくする。ピン留めは独立した属性であり、フィルターで集合を選ぶ。

内容をタップすると編集し、右側のコピーで本文を利用する。整理操作は可視の「その他」へまとめ、スワイプと長押しも同じ処理へ接続する。可視入口が操作の発見を支え、ジェスチャーが反復操作を短くする。コピーと編集の操作領域を分け、対象と操作を取り違えないようにする。

作成は作業画面の下部へ文言付きで固定し、検索入力中は隠す。C09に従い、作成後も呼出元の現在地を保つ。

## ナビゲーションと見出し

一覧と検索は同じ保存済み本文を探して使うための方法なので、一つの作業画面へ統合する。検索語がないときは選択中の集合、検索語があるときは保存済み全体の検索結果を表示する。検索語を消すと元の集合と取得上限へ戻る。設定は日常の利用より頻度の低い管理・説明として階層へ移す。

検索欄を一覧の上部へ常設すると項目表示に使える高さは減るが、検索のための画面移動が不要になる。集合選択と検索語を一つの状態所有者で管理し、入力と取得結果を対応付ける。操作速度や理解度の数値効果は利用者評価で確かめる。

選択・検索語・取得上限はApplicationのLibraryReadStateが所有し、要求を導出する。検索結果は各集合の取得済み内容を置換しない。アプリ内の変更では同じDB transactionから集合と必要な検索結果を更新する。URLから一覧を開く操作と空状態の「すべてを見る」は、同じ`LibraryModel.showAll()`を呼ぶ。原文、ID、下書きの意味は[製品仕様](../../product-specification.md)に従う。

見出しは製品名と設定入口だけにし、件数は集合選択へ集約する。項目は単一列に並べ、行内の編集・コピー・整理を分ける。空集合には重複した作成入口を置かず、下部の作成操作を使う。文字の役割は[F03](../foundations.md#f03-文字と図記号)に従う。

## 下書きと編集

通常一覧の下書きは最新1件を再開帯に置く。残りは件数付きの入口から専用一覧で選ぶ。これにより入力を再開する場所を保ちながら、保存済みの利用対象へ到達できる。フィルターの件数は同じDB snapshotの集合総数であり、表示ページの件数ではない。

本文は原文を編集する「入力」と、記号を隠して読む「プレビュー」を切り替える。入力では構文と文字列を直接修正でき、プレビューでは見出し・強調・段落のまとまりを確認できる。保存データを一つに保つため、表示切替は本文・下書きの番号を更新しない。字形の定義と解析結果を共有し、両表示で意味を揃える。

保存は利用対象への確定、閉じるは下書きの保持、破棄は下書きの除去を意味する。終了は最新入力の永続化を待ち、失敗時には入力と回復手段を画面に残す。競合時の別項目保存は利用者の明示操作で行い、別の編集内容を上書きしない。

作成・編集では上部に固定したButtonの「閉じる」「保存」を文字で示す。外観と操作領域は標準NavigationBarに任せ、保存にはconfirmの役割を付ける。タイトルを中央、閉じるを先頭、保存を末尾に置く。下部の「その他」は44pt以上のアイコンにまとめ、読み上げ名を残す。終了の意味は上部の操作直下に短く示し、原文保持、ペースト条件、長さの上限、下書きが残らない例外は補足シートへ置く。入口は「入力と保存について」と末尾の右向き矢印で示し、説明の対象と押せる入口であることを伝える。キーボード表示中にも補足へ到達でき、入力を保って戻れることを条件とする。これは入力面積と説明への到達を両立するための製品判断であり、説明の理解・発見性はG07・G09・G11で評価する。

共有取込は共通エディターの保存契約を保ち、見出しと案内で共有された内容の確認だと伝える。下書きの左に装飾アイコンを置かず、専用一覧はタイトル・本文・日時と再開を示す矢印を用い、保存済みのコピー操作と区別する。配色と文字の役割はF02・F03で統一する。

## 完了と失敗

コピーの成功は「コピーしました」の短い表示と振動で伝える。削除は対象名と「元に戻す」を持つ通知とし、期限後には削除一覧から復元できる。成功の通知は一覧・検索欄・作成ボタン・検索入力を動かさない。

回復操作が必要な失敗は読める状態で残し、完全削除は対象と回復不能であることを確認してから実行する。各結果の寿命は[通知設計](result-notices.md)、色と表示設定は[共通原則](../foundations.md)に従う。

## 評価条件

共通原則、画面構成、部品台帳に照合する。操作の発見性、似た項目の識別、片手での到達、保持と確定の理解、回復手順の理解は[G課題](../audit.md)で評価する。実装・自動操作の成立と利用者評価は分けて記録する。
