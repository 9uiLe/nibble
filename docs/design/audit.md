# UIの評価課題

採用仕様は[S画面](screens.md)・[C部品](components.md)にあり、本書はその評価で解決すべき問いを管理する。G番号は問いのID、Aは操作と回復、Bは利用条件と標準操作、Cは密度・表現の比較を表す。利用頻度の実測順位ではない。

## 評価対象

本体・共有拡張・Keyboardの現行設計を対象とする。実装の存在、Simulatorでの成立、利用者にとっての理解・発見性は別の評価である。実施済みと未確認は[検証範囲](../mvp-validation.md)および対象ソース付きrunで照合する。

### G01 A — 整理操作の可視入口

C11は可視メニューとジェスチャーを持つ。初見でピン/削除へ到達できるか、ジェスチャーを知らない参加者で評価する。

### G02 A — 下書きの識別情報

C07はタイトル・要約・日時で再開対象を示す。同名/無題の複数下書きで取り違えと再開までの操作を評価する。

### G03 B — 文字拡大と操作対象

表示はF10で固定する。OS文字設定変更時の固定と44pt操作領域を確認し、固定方針の可読性への影響は利用者評価で扱う。

### G04 B — フィルターの選択表示

C04の文字・選択項目の濃淡反転・件数・読み上げ状態を照合する。色の判別条件が異なる利用者の評価は未実施。

### G05 A — 失敗表示と再試行

C17は原因と回復操作を保持する。再読み込み、コピー、「回数と日時を記録し直す」を取り違えず回復できるかを評価する。コピー済みの本文をもう一度コピーする必要があると誤解しないか確認する。

### G06 B — 実画面のコントラスト

単色計算を実画面の合格にしない。primary/secondary、選択、エラー、細線、ガラス、通知素材をライト/ダークで評価する。

### G07 B — 保存可能な入力の説明

C22・C31の空本文/サイズ制約と原文説明を照合する。文字数とbytesを誤解せず、入力を修正して保存できるかを評価する。

### G08 A — 削除・復元の対象表示

C19・C37・C38は対象名と操作結果を示す。同名データ、連続削除、期限後の復旧、完全削除の取消で対象理解を評価する。

### G09 B — 編集シートの終了

C25は保持を待って閉じる。利用者が中断と確定保存を区別し、保存失敗でも入力を回復できるかを評価する。

### G10 C — 表示密度

C05の最新1件の再開帯・残りへの入口と要約表示について、探索・再開・管理の到達を比較する。密度の好みだけで削減を判断しない。

### G11 C — 操作と文言

利用者が文言から操作結果と次の行動を予測できるかを評価する。対象は保存と下書き、閉じると破棄、削除と完全削除、コピーと記録の再試行、キーボードの挿入とフルアクセスである。[文言設計](copy.md)の語彙を、画面で起きる結果に照合する。

初見の日本語話者に手順を教えず、操作後の結果と次の行動を本人の言葉で説明してもらう。提示文言、回答、誤解、文言を修正した場合の再確認を記録する。VoiceOverでは、ラベルの意味に加えて音声・フォーカス順・操作の到達を確認する。利用者による理解確認とVoiceOverの音声・操作評価は未完了である。実画面の観測と評価条件は[文言の検証記録](../copy-validation.md)を参照する。

### G12 B — 共有取込の待機

共有provider取得中の可視進行表示と取消UIは未採用。遅いproviderと離脱で利用者が状態/終了方法を理解できるかを確認し、必要なUIを判断する。

### G13 B — 検索入力中の通知配置

通知は上部の別windowに置く。検索語・focus・keyboard・key windowを保持する。通知中の読み上げ順と音声操作の評価は未実施。

### G14 B — 一時通知によるタブバーの再配置

通知の前・中・後でタブ、作成、フィルター、同じ行の座標を比較する。使用回数による並べ替えと分離する。末尾その他の直接操作、複数scene、実機性能は未確認。

### G15 C — キーボード説明の順序と原文保持

C49の図と文章から、切替後の行タップで本文が入力され、保存済みの原文は残ると理解できるかを評価する。コピーやドラッグ、フルアクセスが挿入に必須だと受け取られないか、途中から見た場合も順序を追えるかを初見の利用者で確認する。図の読みやすさ、読書への干渉、VoiceOverの音声・フォーカス順・戻る操作は、構造検査や画像とは別に評価する。

### G16 C — 説明画面の再生とスクロールの性能

C44・C49の描画性能は受入未完了である。画面更新の遅れで生じる引っかかり（hitch）と初回・復帰時の表示完了時間を測り、予算を定めて判定する。SwiftUI body・UIViewRepresentableの更新時間、CPU・GPU時間も評価する。操作条件はドラッグ・減速・10%可視境界・タブ・画面遷移・全面シート・inactive/backgroundとする。

停止中の周期進行、再生位置の保持、読込と解放の契約検証に、実際の描画性能の測定を組み合わせて評価する。runtimeのフレーム評価であるadvanceの時刻を、画面への表示完了やhitchへ換算しない。対象ソース、計測の成立、補助指標と予算、未評価条件は[再生の検証記録](../rive-playback-validation.md)に置く。

## 利用者評価の手順

手順を教える前に、コピーして作業へ戻る、検索、ピン、下書き再開、誤削除の復旧、保存失敗からの回復という目的を渡す。対象者の利用経験・端末・データを固定し、到達、誤操作、補助説明、本人の言葉を観測する。初見と学習後を分け、少数の観測を全利用者へ一般化しない。採用判断は[ひな形](../../tools/ui-design/templates/decision.md)、時間計測は[性能手順](../performance-verification.md)に従う。
