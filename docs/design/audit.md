## 課題の分類

| 優先度 | 対象 | 理由 |
| --- | --- | --- |
| A | 操作の発見、対象の識別、失敗からの回復 | 目的の操作を完了できるかに関わる |
| B | 表示・入力への適応、標準操作の期待 | 利用条件が変わっても同じ機能を使えるかに関わる |
| C | 密度と表現の比較 | 基本の操作を保ちながら負担を減らす |

優先度は設計上の影響から付けており、利用頻度の実測順位ではない。以下のG01〜G12は表に示す監査ソースでの不足と候補を記録する。G01〜G11の採否は[対象の識別・操作・回復](decisions/0001-library-actions.md)に定義する。G09は明示終了の継続と説明を採用し、G12の共有元データ取得中の表示・取消は未採用の課題として残す。利用者比較・VoiceOver音声による評価は未実施である。

### G01 A — 整理操作の可視入口

**実装**：C11のピン・削除は長押しとスワイプにある。通常表示から押せる同じ操作の入口はない。編集画面の「その他」は本文共有と下書き破棄を持つ。

**課題**：ジェスチャーの知識に依存する。R08・R16はメインUIからの代替操作を勧める。

**候補**：行の「その他」メニュー、または項目を開いた画面の可視操作。比較では本文の幅、コピーの誤操作、未保存入力の扱いを評価する。

**確認条件**：長押し・スワイプを使わずピン・削除へ到達できる。内容の識別とコピー、左右設定を保つ。

### G02 A — 下書きの識別情報

**実装**：C07は全件に「下書きを再開」、無題に「編集中のスニペット」を表示する。`DraftSummary`が持つ表示情報はタイトルのみ。

**課題**：本文の異なる無題の下書きを行の表示から区別できない。

**候補**：タイトル、または無題時の本文先頭を主表示にし、「下書き」を補足する。同じ先頭が続く場合は更新日時の追加も比較する。

**確認条件**：無題3件、同名、長文から目的の編集を再開できる。同じUUIDと保存順序を維持し、行には本文全体を取得しない。

### G03 B — 文字拡大と操作対象

**実装**：コピー16 pt、作成18 ptは固定サイズ。ルートタイトルは1行・`fixedSize`、行は最大2行。復元には対象名付きの独自読み上げラベルがない。

**課題**：文字拡大と対象識別の評価が必要。実画面での欠けや操作不能は、この監査では観測していない。

**候補**：文字とともに拡大する記号、狭幅での行の組み替え、対象名付きの復元ラベル、標準タイトルとの比較。

**確認条件**：標準文字・最大アクセシビリティ文字、小さい対応iPhone幅、長い名前で内容と操作を識別できる。VoiceOverで復元対象が分かる。

### G04 B — フィルターの選択表示

**実装**：C04は文字・塗り・枠の色と選択状態のアクセシビリティ情報を使う。選択専用の記号や文言はない。

**課題**：色を区別しにくい条件で、視覚的な選択状態を判断できるか未評価。

**候補**：選択項目へのチェック表示、または標準のsegmented Picker。記号幅を確保して切替時の位置変化を抑える案を比較する。

**確認条件**：選択状態が視覚と読み上げで一致し、ラベルが跳ねず、大きな文字でも全項目へ到達できる。

### G05 A — 失敗表示と再試行

**実装**：空白検索ではC13がListに代わるため、List内のエラーと読込状態が表示されない。「再試行」は再取得を実行し、失敗したコピー・ピン・削除そのものは繰り返さない。

**課題**：失敗が見えない状態と、ラベルから予測する再実行対象が一致しない可能性がある。

**候補**：失敗・回復、読込、検索前案内、結果の表示優先度を定義する。失敗した操作と対象を保持し、再取得と利用者による再操作を分ける。

**確認条件**：空検索からの作成失敗、DB読込失敗、コピー失敗で理由と行動が分かる。検索語・下書き・UUIDを保ち、破壊的操作を自動再実行しない。

### G06 B — 実画面のコントラスト

**実装**：独自色はライト・ダークで分岐し、コントラスト強調の別分岐は持たない。システムの補助文字や半透明素材を含む全組合せの測定記録はない。

**課題**：単色計算から、背景合成後の読みやすさは判断できない。

**候補**：文字、ピン、コピー、選択、通知、エラーを実画面で測定し、必要な色・太さ・素材を調整する。

**確認条件**：ライト・ダーク、コントラスト強調、透明度低減で本文4.5:1、意味を担うアイコン・状態3:1を目標に評価する。

### G07 B — 保存可能な入力の説明

**実装**：本文が空白だけの場合は保存が無効になる。本文ラベルは「本文」、補足は下書き保持と原文の扱いを説明する。

**課題**：保存できない理由を入力画面から理解できるか未評価。

**候補**：本文が必要なことを短く示す。未入力と保存処理の失敗を分け、入力開始から強いエラーを表示しない構成を比較する。

**確認条件**：タイトルのみ、本文なし、空白・改行のみ、本文ありの違いが分かる。原文保持の契約を維持する。

### G08 A — 削除・復元の対象表示

**実装**：通知と確認は「削除しました」「完全に削除しますか？」で対象名を含まない。取り消し通知は直前の1件を扱い、新しい通知で置き換わる。

**課題**：連続操作で、戻す対象と完全削除する対象を予測できるか評価が必要。

**候補**：対象名を含む通知と確認。長い名前でも操作が隠れない構成を比較する。

**確認条件**：2件を連続削除した後、取り消し対象が分かる。通知期限後も両方を削除一覧から復元できる。完全削除は対象を確認して取り消せる。

### G09 B — 編集シートの終了

**実装**：C20はスワイプ終了を無効にし、最新入力の永続化成功後にだけ明示操作で閉じる。

**課題**：入力保持の契約と、R09の標準的なスワイプ終了の期待を両立する方式が必要。

**候補**：終了意思を受け取って保持を待つ方式と、明示終了を維持する方式。いずれも永続化前に画面を閉じない。

**確認条件**：日本語変換中、保持中、保存失敗、共有拡張、繰り返し終了で入力を失わない。終了処理のテストと実操作の両方で確認する。

### G10 C — 表示密度

**実装**：下書きは件数制限なく先頭に並ぶ。初回・下書き0件では文言付き作成と下部＋がある。設定は独立したタブを持つ。

**課題**：コピー対象への到達、再開の発見、管理の入口と占有面積の関係は利用者比較が必要。

**候補**：下書きの先頭要約と全件への入口、空状態の作成入口の一本化、設定タブの維持を、それぞれ独立した条件で比較する。

**確認条件**：下書き0・3・20件と保存済み20件で到達、取り違え、必要な補助説明を観測する。件数は試験条件として扱う。

### G11 C — 操作と文言

**実装**：ペーストは本文末尾へ追記するがラベルは「本文にペースト」。終了処理の読み上げは保持・破棄も「保存中」とする。

**課題**：挿入位置と、保存済みへ確定する操作の意味が曖昧になる可能性がある。

**候補**：追記位置と実行中の処理が分かる表現。カーソル挿入へ変更する場合は、入力動作として別に設計する。

**確認条件**：本文の途中を選択していても結果を予測できる。保持・破棄と確定保存を区別し、視覚と読み上げの説明が一致する。

### G12 B — 共有取込の待機

**実装**：共有元のデータ取得と下書き作成を待つ間、独自の進行表示や終了操作を配置していない。

**課題**：待機中の状態と終了方法を理解できるか評価が必要。

**候補**：取込中の表示と明示終了。取消時のデータ取得コールバック、作成済み下書き、共有元への通知を合わせて設計する。

**確認条件**：遅延、非対応形式、取得失敗、取消、共有元終了で二重終了や意図しない保存を起こさず、状態が分かる。

## 単色のコントラスト計算

2026-09-17、評価対象の`NibbleTheme`のRGBと`LibraryScreen`の不透明度を使い、NixのPythonでsRGBの相対輝度を計算した。

| 前景と背景 | ライト | ダーク |
| --- | --- | --- |
| accent / canvas | 6.0376:1 | 9.2667:1 |
| accent / コピー背景（accent 7%をcanvasへ合成） | 5.4432:1 | 8.2526:1 |
| accent / 選択背景（accent 14%をcanvasへ合成） | 4.8891:1 | 7.1391:1 |

sRGB成分は`c <= 0.04045`なら`c / 12.92`、それ以外は`((c + 0.055) / 1.055)^2.4`へ変換した。輝度は`0.2126 R + 0.7152 G + 0.0722 B`、比は`(明るい輝度 + 0.05) / (暗い輝度 + 0.05)`。合成色は各sRGB成分を`前景 × alpha + 背景 × (1 - alpha)`で求めた。表示値のみ丸めている。

6条件とも4.5:1を超える。これは単色の理想的な合成に対する計算である。実際の色空間、システムの補助文字、エラー色、細線、ガラス、通知素材、視覚設定の変更は含めない。入力と結果はGit管理対象外の`artifacts/design-research/solid-color-contrast.json`に保存した。

## 利用者評価の手順

参加者には操作手順ではなく達成したい目的を伝える。アプリの使用経験、端末、表示設定、データを記録し、初見の発見性と学習後の効率を区別する。

| 課題 | 観測すること |
| --- | --- |
| 見えている定型文をコピーし、元の作業へ戻る | 対象の取り違え、不要な画面移動、復帰までの操作 |
| 本文だけ覚えている項目を探す | 検索開始、範囲の理解、0件からの回復 |
| 項目をピン留めする | 初回の到達、必要な補助説明 |
| 無題の下書きを再開する | 識別、開き直し、入力保持 |
| 削除した項目を戻す | 通知中と期限後の復元先の発見 |
| 保存失敗から回復する | 原因の理解、次の操作、二重操作、内容保持 |

開始・終了状態、誤操作、戻り、補助説明、参加者の言葉を残す。時間比較は条件と試行順をそろえ、学習の影響を記録する。少数の評価結果はその参加者と利用場面に限定して解釈する。応答・描画の計測は[性能評価](../../CONTRIBUTING.md#性能の評価)に従う。

## G13 A — 検索入力中の操作完了通知

**対象**：S02検索、C18完了通知、C19削除取り消し。ソースは`ecacb21a8eaca320ef3927d92593f09ae44f9703`、確認環境は2026-09-19のiOS 26.5 Simulator。

**必要条件**：検索語とフォーカスを保持して結果を読め、取り消しを操作できる。表示時間は実際に通知を表示した時点から計測する。
