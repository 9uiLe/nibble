# 使用回数順の一覧と整理候補

本体は頻繁にコピーする内容へ到達しやすくするため、保存済み項目を使用回数順に並べる。ピン留めは利用回数と独立した利用者の整理属性とする。

## 使用の定義と適用範囲

本体の一覧・検索から本文をOSへ書き込み、呼出しが戻った時点を1回の使用とする。閲覧、編集、本文共有、Keyboardの挿入/コピーは加算しない。長い間開いていないことと、使っていないことを混同しない。

## 一覧と検索の並び順

すべて・ピン留め・検索は使用回数降順、更新日時降順、UUID昇順で安定させる。下書きは別区分、削除一覧は更新順、Keyboardはピン優先であり、それぞれの目的に合わせる。コピー後は同じ検索/フィルター/取得範囲を再取得する。

## 整理候補の表示

最終使用から720時間以上の項目へ未使用の補足と最終使用日を示し、一度も使っていない項目にはこの補足を表示しない。自動削除やピン解除は行わず、利用者が対象を確認して整理する。低頻度でも重要な定型文を失わせないためである。正確な基準値の処理は[使用モデル](../../../app/Shared/Snippet.swift)と保存層に従う。

## 保存するデータと整合性

使用回数・最終使用日時と操作UUIDを同じtransactionで記録する。操作UUIDは二重加算を防ぐ単位であり、項目UUIDや表示通知IDとは異なる。schema移行は既存UUID・原文・ピン・下書き・削除状態を維持する。

## コピーと記録失敗からの回復

clipboardとSQLiteは別の確定処理である。コピー後の使用記録失敗をコピー失敗として示さず、同じ操作IDの記録だけを再試行する。本文を再コピーしたり新しい操作IDで加算しない。未確定の再試行待ちはプロセス内だけに保持し、二つの確定の間のプロセス終了による記録喪失は防げない。

使用記録はコピーへDB書込の負担を追加する。copy経路の性能測定には記録までを含め、本文取得やclipboard単独の時間と区別する。

## 採用理由と評価条件

ピンだけを先頭へ分割する方式より、集合全体の利用頻度を反映する。使用回数は今後も必要な価値を断定する指標ではないため、未使用表示は手動整理の補助に限る。

同じ操作IDの再試行、記録失敗、並び替え、検索条件保持、再起動後の確定データ、ピン項目の整理候補を確認する。表示はS01/S02・C05/C06、受入手順は[製品検証](../../mvp.md)を参照する。
