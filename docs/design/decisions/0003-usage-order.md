# 使用回数順の一覧と整理候補

nibbleは、文章をスニペットとして保存し、必要なときにコピーして再利用するiOSアプリである。本体の一覧と検索は使用回数の多い項目から並べ、長期間使っていない項目には整理を判断するための補足を表示する。利用者は同じ一覧から、コピー、編集、ピン留め、削除、復元を行える。

対象は[画面構成](../screens.md)のS01一覧・S02検索と、[部品台帳](../components.md)のC05区分・C06保存済み行・C10コピー・C17失敗と再試行。関連タスクは[Issue #25](https://github.com/9uiLe/nibble/issues/25)、実行結果は[検証記録](../../snippet-usage-validation.md)に定義する。

## 使用の定義と適用範囲

使用1回とは、本体の一覧または検索から保存済み本文をコピーし、OSのクリップボード書込呼び出しが正常に戻ることである。貼り付け先での利用は集計しない。同じスニペットの使用回数と最終使用日時を、保存済み項目のUUIDに対応付けて保持する。一覧と検索からのコピーは同じ項目へ合算する。

| 操作 | 使用記録 |
| --- | --- |
| 一覧・検索から保存済み本文をコピー | 成功した操作ごとに1回加算し、完了日時を記録する |
| コピー前の読込失敗・キャンセル | 記録しない |
| 閲覧、編集、保存、共有取り込み、ピン操作 | 記録しない |
| 編集画面の未保存本文をコピー | 記録しない |
| キーボード拡張のコピー・挿入 | 記録しない |

## 一覧と検索の並び順

「すべて」「ピン留め」と検索結果は、使用回数の降順、更新日時の降順、UUIDの昇順で並べる。ピン留めフィルターは対象を絞り込む機能とし、「すべて」の項目をピンの有無で分割しない。下書きは更新日時順の独立した区分、削除した項目は更新日時順の一覧に表示する。

並べ替えはSQLで対象全件へ適用し、その後で取得件数を制限する。初回は100件を取得し、「さらに表示」は上限を100件ずつ増やして先頭から再取得する。データが変わらない場合は、取得境界で重複や欠落を生じさせない。コピーや編集で順序が変わる場合は、現在の取得上限まで読み直す。

行にはタイトル、本文プレビュー、ピン状態を表示する。使用回数は並べ替えに用い、数値の比較を利用者へ要求する操作は設けない。

## 整理候補の表示

最終使用から720時間以上経過した未削除の保存済み項目には、「30日以上未使用」と最終使用日を行内に表示する。日付は利用者の暦と言語設定で表し、30日の判定には経過時間を用いる。

| 項目の状態 | 整理候補の扱い |
| --- | --- |
| 最終使用日時があり、720時間以上経過 | 表示する。ピン留めした項目も含む |
| 使用履歴がない、日時が未来、720時間未満 | 表示しない |
| 下書き、削除した項目 | 表示しない |

一覧の取得・再読込、アプリへの復帰、コピー・削除・復元後の再取得で評価時刻を更新する。コピーの使用記録が確定すると最終使用日時が更新され、再取得した行から補足が消える。

補足は手動整理の判断材料とする。削除は行のメニュー・長押し・スワイプで実行し、削除通知の取り消しと「削除した項目」からの復元を利用できる。自動削除と、整理候補だけの専用画面は提供しない。

## 保存するデータと整合性

SQLiteのschema version 2は、`snippets`に非負の使用回数`use_count`と、未設定を許す最終使用日時`last_used`を持つ。コピーごとの記録`snippet_uses`は、操作ID、対象スニペットのUUID、完了日時を保持する。操作IDはコピーが完了するたびに生成するUUIDであり、スニペット自身のUUIDとは異なる。

操作記録の挿入、使用回数の加算、最終使用日時の更新を一つの書込トランザクションで確定する。同じ操作ID・対象・日時の再試行は加算せず成功を返す。異なる内容で同じ操作IDを使った要求は拒否する。遅れて確定した記録で最終使用日時を過去へ戻さない。

使用記録は本文編集のrevisionと更新日時を変更しない。編集・ピン留め・削除・復元は使用履歴を保持し、完全削除は対象の操作記録も除去する。

schema version 1からの移行では、全項目を0回・日時未設定とする。更新日時から使用を推定しない。タイトル・本文の原文、UUID、ピン、削除状態、下書きを保持し、書込トランザクション内でversionを再確認して複数接続からの重複移行を防ぐ。

本体と共有拡張は、`SnippetStore`の書込接続でDBを作成・移行する。キーボード拡張はschema version 1と2を読み取るため、DBの移行を待たずに保存済み本文を利用できる。DBが存在しない場合は本体での保存を案内する。キーボードの並び順はピン優先、更新日時降順、UUID昇順とする。

## コピーと記録失敗からの回復

`LibraryModel.copy`は保存済み本文を読み、OSへコピーした後、使用記録を保存して一覧を再取得する。コピーの成功表示はOSへの書込完了を表す。使用記録の保存失敗を、本文のコピー失敗として表示しない。

コピー後に呼出元タスクがキャンセルされても、受理した使用記録の保存は試みる。記録失敗時は、コピー済みであることと「使用記録を再試行」を表示する。再試行は同じ操作IDの保存だけを行い、クリップボードへ再度書き込まない。対象が完全削除されている場合は再試行待ちを終了し、記録対象がないことを閉じられる説明として示す。

未確定の記録はモデルのメモリに保持する。OSクリップボードとSQLiteに共通のトランザクションはないため、コピー完了からDB確定までのプロセス終了による記録喪失は保証範囲外とする。DBに確定した回数・日時は再起動後も保持する。

操作記録の保持量はコピー成功回数に比例する。二重加算の判定に必要なため期限による削除は行わず、対象の完全削除に合わせて除去する。本文や端末情報を操作記録へ重複保存しない。

## 実装の責務

| 構成要素 | 責務 |
| --- | --- |
| `LibraryModel` | コピー、操作IDと日時の生成、未確定記録の保持、記録の再試行、一覧の再取得 |
| `LibraryEffects` | OSのクリップボードへ同期的に書き込む |
| `SnippetStore` / `SnippetCommands` | 保存要求の直列化、トランザクション、操作IDの照合、使用記録の確定 |
| `SnippetQueries` | 絞り込み、全体の並べ替え、取得件数の制限 |
| `SnippetSchema` | テーブル・索引と、原文を保持するversion移行 |
| `SnippetRowContent` / `LibraryScreen` | 整理候補の補足、項目操作、失敗の説明と回復操作 |

## 採用理由と評価条件

使用回数を全体の第一ソート条件とすることで、よく使う項目を先頭から選べる。ピン優先の区分は使用回数順を分断するため、ピン留めは絞り込みとして扱う。整理候補は項目の近くに補足し、一覧と手動整理を同じ導線で行えるようにする。操作IDの永続化は、回数だけの更新では区別できない再試行と別のコピーを判別するために採用する。

自動テストは、並び順と取得境界、原子的な更新、複数接続、同じ操作の再試行、原文を保持する移行、720時間の境界、キャンセル、記録失敗と完全削除からの回復を扱う。iOS 26.5の小画面では、ライト／ダーク、検索、コピー後の順位と補足、削除・復元を操作し、画像・動画で確認する。大量データの取得・コピー・スクロールは条件を固定して測定し、保存層の処理時間と画面応答の測定を区別する。
