# 対象を識別して操作し、失敗から回復するUI

一覧での利用と整理、下書き再開、編集の終了を対象にする。採用する画面はS01〜S07、部品は[C台帳](../components.md)に定める。本書はそれらの構成を選ぶ理由を説明する。

## 採用する構成

整理は行の可視メニューとジェスチャーの両方から実行できるようにする。長押し/スワイプだけの構成は密度を保てるが、知らない操作の発見に依存する。対象名・要約・日時・状態を示し、同名/無題でも対象を見分けられるようにする。

下書きは直近3件を通常一覧へ置き、残りは専用フィルターへ分ける。全下書きを先に並べる構成は再開に近い一方、保存済みの利用を遠ざける。保存済み全体は使用回数順の一集合とし、ピンは集合選択で扱う。

編集の終了は保存・下書き保持・破棄を区別する。明示終了で永続化の成功を待つことで、ジェスチャー終了直前の入力や保存失敗を扱える。失敗は入力を残し、競合時は別項目保存という回復手段を示す。

## 判断理由と評価条件

コピーや削除の成功は探索を中断しない短い通知、回復に操作が必要な失敗は残る表示、完全削除は対象を確かめる確認にする。同じ「結果」を一つの表示方式で処理しない。

色と動きは[共通原則](../foundations.md)・[表示固定](0002-fixed-interface.md)へ従う。状態は色だけで伝えない。初見の発見性、対象の取り違え、保持と確定の理解、失敗からの回復を[G課題](../audit.md)として評価する。実装されたことと利用者に伝わることを区別する。
