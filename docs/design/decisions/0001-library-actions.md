# 対象を識別して操作し、失敗から回復するUI

一覧での利用と整理、下書き再開、編集の終了を対象にする。採用する画面はS01〜S07、部品は[C台帳](../components.md)に定める。本書はそれらの構成を選ぶ理由を説明する。

## 採用する構成

整理は行の可視メニューとジェスチャーの両方から実行できるようにする。長押し/スワイプだけの構成は密度を保てるが、知らない操作の発見に依存する。対象名・要約・日時・状態を示し、同名/無題でも対象を見分けられるようにする。

下書きは直近1件をコンパクトな再開帯に置き、残りは件数付きの入口と専用フィルターへ分ける。全下書きを先に並べる構成は再開に近い一方、保存済みの利用を遠ざける。保存済み全体は使用回数順の一集合とし、ピンは集合選択で扱う。

編集の終了は保存・下書き保持・破棄を区別する。明示終了で永続化の成功を待つことで、ジェスチャー終了直前の入力や保存失敗を扱える。失敗は入力を残し、競合時は別項目保存という回復手段を示す。

## 判断理由と評価条件

コピーや削除の成功は探索を中断しない短い通知、回復に操作が必要な失敗は残る表示、完全削除は対象を確かめる確認にする。同じ「結果」を一つの表示方式で処理しない。

色と動きは[共通原則](../foundations.md)・[表示固定](0002-fixed-interface.md)へ従う。状態は色だけで伝えない。初見の発見性、対象の取り違え、保持と確定の理解、失敗からの回復を[G課題](../audit.md)として評価する。実装されたことと利用者に伝わることを区別する。

## 一覧からコピーまでの配置

S01・S02の代表画面を比較し、利用者が選んだ一覧中心の案を採用する。C01のボトムタブはネイティブのLiquid Glass、C09の作成ボタンは正円という指定に従う。SwiftUIの標準TabViewと検索roleを使い、素材・タブの動きはOSが所有する。

| 候補 | 利点 | 負担と判断 |
| --- | --- | --- |
| 一覧＋行コピー＋下部検索 | 保存済みを読み比べ、対象の横からコピーできる | 全文には編集を開く。利用者が代表画面を確認し採用 |
| 上部常設検索＋密な行 | 検索の入口を常に示せる | 上部への到達と要約の面積に負担があるため不採用 |
| 上部一覧＋下部全文 | 似た項目の全文を選択後に比較できる | 一覧の高さが減り、行タップの意味も変わるため不採用 |

F01〜F07・F09、R01〜R04・R07に対応する。フィルターの件数はページ内の件数ではなく同じDB snapshotの集合総数である。下書き再開帯では最新の1件を示し、複数件の識別は専用一覧へ移す。詳細な理由と評価条件はC04〜C12、未評価の到達性・密度・読み上げはG01・G02・G04・G06・G10・G13・G14を対象にする。プロトタイプへの肯定的なフィードバックは採用判断であり、探索速度・誤操作率の実測とは区別する。

## 操作配置と文字の統一

一覧・検索の右上にあった装飾アイコンを除き、見出しと補足で現在地を示す。作成・コピー・その他は右側に固定し、左右の切替設定・保存状態・配置分岐を持たない。利用者の指定に基づく簡素化であり、片手での到達性は引き続きG01・G14で評価する。

一覧・編集・説明画面の本文と見出しにはF03の共通文字スタイルを適用する。画面ごとに大きくしていた入力文字・説明文や追加行間を揃え、primary/secondary等の文字色は維持する。S01〜S05・S10、C02・C09〜C11・C21・C22・C36・C48・C49に対応する。狭幅の入力・折返し・説明末尾への到達と、図に添えた文の読みやすさを確認する。
