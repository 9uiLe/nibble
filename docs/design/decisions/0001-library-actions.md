# 対象を識別して操作し、失敗から回復するUI

## 目的と適用範囲

状態：採用。判断日：2026-09-17。判断者：nibble開発担当。

一覧・検索・編集・削除した項目で、利用者が対象を見分け、操作を発見し、結果と次の行動を理解できることを目的とする。対象はS01〜S06、C02〜C19・C21〜C25・C29・C33・C37〜C39、F02〜F09。監査のG01〜G11に対する採用判断を含む。

標準タブと検索、単一の一覧と3フィルター、ナビゲーションバー内の見出し、下部の作成、共通背景を使う。保存済みと下書きの区別、原文とUUID、非同期操作の完了、iOS 26.0以上の対応を契約とする。

## 採用する構成

| 領域 | 構成と理由 |
| --- | --- |
| 保存済みの行 | 内容、コピー、可視の「その他」を持つ。コピーは一度のタップ、整理は対象行のメニューから行う。長押しとスワイプも同じ操作へ接続する |
| 下書き | タイトル、無題なら本文先頭を名前として示し、更新時刻を補足する。一覧の「すべて」は直近3件と全下書きへの入口を持ち、保存済みの内容に到達できる高さを確保する |
| フィルター | 文字・塗り・枠の色と読み上げる選択状態を併用する。文字だけのラベルに一定の左右余白を設け、選択によって幅を変えない |
| 文字拡大 | 保存済みの内容と行の操作を縦に組み替える。内容の高さを増やし、記号は文字スタイルに従う。通常文字では左右設定をコピーの物理的な位置へ反映する |
| 空状態 | 作成可能な空の一覧では文言付き作成ボタンを唯一の作成入口とする。項目がある一覧では下部の＋を使う |
| 失敗 | 検索前案内や空状態より先に、失敗した処理と回復方法を表示する。読込失敗の「一覧を再読み込み」と、操作失敗の説明・閉じるを区別する |
| 完了と復旧 | 削除・復元の通知、復元ボタン、完全削除の確認に対象名を含める。通知の対象と取り消すUUIDを同じ記録で保持する |
| 編集 | 本文が必要な理由、末尾への追記、下書き保持による終了を明示する。進行表示は保存・保持・破棄を区別する |
| 外観 | 独自色にコントラスト強調の明暗両方の値を持たせ、状態は文字・形・読み上げでも伝える |

「その他」は整理操作の入口であり、毎回使うコピーをその中へ移さない。操作は標準ButtonとMenuを使い、削除はメニューの最後に置く。完全削除には対象名付きの確認を要求する。

## 候補と判断理由

| 選択 | 比較した案 | 採否と理由 |
| --- | --- | --- |
| 整理の入口 | 行の可視メニュー / 編集画面の操作 / 長押しのみ | 行のメニューを採用。編集の下書きを作らずに整理でき、ジェスチャーの知識に依存しない（R08・R16） |
| 行の密度 | 全文字サイズで横並び / 大きな文字で縦並び | 大きな文字で縦並び。操作領域が本文の幅を奪うことを避ける（R14） |
| 選択状態 | 色のみ / チェック / 標準segmented Picker | 色と塗りを採用。ラベルを文字中心にまとめ、横幅と装飾量を抑える。文字拡大は横スクロールで扱い、読み上げの選択状態は視覚表現と独立して伝える（R06・R16・R17） |
| 下書きの表示量 | 全件を先頭へ表示 / 直近3件と専用フィルター | 直近3件を採用。3は表示面積の製品予算であり、最適値の実証ではない。全件は下書きフィルターから取得する |
| 操作失敗の回復 | 全失敗に再試行 / 読込と操作を区別 | 処理を区別する。再取得を削除やコピーの再実行と誤認させず、入力と検索語を保持する（R13） |
| 編集終了 | 永続化前にスワイプ終了 / 明示終了して保持を待つ | 明示終了を採用。標準シートの終了期待より、最新入力の保持結果が分かることを優先し、終了方法を画面内で説明する（G09・R09） |

Apple HIGの可視の代替操作、Dynamic Type、問題に近い回復説明を適用する。フィルターの視覚的な選択は配色と塗りで示す製品判断とし、色の判別条件と読み上げは別に評価する。出典と適用条件は[根拠資料](../../../research/06-interface-design-evidence.md)に定義する。操作の発見性・取り違えの減少は製品仮説であり、実装した事実と利用者評価の成功を区別する。

## 状態と実装の所有者

`LibraryModel`は取得状態・操作失敗・通知と対象を所有する。再取得の成功によって無関係な操作失敗を消さない。`LibraryScreen`は表示優先度と配置を持ち、タスクの開始は`LibraryTaskOwner`へ渡す。`SnippetStore`は下書きの短い要約と更新日時を返し、全文は編集時に読む。

`EditorModel`は保存可能な入力と終了処理を所有する。本文の空白・改行を保存前に書き換えず、保存可否だけを判定する。共有拡張も共通エディターの説明と終了契約を使う。共有元からのデータ取得中の状態と取消はG12で独立して管理する。

## 評価条件

- 通常文字で、可視メニューからピン・解除・削除に到達できる。左右設定、検索結果からのコピー・編集が成立する。
- 無題3件・同名・長文の下書きを識別できる。20件の下書きがあっても「すべて」には3件と全件への入口を表示する。
- 空白検索中の失敗が見え、再読み込みと操作のやり直しを区別できる。検索語とUUIDを保つ。
- 2件を連続削除した通知の対象と取り消すUUIDが一致し、期限後は削除一覧で復元できる。完全削除の取消で内容を保つ。
- 本文なし・空白のみ・本文ありで保存可否と説明が一致する。保存・保持・破棄は成功後だけ終了する。
- iOS 26.5 Simulatorの標準文字・最大アクセシビリティ文字、狭幅、ライト・ダーク・コントラスト強調を確認する。画像・録画とAX情報の確認を、VoiceOver音声による評価と区別する。
- Releaseで基本操作・保存層・表示比較の回帰を検査する。要約取得とアプリサイズは同じ条件で比較し、操作動画の長さを応答性能の測定値にしない。

比較条件と対象ソース、実行結果は製品の検証記録へ残す。本文が操作に押し出される、対象名が識別に不足する、再開とコピーの到達性が悪化する場合は、表示件数・行構成・文言を再検討する。
