# 操作完了通知と削除の取り消し

nibbleは、文章をスニペットとして保存し、コピーして再利用するiOSアプリである。本体の一覧と検索では、コピー・削除・復元の結果を短時間表示する。利用者は通知を閉じずに次の操作へ進め、削除を誤った場合は通知から対象を復元できる。

対象は[画面構成](../screens.md)のS01一覧・S02検索と、[部品台帳](../components.md)のC01標準タブ・C09新規作成・C18完了通知・C19削除取り消し。要求は[Issue #26](https://github.com/9uiLe/nibble/issues/26)、実行結果と受け入れ状況は[検証記録](../../tab-accessory-validation.md)に定義する。

通知内容、操作、状態管理と、通常のタブ画面への配置を採用契約とする。検索入力中の配置は設計の未決定条件であり、本機能の受け入れにはその決定と実画面での確認を必要とする。

## 利用者へ伝える結果

| 成功した操作 | メッセージ | 対象名 | 通知内の操作 | 表示時間 |
| --- | --- | --- | --- | --- |
| 保存済み本文のコピー | コピーしました | なし | なし | 2秒 |
| スニペットの削除 | 削除しました | 削除した項目の名前 | 元に戻す | 6秒 |
| 通知からの削除取り消し | 元に戻しました | 復元した項目の名前 | なし | 2秒 |

コピーの成功はOSのクリップボード書込呼び出しが戻ったことを表し、削除と復元の成功は保存層の変更が確定したことを表す。通知の表示時間は処理の完了待ちに含めない。使用記録の保存が失敗した場合の説明と再試行は、[使用履歴の設計](0003-usage-order.md)に従う。

結果メッセージを主表示とし、対象名は補足の1行に収める。長い対象名は末尾を省略し、結果と取り消しボタンの領域を確保する。本文全体は通知に含めない。

## 画面と配置の責務

Tab Bar accessoryは、システムのタブバーに付随する補助表示領域である。通常のタブ画面では、この領域に通知を1件表示する。背景、タブバーとの間隔、表示・消去の遷移はOSが管理し、通知がない間は領域とタップ判定を解放する。

| 画面・状態 | 結果の表示と操作 |
| --- | --- |
| 一覧タブ・検索タブ | コピー・削除・削除取り消しをC18/C19の通知として扱う。検索入力中の配置は未決定条件に従う |
| 「削除した項目」シート | シート内の`LibraryNotice`で復元・完全削除を伝える |
| 編集シート・共有拡張・キーボード拡張 | 各画面が保存・利用の結果を管理する |
| 操作失敗・入力エラー | 理由と回復操作を持つエラー表示を使う |
| 完全削除などの確認 | 実行前に確認画面を表示する |

新規作成ボタンは一覧・検索画面の操作として配置し、通知部品に含めない。一覧の下部から新規作成、通知、タブバーの順に領域を確保する。通知がない場合はその領域を除き、末尾の項目までスクロールして操作できる構成にする。

通知を表示・更新・消去しても、検索語、フォーカス、フィルター、スクロール位置、編集セッションを作り直さない。保存データの更新に伴う並べ替えと、通知だけの表示更新を区別する。通知中も検索入力、コピー、スクロール、タブ切り替えを受け付ける。

## 表示する通知の状態

`LibraryNotifications`が、通知ID、発生元タブ、メッセージ、対象名、復元対象のUUID、復元中の状態を一つの値として保持する。通知IDは結果ごとに生成するUUIDであり、保存済み項目のUUIDとは別の識別子とする。同じメッセージでも新しい操作結果には新しい通知IDを付ける。

表示世代は、操作結果を表示できる画面の有効期間を識別する値である。操作開始時に発生元タブと表示世代を取得し、完了時に両方が現在の画面と一致する結果だけを受理する。

| 出来事 | 通知の扱い |
| --- | --- |
| 有効な画面で操作が成功 | 通知を設定し、画面に現れた時点で期限を開始する |
| 通知中に次の操作が成功 | メッセージ・対象名・復元対象をまとめて最新の通知へ置き換える |
| 同じ結果の操作を繰り返す | 新しい通知IDで表示時間を開始し直す |
| 期限に到達 | 期限の通知IDが現在のIDと一致する場合だけ消去する |
| タブ移動・シート表示・シーンの非アクティブ化 | 表示世代を更新し、通知と期限を終了する |
| 離脱した画面の操作が遅れて完了 | データの結果を保持し、通知は受理しない |
| タブ・シート・アプリへ戻る | 終了した通知を再表示しない |

シーンはアプリの一つの表示単位を指す。通知を消すことを理由にデータ操作を再実行したり、確定済みのコピー・削除・復元を取り消したりしない。通知履歴と待ち行列は持たない。

## 表示開始、期限、読み上げ

通知が実際に画面へ表示された時点で、単調増加時計による期限を確定する。同じ通知IDの再描画や表示タスクの再開始では、最初に決めた期限を使う。古い通知の期限処理は、新しい通知を消去できない。

初回表示で読み上げと触覚の発生番号を一度だけ更新する。結果と必要な対象名を読み上げ対象とし、省略前の対象名をアクセシビリティラベルに含める。「元に戻す」は独立したボタンとし、原則44×44pt以上の操作領域を確保する。

文字サイズ・太字・コントラストは[本体の固定表示方針](0002-fixed-interface.md)を適用し、配色はライト／ダークに従う。これらの表示方針と、読み上げラベルやボタンの意味情報を区別する。

期限タスクのキャンセルは正常な終了として扱う。それ以外のタイマー失敗は診断ログへ残し、現在の通知IDが一致する場合だけ消去する。

## 削除の取り消し

「元に戻す」は押した時点の通知IDを受け取る。管理者は現在表示しているIDと照合し、その通知が保持するUUIDだけを復元対象として渡す。復元中の同じ通知は操作を受理せず、ボタンを無効にする。

復元が成功したら、対象名付きの「元に戻しました」へ置き換える。失敗したら成功通知を出さず、理由と回復方法をエラー表示に残す。通知がまだ有効であれば復元中の状態を解除し、再試行できるようにする。

通知の期限後も、削除したスニペットは「削除した項目」から復元できる。通知の終了は完全削除を意味しない。

## 実装構成とOS対応

| 構成要素 | 責務 |
| --- | --- |
| `LibraryView` | タブ、シート、検索フォーカス、通知管理者を所有し、画面の有効期間と配置を管理する |
| `LibraryModel` | コピー・削除・復元を完了し、開始時の発生元・表示世代に対応する結果を渡す |
| `LibraryNotifications` | 通知の置換、表示世代、期限、一度だけの効果、復元対象の照合と重複防止 |
| `LibraryAccessory` | 結果と取り消しを表示し、表示開始と期限タスクを接続する |
| `LibraryTaskOwner` | 利用者操作の非同期処理を開始・所有し、モデルの完了を待つ |
| `LibraryScreen` | 一覧とエラー、新規作成を配置する |

最低対応OSはiOS 26.0とする。OSの利用条件だけで配置方式を選び、通知の有無によってTabView全体を条件分岐したり、表示のIDを変更したりしない。

| OS | 配置と非表示 |
| --- | --- |
| iOS 26.1以降 | SwiftUIの[`tabViewBottomAccessory(isEnabled:content:)`](https://developer.apple.com/documentation/swiftui/view/tabviewbottomaccessory%28isenabled%3Acontent%3A%29)で有無を制御する |
| iOS 26.0 | `LegacyLibraryAccessory`が公開UIKitの[`UITabBarController.bottomAccessory`](https://developer.apple.com/documentation/uikit/uitabbarcontroller/bottomaccessory)へ`UITabAccessory`を設定し、非表示時はnilにする |

26.0の接続部品はNavigationStack内の内容へ配置する。公開の親子関係からタブコントローラーへ接続し、通知のSwiftUIホストを子として保持する。取り外すのは自分が設定したaccessoryと子だけとする。ホストには本体と同じ表示設定を適用する。非公開APIやOS内部のクラス名による探索は使わない。

## 採用理由

システムの補助領域はタブとの配置と背景をOSへ委ねられ、新規作成から通知の責務を分離できる。各画面に独自の通知カードを積む方式は、通知と画面操作の領域をアプリ側で一括管理する必要がある。通常のタブ画面にはシステムのaccessoryを採用する。

26.0では、空のSwiftUI contentだけで領域の解放を保証する方式や、通知ごとにTabViewを作り直す方式を採用しない。公開UIKitへの接続をOS別の部品に閉じ込め、最低対応OSを引き上げる場合に除去できる構成とする。

## 未決定条件と受け入れ

検索入力中も、検索語とフォーカスを保持したまま結果を読み取れて、取り消しを操作できることを要求する。システムの検索表示がTab Bar accessoryを隠す場合の配置は未決定である。候補は検索中だけ検索欄の上に通知を置く構成とし、採用には配置契約の決定と実画面での確認を必要とする。この候補を実装済み・採用済みとは扱わない。

自動テストは、通知の原子的な置換、表示開始と期限、古い期限と新しい結果の競合、画面離脱後の完了、UUIDによる復元、重複操作、復元失敗を扱う。iOS 26.5 Simulatorでは、小画面、長い対象名、ライト／ダーク、連続コピー、削除取り消し、検索入力、タブ・シート・バックグラウンドの遷移を操作し、画像・動画で確認する。

最低対応OSへのAPI適合と、iOS 26.5での実行確認は区別する。UIKit接続部品を26.5で直接マウントした結果は26.0での実行を保証しない。未実施の環境・操作と機能全体の受け入れ状況は検証記録へ残す。
