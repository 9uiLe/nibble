# 0005：スニペットキーボード

状態：採用。設計基準日：2026-09-19。最低対応OS：iOS 26.0。

## 目的と提供範囲

nibbleのキーボードは、他アプリの入力欄で保存済みスニペットを選び、本文を直接挿入するための入力面である。タイトルから対象を識別し、行を1回タップして本文を入力先へ渡せることを優先する。全文を確認してから使いたい場合は、行末の「…」から詳細を開く。

キーボードは一覧、全文確認、挿入、コピー、ピン留めを提供する。作成・編集・検索・削除とキーボードの設定案内は本体アプリが担当する。表示対象は削除されていない保存済みスニペットで、下書きは含まない。独自の文字入力、カテゴリ、同期、データの複製は提供範囲に含めない。

画面はSwiftUI、入力先との接続とOS操作はUIKitで実装する。[画面構成のS09・S10](../design/screens.md#s09-スニペットキーボード)と[部品台帳のC45〜C48](../design/components.md#スニペットキーボード)がUIの構成単位である。利用手順は[MVP手順](../mvp.md#キーボードから使う)、実行結果と未確認事項は[検証記録](../keyboard-readability-validation.md)に定義する。

## 用語と操作

「一覧」はタイトル、本文の短いプレビュー、ピン状態を並べた画面、「詳細」は選択した1件のタイトルと全文を読む画面を指す。「入力先」はキーボードを表示しているアプリの入力欄である。「フルアクセス」は利用者がiOS設定でキーボードに与える権限で、コピーと共有データへのピン更新に必要となる。

| 操作 | 条件と結果 |
| --- | --- |
| 行のタイトル・本文プレビューをタップ | 本文を取得・照合し、入力先へ1回渡す。フルアクセスは不要 |
| 行末の「…」をタップ | 同じキーボード領域で詳細を開く。挿入・コピーは行わない |
| 詳細の「一覧に戻る」 | 選択中のフィルター、ページ、スクロール位置を保持した一覧を表示する |
| 詳細の「入力する」 | 本文を再取得・照合し、入力先へ1回渡して一覧へ戻る |
| 詳細の「コピー」 | フルアクセスを確認し、本文を端末内のクリップボードへ書く。詳細は開いたままとする |
| 詳細のピン留め／解除 | フルアクセスと選択時の更新番号を確認して保存する。詳細の状態と一覧へ結果を反映する |
| 「すべて／ピン留め」を切り替え | 選んだ集合の先頭ページを取得する |
| 前後のページへ移動 | 選択中の集合を50件単位で取得する。1ページだけの場合はページ操作を表示しない |
| 更新・キーボードの再表示 | 選択中のフィルターの先頭ページを再取得する |
| 地球儀・閉じる | OSのキーボード切替操作、キーボードを非表示にする操作を呼び出す |

挿入・コピーに使うのは保存済み本文の全文であり、一覧のプレビューではない。空白、改行、Unicodeを変換しない。

## レイアウトと操作の意味

### 一覧と詳細

| 部品 | 構成 | 配置理由 |
| --- | --- | --- |
| C45 対象選択 | 上段に「すべて／ピン留め」のコンパクトな2択セグメントと更新ボタン | 一覧の対象を示し、本文を読む領域を広く取る |
| C46 一覧 | 一つの角丸リストに行を並べ、薄い区切り線で分ける。各行はタイトル、1行の本文プレビュー、小さなピン印を持つ | タイトルの横幅を確保し、連続した面で項目を読み比べられるようにする |
| C46 行の操作 | タイトル・プレビュー領域の入力Buttonと、右端の「…」Buttonを横に並べる | 挿入と全文確認を独立した操作領域にする。Buttonの入れ子や親行のタップ処理は使わない |
| C46 詳細 | 上段に戻る・ピン、中央にスクロール可能なタイトルと全文、下段にコピーと青い「入力する」 | キーボード内で全文を読み、主操作の挿入へ進める。操作列は本文と一緒にスクロールさせない |
| C47 結果と補助操作 | 最下段に控えめなnibble表示、結果文、必要なページ操作、地球儀、閉じる | 結果文とブランド表示は同じ領域を使い、次の選択を遮らない |
| C48 利用案内 | 本体の設定から、追加手順、全文操作、権限、入力先の制約を読む | 設定の説明を読む場面と、入力する場面を分ける |

詳細の表示中も一覧のScrollViewを保持し、描画とタップ・読み上げの対象から外す。詳細を閉じると同じ一覧を再表示する。ピン操作で並び順や対象集合が変わった場合は、残っている項目の範囲で位置を保持する。

「すべて」が0件の場合は本体での保存を案内する。「ピン留め」が0件の場合は、「すべて」の「…」からピンを追加できることを案内する。読込中と読込失敗は空状態と区別する。全文の取得中・失敗時には詳細内に状態を示し、本文を使う操作を無効にする。

### 寸法・色・表示設定

キーボードの基準高は288pt、vertical size classがcompactの場合は196ptとする。高さ制約の優先度は750で、OSの必須制約を優先する。幅は拡張へ割り当てられた表示領域に合わせ、中央の一覧・全文領域が残りの高さを使う。

左右の外余白は10pt、行の左余白と詳細本文の内余白は12pt、リストの角丸は13ptを基準とする。行高は54pt以上、「…」は44×54pt、補助操作は44×44pt以上のタップ領域を持つ。セグメントの見た目がコンパクトでも、タップ領域の高さは44ptを確保する。

背景は`UIInputView.Style.keyboard`、SwiftUIホストは透明とする。リストと全文の面は`tertiarySystemBackground`、主文字はprimary、補助文字はsecondaryを使う。一覧のタイトルはmediumのsubheadline、プレビューはcaptionで、それぞれ1行とする。詳細ではheadlineのタイトルとbodyの全文を折り返して表示する。青は「入力する」と挿入後の行背景に使い、結果は文章でも伝える。

[固定表示方針](../design/decisions/0002-fixed-interface.md)を本体・共有拡張・キーボードに適用する。Dynamic Typeはlarge、太字設定とコントラスト設定は標準値に固定し、OSのライト／ダーク外観には追従する。画面幅と高さに応じて配置・折返し・スクロール領域を調整する。独自のアニメーションは使わない。

VoiceOverには操作名、対象名、選択状態、ピン状態を伝える。詳細を開くと「一覧に戻る」へ、閉じると呼出元の「…」へフォーカスを移す。呼出元が一覧にない場合は選択中のフィルターへ移す。結果文はannouncementとして読み上げる。

### 構成の選択理由

単一リストは、項目ごとのカードや2列タイルに比べて長いタイトルの表示幅と一覧の密度を確保しやすい。行の主領域を入力に割り当てることで、挿入のための専用ボタン幅を必要としない。「…」と詳細は、内容の確認とコピー・ピン操作を引き受ける。詳細をキーボード内の画面として構成すると、入力先との位置関係と拡張の高さを保ちながら操作できる。

この構成は、即時挿入と全文確認の誤操作、長い名前の識別、狭幅での操作到達性を評価対象とする。比較の根拠と利用者評価の仮説は[UI設計根拠](../../research/08-keyboard-interface.md)に定義する。

## 操作結果と失敗

| 操作 | 完了として扱う時点 | 表示 |
| --- | --- | --- |
| 挿入 | `textDocumentProxy.insertText`の呼出しが戻った時点 | 「入力先へ本文を渡しました」と対象行の短いハイライト |
| コピー | フルアクセスを確認したうえで`UIPasteboard.setItems`の呼出しが戻った時点 | 「コピーしました」 |
| ピン留め／解除 | DBの書込transactionがcommitした時点 | 「ピン留めしました」または「ピン留めを解除しました」 |

成功の結果文と挿入行のハイライトは2秒で消す。挿入APIは入力先の受理・保存結果を返さないため、通知は本文の受け渡しを表す。コピーは`localOnly`で書き込み、クリップボードの読取による事後照合は行わない。

権限不足、本文の変更・削除、入力位置の変更、読込・書込失敗は理由を表示し、成功のハイライトを出さない。失敗・権限案内には自動消去の期限を設けず、次の読込要求や利用操作などが通知を更新するまで表示する。権限不足ではコピー・ピン更新を実行しない。本文の変更・削除時は、一覧を更新して選び直すよう案内する。

## 構成と責務

| 所有者 | 責務 |
| --- | --- |
| `KeyboardViewController` | 入力先、権限、モデル、高さ、地球儀UIButtonを所有する。`KeyboardEffects`として挿入・コピー・閉じるを実行する |
| `KeyboardView` | 一覧・詳細・結果を配置する。読込・全文・通知期限をSwiftUI `.task`で、利用操作を`ViewTaskStore`で管理する |
| `KeyboardModel` | 要求世代、ページ、詳細1件分の本文、通知、操作IDを保持し、完了待ち可能な操作を提供する |
| `KeyboardReader` | actor内の短命な接続で一覧・本文を読み、ピン属性を更新する。モデルには`KeyboardReading`として渡す |
| `SnippetLocation` / `SnippetQueries` / `SQLiteDatabase` | App Group内の保存先、要約・原文の問い合わせ、SQLite接続とtransactionを提供する |

UIとOS操作はMainActor、DB処理はactorで行う。行はスニペットUUID、詳細の読込は開くたびに生成するUUIDで識別する。

## 共有データと読み取りの契約

正本はApp Group `group.nibble.9uiLe.com`の`Library/snippets.sqlite`、schema versionは1とする。本体が保存領域を準備し、キーボードはDBの作成・schema移行・別保存先へのfallbackを行わない。未準備、未知schema、アクセス不能は利用者に失敗として伝える。

一覧と本文には読取専用接続を使う。一覧はピン留め優先、更新日時の降順、UUIDの昇順で最大50件を表示する。51件まで問い合わせて続きの有無を判定する。要約にはUUID、タイトル、本文の先頭180文字、ピン状態、更新番号`revision`を含む。全文は詳細を開く、または挿入・コピーする1件だけ取得し、未削除とrevision一致を照合する。

ピン操作は`SQLITE_OPEN_READWRITE`で存在するDBだけを開く。単一の書込transaction内でUUID・revision・未削除を条件に`pinned`と`revision`を更新し、更新後の要約を返す。タイトル、本文、更新日時、下書きは変更しない。commit後に詳細と一覧の該当項目へ結果を反映し、同じフィルター・ページを再取得して並び順とページ境界を照合する。

書込接続は`SQLITE_FCNTL_PERSIST_WAL`でWAL・SHMを保持し、書込権限を持たない読取専用接続からも確定した更新を読めるようにする。

## 状態と操作の寿命

一覧の要求世代`loadID`と、同じ世代の読込実行を区別する`readID`を照合する。古い読込の完了・失敗は現在のページに反映しない。再表示・更新・フィルター変更は先頭ページを要求し、詳細からの復帰は元の要求を保持する。キーボードが非表示になるとページ、全文、通知を解放する。

挿入・コピー・ピンは共通タスクID`keyboard.use`を使う。`screenBound`で画面の寿命に合わせてキャンセルし、`ignoreNew`で処理中の重複開始を防ぐ。モデルも操作ID、表示中であること、要求世代を照合してから結果を反映する。

挿入では本文の取得前後で入力先のdocument identifierと選択位置の世代を照合する。コピーでは取得前後でフルアクセスを確認する。ピンでは権限確認後に書込を待ち、実際の共有領域へのアクセスはOSのsandbox制御に従う。commit済みの更新を後からのキャンセルで取り消さず、非表示・要求変更後には古い操作結果を表示しない。

詳細の読込は選択項目と詳細を開いたIDを照合する。同じ項目を閉じて再度開いても、前の読込結果を採用しない。期限付き通知は自身のIDを照合して消去し、古い期限処理が新しい通知を消さないようにする。

## 権限とOSの境界

拡張の`RequestsOpenAccess`はtrueとする。一覧・全文確認・挿入はフルアクセスなしで利用でき、コピーとピン更新は利用者の許可を必要とする。通信、入力履歴の保存、クリップボードの読取、入力欄の前後文脈取得は行わない。

`needsInputModeSwitchKey`がtrueの場合だけ地球儀を表示し、`handleInputModeList(from:with:)`へ接続する。閉じる操作は`dismissKeyboard()`を呼ぶ。OSが管理する音声入力、ホームインジケータ、セーフエリアを独自の部品・余白として複製しない。

secure入力、phonePad・namePhonePad、他社キーボードを禁止するアプリではOSの制御に従う。本体の利用案内で、キーボードの追加方法と利用できない入力欄を説明する。

## ビルドと評価

Bundle IDは`nibble.9uiLe.com.keyboard`、extension pointは`com.apple.keyboard-service`とする。最低iOS 26.0、Swift 6、strict concurrency complete、extension-safe APIを使用する。Tasking・AppMacrosと共有の保存コードを利用し、編集用StoreやRiveはリンクしない。

評価環境はXcode 26.5 / iOS 26.5 Simulatorとする。1タップ1挿入、「…」で挿入されないこと、長文末尾、詳細から戻る位置、ピン追加・解除と0件、権限不足、更新・ページ・切替・終了を確認する。狭幅・縦横・ライト／ダークと、OSの文字・太字・コントラスト設定変更時の固定表示を評価する。遅延・キャンセル・失敗・更新競合はモデルと保存層のテストで照合する。

VoiceOverの実操作、実機、性能計測は実施条件と結果を個別に記録する。設計条件や静的検査の成功を、動作確認の完了として扱わない。
