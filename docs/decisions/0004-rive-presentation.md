# Riveによる説明イラスト

判断日：2026-09-17。状態：採用。対象：iOS 26.0以上のnibble本体と、製品から独立した表示パッケージ。

## 目的と範囲

「nibbleについて」は、よく使う言葉を保存して再利用する道具の使い方を説明する。図は、ほかのアプリで選んだ文章をコピーし、nibbleへ保存する流れを補足する。文章で操作を伝え、短い図と動きでコピー元と保存先の関係を補足する。演出はクリップボード、保存データ、他アプリを操作しない。

説明文、読み上げ、失敗時の再試行はSwiftUIが持つ。図形、動き、演出内の状態遷移はRiveが持つ。この分担により、文字拡大や読み上げを保ち、図の制作と画面の実装を別々に扱える。読み込み中や失敗時にも文章を読めることを要件とする。

制作にはRMLとRive CLI、表示にはRive iOSの新Apple runtime APIとData Bindingを採用する。Legacy APIへの接続は設けない。アセットは2D図形とタイムラインで構成し、外部画像、フォントファイル、通信、Luauスクリプト、シェーダーを使用しない。Rive Editor、`.rev`、ログイン、Riveの署名サービスは制作・生成に必要ない。

## 用語と構成

| 用語 | この設計での意味 |
| --- | --- |
| RML / `.riv` | RMLは編集可能な制作ソース、`.riv`はアプリへ同梱する生成済みバイナリ |
| Artboard | 図形と座標系を持つ描画面 |
| State Machine | 演出の状態と、その間の遷移条件を定義する仕組み |
| View Model / Data Binding | 型付きの値とtriggerを通じて、ホストアプリと演出を接続する仕組み |
| Resource / Session | Resourceは読み込んだファイル、Sessionは一つの表示が所有する可変の再生状態 |
| ホスト | パッケージを利用し、アセットの意味と画面の振る舞いを決めるアプリ側のコード |

| 層 | 所有する責務 | 入口 |
| --- | --- | --- |
| 制作ソース | 図形、タイミング、状態遷移、Data Bindingの名前・型・初期値 | [アセットの制作と配布](../../app/Animations/README.md) |
| RivePresentation | ローカルファイルの読込、実ファイルの契約検査、独立したSessionの生成、表示と停止 | [パッケージの利用契約](../../app/Packages/RivePresentation/README.md) |
| AboutIllustration | 説明、配色、Reduce Motion、スクロール可視性、読み上げ、失敗時の回復 | [ホスト実装](../../app/Nibble/AboutIllustration.swift) |
| 生成検査 | 宣言済みアセットのソース・生成物のハッシュ、名前・型・参照、CLI版の照合 | [rive_assets.py](../../scripts/rive_assets.py) |

RivePresentationは製品名、アセット、色、文章、画面構成を持たない。新APIの`Rive`と`ViewModelInstance`を公開し、プロパティの各型やレンダラーを独自APIへ重複実装しない。他製品では、パッケージと依存を導入し、ホストが自身のアセットと接続契約を用意する。

## 資源、状態、実行の所有

`RiveResource.load(named:in:)`はWorkerとFileの生成を待つ。Workerはランタイム内の処理を担い、Fileが保持する。Resourceを機能の寿命で保持すれば、同じファイルの読み込みを再利用できる。`makeSession`は指定したArtboard、State Machine、View Modelのインスタンスを毎回生成する。一つのSessionを同時に二つの表示へ渡さない。

AboutはSessionをViewの`@State`で保持する。bodyの再評価、文字サイズ、外観の変更は再ロードの契機にしない。ロードは画面の`.task`が所有し、キャンセルされたロード結果を表示しない。Sessionを保持したままの一時的な離脱では再生位置を保つ。Viewの状態が破棄された後の再入場は、新しいSessionの初期状態から始める。アプリ全体に常駐するWorkerや無制限のキャッシュは設けない。

ロード、Sessionの生成、Data Bindingの操作はMainActorの条件に従う。ホストはasync APIの完了を直接awaitし、フレーム進行はRiveに任せる。Timer、DisplayLink、生Taskによる別の再生時計は追加しない。SwiftUI側の独自アニメーションはScopedAnimationが適用範囲を定め、キャンバス内の動きはRMLのタイムラインが定める。

`motionAllowed`はホストが渡す動作設定である。`active`はループ状態の出力で、画面外などで停止中もtrueを保つ。ホストはこの出力を購読せず、フレームごとのSwiftUI状態更新を行わない。表示上の完了を、保存やコピーなどの業務処理の成功判定に使わない。

## Aboutの表現と配置

UI設計の対象はS05（製品情報画面）、C36（説明文）、C44（説明イラスト）。導入文の直後、具体的な操作説明の前に図を置き、道具の用途から利用の流れへ読み進められる順序にする。透過背景の図は480:300の比率で本文幅の内側へ収め、本文と一緒にスクロールする。

主動作は「メモ画面の文章を選択し、コピーした複製をnibbleの一覧へ運び、保存する」。元の文章を残し、選択ハンドルとコピーメニューでコピーの起点を示す。複製は緩い弧を描き、既存の行は挿入位置を空ける。保存操作後にチェックと完了通知を出す。二つの枠は同じ端末内のアプリを並べた説明図であり、同期機能を表さない。

6.2秒周期で自動再生を繰り返し、利用者が再生操作を学ばずに流れを見られるようにする。完成図を保持してから次の説明へ戻す。図の下に「選ぶ → コピー → nibbleに保存」を置き、再生・停止ボタンは設けない。キャンバスはタッチを受けず、アクセシビリティツリーから除く。操作ラベルは図の部品としてベクター化し、意味の読み上げと文字拡大は隣接するSwiftUIのTextが担う。

### 停止と復帰

| 条件 | 動作と所有者 |
| --- | --- |
| 通常の表示 | RMLが自動ループする。ホストは別の再生時計や完了購読を持たない |
| スクロールで図の可視割合が10%未満 | ホストが停止を要求し、再表示時に同じ位置から続ける |
| Canvasの離脱、非アクティブ・バックグラウンド | Canvasが停止し、同じSessionで復帰する |
| Reduce Motionが有効 | RMLが完成図へ移る。途中で有効にしても静止した説明へ切り替わる |
| Reduce Motionを無効へ変更 | 先頭から自動ループを再開する |
| 読込失敗 | ホストが図記号、説明文、再読み込みボタンを表示する |

Reduce Motionは演出の状態、可視性とscenePhaseはフレーム進行を制御する。画面外・非アクティブ中の設定変更は、再表示時のフレーム評価で反映する。ループの注意喚起と描画負荷は評価対象とし、視界外では動作を止める。

### 外観の更新

ホストはライト、ダーク、コントラスト強調に応じて4色をData Bindingへ渡す。rive-ios 6.27.0では一時停止中の値変更だけでは描画が更新されないため、配色設定後に`renderingRevision`を増やす。Canvasは表示用Viewだけを作り直し、同じSessionを時間差0で描画する。File、Artboard、State Machine、View Modelと再生位置は保持する。

この処理は外観変更時の表示更新として使用する。通常のbody評価やフレームごとに番号を変えない。ランタイム更新時は、停止中の配色反映、位置保持、表示用Viewの再生成コストを再評価する。

## 採用理由と負担

| 選択肢 | 適性と負担 |
| --- | --- |
| 文章と静止したSF Symbols | 小さな実装で意味を説明できる。複製の軌道や時間差を示すには別の演出実装が必要 |
| SwiftUIで図と動きを制作 | 単純な状態変化に適する。複数図形のタイムラインと演出データもSwift側で設計・管理する必要がある |
| 動画 | 固定した演出の再生に適する。配色、任意の停止位置、Reduce Motion向けの静止図を別途管理する必要がある |
| Rive | ベクターの制作ソースと型付きの外部制御を分離できる。外部ランタイムの容量、描画資源、API更新への対応を引き受ける |

Riveを採用する理由は、制作ソースを再生成可能に保ち、演出とiOSの状態管理を接続契約で分けられることにある。理解しやすさと性能は評価対象とし、技術の採用だけで効果を保証しない。対象ソースの測定値、観測、未実施項目は[検証記録](../rive-validation.md)に置く。

## 配布、保守、受け入れ

CLI 1.0.4をNixの配布物ハッシュで、rive-ios 6.27.0をPackage.swiftのexact指定と共有Package.resolvedで固定する。これらは本構成の採用版であり、最新版の指定ではない。CLIによる制作と生成は公式のApple Silicon macOS版、iOSの実行検証はXcodeとiOS 26.5 Simulatorを使う。最低対応OSは26.0とする。

RiveRuntimeは本体だけにリンクし、通常起動で同梱Frameworkを解決できるrunpathを設定する。共有拡張にはリンクしない。配布物にはMITライセンスと同梱ライセンスを保持する。Riveの署名が不要なアセットでも、iOSアプリの署名・配布は[配布設計](0003-testflight-distribution.md)に従う。スクリプトやシェーダーの導入は、制作可否、実行条件、署名・公開条件を再評価する別の判断とする。

| 評価 | 確認する内容 |
| --- | --- |
| 生成と構造 | 固定CLIによる生成、ソースと出力の対応、名前・型・初期値の定義、実バイナリの接続契約 |
| iOS統合 | 独立したSession、通常起動、外部制御、失敗とキャンセル、停止と復帰 |
| 表現とアクセシビリティ | 図の関係と動き、停止中の配色、Reduce Motion、文字拡大、説明の読み上げ |
| 負担 | 同条件のアプリサイズ、対象環境での描画・応答コスト |

Ubuntu CIは生成契約とソース規約を検査する。画像の品質、iOSでの動作、描画性能はローカルの観測で評価する。依存更新時はCLIでの制作可否と対象ランタイムの実行可否を別々に確認し、上記の契約と検証をそろえる。
