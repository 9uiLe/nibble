# 保存・入力を伝える説明イラスト

nibbleの説明イラストは、文章を保存する操作と、保存した本文を入力先で利用する操作を伝える。どちらも原文を残して利用できることを示す。図を見なくても操作を理解できるよう、意味と読み上げは隣接する文章に持たせる。

| 画面・部品 | 伝える操作 | 配置 |
| --- | --- | --- |
| S05「nibbleについて」・C44 | 他アプリの文章を選択してコピーし、nibbleへ保存する | 導入文の直後。元の文章と保存先を二つのモバイル画面で示す |
| S10「nibbleキーボード」・C49 | 入力先でキーボードを切り替え、保存済みの行をタップして本文を挿入する | 導入文と追加手順の間。入力欄とキーボードを一つの画面内で上下に示す |

## 表現と配置の理由

保存の図は、文章選択、コピーメニュー、複製の移動、保存、完了を一周期で示す。元の文章を残し、保存先に項目が増えることで、複製を保存する関係を表す。

入力の図は360×320の描画面に、入力欄を上、キーボードを下として同時に配置する。入力に必要な領域を大きく見せ、小画面でも入力結果と保存済み本文を見比べられる構図とする。二つの端末を並べる構図ではアプリ間の移動に見え、縦長の端末全体を描く構図ではキーボードの文字が小さくなる。図は本文と一緒にスクロールし、標準の戻る操作を妨げない。

両図は紙の色、柔らかな輪郭、余白、控えめなタップ表示を共通にする。入力の図では、キーボードの選択状態と挿入結果に製品と同じ青を使う。キーボードの上部に表示対象の切替と更新、中段に単一リスト、下部に結果・キーボード切替・終了を配置する。操作と権限の意味は[キーボード設計](0005-snippet-keyboard.md)に従う。

### 入力の図の時間構成

一周期は8.4秒とし、切替・行の選択・挿入・結果確認を順に示す。

| 時点 | 表示と動作 | 目的 |
| --- | --- | --- |
| 開始〜約2.7秒 | 地球儀を長押しし、切替候補からnibbleを選ぶ | 入力先の画面にとどまってキーボードを切り替えることを示す |
| 約3.3秒 | 保存済み行の主領域をタップする | 全文確認用の「…」と、直接入力する領域を区別する |
| 約3.6秒 | 本文を入力欄へ一度に表示する | 一回のタップで本文全体を挿入する関係を示す |
| 挿入後〜6.8秒 | 入力結果と保存済み行を同時に表示する | 約3秒間、同じ本文が入力先と保存元に残ることを見比べられるようにする |
| 6.8秒以降〜次の周期 | 内容全体をフェードし、初期状態へ戻す | 本文だけを消して削除操作に見せず、次の説明へ移る |

行のハイライトと「本文を送りました」は、製品の挿入結果と同じく2秒間表示する。始点と終点の値・静止期間を揃え、周期境界で位置が飛ばないようにする。図の挿入操作は、コピー・ドラッグ・フルアクセスの許可を前提にしない。

自動ループにより、途中から見た場合にも説明の始点へ戻れる。静止図は描画負荷と注意の分散を抑えられる一方、操作の順序を別の表現で補う必要がある。自動再生による理解度と読書への干渉は利用者評価で確認する。

## 制作・表示・画面の分担

| 所有者 | 責務 |
| --- | --- |
| RML | 図形、タイムライン、状態遷移、型付きData Bindingを定義する編集の正本 |
| 生成物とmanifest | Bundleへ同梱する`.riv`と、制作ソース・生成物・接続名・型の対応 |
| RivePresentation | ファイルの再利用、接続契約の検査、表示ごとのSession、Canvasの停止と再描画 |
| SwiftUIのホスト | Sessionの寿命、配色、可視性、再生方針、説明文、読込失敗時の表示と再試行 |

Sessionは一つの表示が所有する再生状態で、別の表示とは共有しない。接続名・型・初期値・状態遷移は[アセット手順](../../app/Animations/README.md)、汎用APIの契約は[RivePresentation](../../app/Packages/RivePresentation/README.md)を参照する。

## 状態と寿命

ホストはViewのtaskからファイルの読込とSession生成を待ち、取消済みの結果を表示しない。同じ表示の再描画ではSessionを保持し、画面を開き直した表示には独立したSessionを生成する。

nibbleは[表示固定方針](../design/decisions/0002-fixed-interface.md)に従い、演出を選ぶ`motionAllowed`をtrueに固定する。可視性はフレーム進行の停止条件として扱い、図の可視部分が10%未満、Viewの離脱、sceneの非アクティブ状態では進行を止める。表示へ戻った同じSessionは保持した再生位置から進む。

ライト／ダークの色はホストからData Bindingへ渡す。停止中の配色変更は描画更新番号でCanvasへ反映し、Sessionの再生位置は保持する。

図は操作を受けず、保存・コピー・入力を行う製品モデルへ接続しない。演出状態の`active`を製品操作の成否へ転用しない。図自体はアクセシビリティの読み上げ対象から外し、隣接Textが操作順、原文保持、入力先への反映確認を伝える。読込中と失敗時も文章を表示し、失敗時には再読み込みボタンを提供する。

## 採用理由と再利用

図形と時間をRML、画面状態をSwiftUI、両者の受け渡しを型付きData Bindingに分担する。RivePresentationは製品パスに依存せず、利用する製品がアセット・ホスト方針・依存lock・runtime同梱を用意する。iOSの接続にはApple runtime APIを用いる。

## 保守と受け入れ

制作ソース・生成物・manifestを一組で更新する。構造検査と実バイナリの接続テストに加え、画像、複数周期、停止と復帰、配色、読込失敗からの回復を確認する。CLIのviewport指定は実際の出力寸法で確かめる。

依存は互換性・ライセンス・toolchain・runtime容量を確認して固定する。描画負荷は[性能手順](../performance-verification.md)、操作は[MVP手順](../mvp.md)で評価する。CLIの処理時間、設計値、生成の成功は、iOSの描画性能を証明するものとして扱わない。観測と未実施条件は対象ソースを持つ検証記録へ残す。
