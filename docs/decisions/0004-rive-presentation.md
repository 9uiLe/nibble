# Riveによる利用説明の設計

判断日：2026-09-18。状態：採用。対象：iOS 26.0以上のnibble本体と、独立した表示パッケージRivePresentation。

## 目的

「nibbleについて」では、ほかのアプリの文章をコピーし、nibbleに保存する流れを図と動きで伝える。コピー元の文章が残ることと、複製が保存先へ届くことを一続きの演出にする。利用者は再生操作を覚える必要がなく、文章を読む途中からでも繰り返しを見られる。

操作手順とデータの扱いはSwiftUIの文章で説明する。アニメーションはその補足であり、読み込み中、失敗時、動きを減らす設定でも説明を読める。図に登場するボタンやカードは説明用の図形で、クリップボード・保存データ・他アプリを操作しない。

## 画面と演出

対象は[画面S05](../design/screens.md#s05-nibbleについて)、説明文C36、説明イラストC44である。導入文、イラスト、具体的な操作説明の順に置き、道具の用途から使い方へ読み進められる構成にする。図は本文幅に収まる480:300の比率と透過背景を持ち、本文と一緒にスクロールする。

| 段階 | 表現 | 伝える意味 |
| --- | --- | --- |
| 選ぶ | 左のメモ画面に選択範囲とハンドルを示す | コピーする文章を特定する |
| コピーする | コピーメニューを示し、複製を持ち上げる | 元の文章を保持したまま複製を作る |
| 保存先へ運ぶ | 複製が緩い弧を描き、右のnibbleの既存行が場所を空ける | コピー元と保存先の関係、追加される位置を示す |
| 保存する | 保存操作の後にチェックと「保存しました」を示す | 操作と結果の順序を伝える |
| 完成図を保持する | 保存先のカードを落ち着かせてから次の周期へ戻る | 結果を見届ける時間を確保する |

二つの枠は同じ端末で使うアプリを並べた説明図である。端末間の同期や、アプリをまたぐドラッグ操作の手順を表すものではない。

主動作は5.4秒までに収束し、全体は6.2秒周期で自動再生する。周期の境界では説明の開始位置へ戻る。再生・停止ボタンは設けず、図の下に「選ぶ → コピー → nibbleに保存」を置く。時間と軌道は製品の演出値であり、操作の所要時間を表さない。

図はタッチと読み上げの対象から除き、隣接するSwiftUIのTextが意味の読み上げとDynamic Typeを担う。図中の短い操作ラベルはベクター輪郭として保持する。読み込み中は図記号、失敗時は図記号と再読み込みボタンを表示し、説明文の位置と内容を保つ。

## 構成と責務

制作にはRMLとRive CLI、iOSにはrive-iosのApple runtime API（`Worker`、`File`、`Rive`、`ViewModelInstance`）とData Bindingを使う。このAPI世代で接続を統一し、Legacy APIとState Machineの旧inputsは使用しない。

| 用語 | 意味 |
| --- | --- |
| RML / `.riv` | RMLは編集可能な制作ソース、`.riv`はアプリへ同梱する生成済みバイナリ |
| Artboard | 図形と座標系を持つ描画面 |
| State Machine | 演出の状態と遷移条件を定義する仕組み |
| View Model / Data Binding | 演出の型付きデータと、ホストとの値の受渡し。アプリの業務モデルとは別のもの |
| Resource / Session | Resourceは読み込んだファイル、Sessionは一つの表示が所有する可変の再生状態 |
| ホスト | アセットの意味、画面での配置、外部から渡す値を決めるアプリ側のコード |

| 層 | 責務 | 契約の所在 |
| --- | --- | --- |
| 制作ソース | 図形、時間、状態遷移、プロパティの名前・型・初期値 | [アセットの制作と配布](../../app/Animations/README.md) |
| RivePresentation | ローカルファイルの読込、接続契約の検査、独立したSessionの生成、表示と停止 | [パッケージの利用契約](../../app/Packages/RivePresentation/README.md) |
| AboutIllustration | Sessionの寿命、配色、Reduce Motion、スクロール可視性、説明、回復 | [ホスト実装](../../app/Nibble/AboutIllustration.swift) |
| 生成検査 | 登録した制作ソースと生成物の対応、RMLの接続契約、CLI版の照合 | [rive_assets.py](../../scripts/rive_assets.py) |

RivePresentationは製品名、アセット、配色、文章を持たない。ランタイムの`Rive`と`ViewModelInstance`を公開し、プロパティ操作やレンダラーを独自APIで重複して包まない。他製品への導入では、パッケージと依存を移し、製品側にアセットとホストを用意する。

## 資源と実行の所有

ロードとSession生成はMainActor上のasync APIを直接awaitする。ResourceはFileを、FileはWorkerを保持する。同じファイルを複数の表示で使う場合はResourceを機能の寿命で再利用し、各表示には独立したArtboard・State Machine・View Model instanceを持つSessionを作る。一つのSessionを二つの表示へ同時に渡さない。

AboutIllustrationは画面の`.task`でロードし、キャンセルされていない結果を`@State`に保持する。bodyの再評価や外観・文字サイズの変更では再ロードしない。Sessionが生存する一時離脱では再生位置を保ち、Viewの状態が破棄された後は新しいSessionの初期状態から始める。アプリ全体に常駐するWorkerや無制限のキャッシュは設けない。

Riveがフレーム進行を所有し、ホストは別のTimer・DisplayLink・生Taskで再生時計を作らない。SwiftUI側の独自アニメーションはScopedAnimation、キャンバス内の時間はRMLが管理する。演出内の完了表示を、コピーや保存の業務処理の成功判定に使わない。

## 状態と表示の契約

演出は自動ループの`CopyAndSave`と静止した完成図の`Overview`を持つ。ホストはReduce Motionの設定を`motionAllowed`へ渡す。`active`は選択されている演出状態を示す出力で、フレームが停止していてもループ状態ならtrueを保つ。AboutIllustrationはこの出力を購読せず、フレーム進行に伴うSwiftUI状態更新を行わない。

| 条件 | 振る舞い |
| --- | --- |
| Reduce Motion無効で入場 | CopyAndSaveの先頭から自動ループする |
| Reduce Motion有効で入場、または途中で有効化 | Overviewの完成図へ移る |
| Reduce Motionを無効化 | CopyAndSaveの先頭から自動ループを始める |
| 図の可視割合が10%未満 | ホストがCanvasへフレーム停止を要求する |
| Canvasが離脱、アプリが非アクティブまたはバックグラウンド | Canvasがフレーム進行を止める |
| フレーム停止の条件がすべて解除 | 同じSessionの位置から進める |
| 読込失敗 | ホストが説明と再読み込み手段を提供する |

Reduce Motionは演出の状態、可視性とscenePhaseはフレーム進行を制御する。停止中の設定変更は、次のフレーム評価で状態遷移へ反映する。名前・型・初期値・更新方向の詳細は[アセットの接続契約](../../app/Animations/README.md#接続契約)を正とする。

### 配色と停止中の描画

ホストはライト・ダーク・コントラスト強調に応じて`paper`、`ink`、`accent`、`muted`を渡す。色の役割はアセット、環境ごとの値はホストが所有する。透過背景には画面の背景面を使用する。

rive-ios 6.27.0では、停止中にData Bindingの色を変えるだけでは描画が更新されない。ホストは配色設定後に`renderingRevision`を増やし、Canvasの表示用Viewだけを再生成する。同じSessionを時間差0で描画するため、ファイル、演出状態、再生位置を保持できる。通常のbody評価やフレームごとには番号を変えない。

## 採用理由と制約

| 選択肢 | 適性と負担 |
| --- | --- |
| 文章と静止したSF Symbols | 小さな実装で意味を伝えられる。複製の軌道や時間差を示すには動きの実装が必要 |
| SwiftUIで図と動きを制作 | 単純な状態変化に適する。複数図形のタイムラインもSwift側で管理する必要がある |
| 動画 | 固定した演出の再生に適する。配色や静止した完成図を別途管理する必要がある |
| Rive | 制作ソースと型付きの外部制御を分離できる。ランタイム容量、描画資源、依存更新への対応が必要 |

再生成可能なベクター表現とiOSの状態管理を分けるためRiveを採用する。動きが理解を助ける効果と、繰り返しが読書を妨げる可能性は利用者評価の対象とする。容量・描画負荷は対象環境で測り、技術の採用だけで効果や性能を保証しない。

アセットは2D図形とタイムラインで構成する。外部画像、フォントファイル、通信、Luauスクリプト、シェーダーを使用しない。Rive CLIで制作・プレビュー・生成が完結し、Editor、`.rev`、Riveログイン、Riveの署名サービスは不要である。iOSアプリの署名と配布は[TestFlight配布設計](0003-testflight-distribution.md)に従う。

## 保守と受け入れ

Rive CLI 1.0.4はNixの配布物ハッシュ、rive-ios 6.27.0はPackage.swiftのexact指定と共有Package.resolvedで固定する。これらは採用版であり、最新版という意味ではない。CLIはApple Silicon macOS、iOSの実行検証はXcodeとiOS 26.5 Simulatorを使用する。最低対応OSは26.0である。

RiveRuntimeは本体に同梱・リンクし、通常起動で解決できるFramework探索経路を設定する。共有拡張にはリンクしない。配布物にはMITライセンスと同梱ライセンスを保持する。

| 評価対象 | 受け入れ条件 |
| --- | --- |
| 生成・構造 | 固定CLIで生成でき、ソースと出力が対応し、実バイナリが接続契約を満たす |
| 表現 | 選択・複製・保存の関係、複数周期、収束と周期境界を画像と再生で確認できる |
| iOS統合 | 通常起動、独立したSession、設定変更、停止・復帰、失敗・キャンセルが契約に従う |
| 利用可能性 | 読み込み状態にかかわらず説明を読め、外観・文字拡大・Reduce Motionに対応する |
| 負担 | 同条件の容量、描画・応答コストと未測定項目を記録する |

Ubuntu CIは生成契約とソース・文書の整合を検査する。iOS動作と視覚品質はローカルで評価し、対象ソース・観測・失敗・限界を[検証記録](../rive-validation.md)に置く。

依存更新時はCLIでの制作可否と対象ランタイムでの実行可否を別々に確認する。所有関係、MainActor条件、Data Binding、停止中の描画と位置保持、容量・描画コストを再評価する。スクリプトやシェーダーの導入、API世代や最低OSの変更は別の採用判断を必要とする。
