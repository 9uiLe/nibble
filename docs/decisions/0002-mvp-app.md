# 0002：nibble MVPの構成

- 状態：採用（MVP）
- 決定日：2026-09-13
- 最低対応OS：iOS 26.0
- 実行評価：iOS 26.5 Simulator。MVPの作業範囲では実機検証を省略する

## 目的と範囲

メッセージの定型文、住所、Webフォームに使う短いテキストを、探してコピーし、入力先へ貼り付ける往復を提供する。本文の正確さ、少ない操作、入力を妨げない保存と検索、編集の中断からの復旧を優先する。

MVPは日本語UIのiPhoneアプリとShare Extensionで構成する。本体は作成・編集・検索・ピン留め・コピー・削除と復元、共有拡張はテキストとURLの取り込みを担当する。本体の一覧・作成画面にはURLから遷移でき、標準のShortcutsアクション「URLを開く」から呼び出す。

キーボード拡張、Widget、Controls、同期、アカウント、rich text、変数展開、AI、課金はMVPに含めない。入力先へのペーストは利用者が行う。対象アプリによる共有・ペーストの制約を超えて直接挿入できるとは扱わない。

## UIとデータフロー

一覧と検索を1画面にまとめ、各行には本文のプレビューとコピーボタンを置く。行をタップすると編集、長押しまたはスワイプでピン留め・削除ができる。コピーは元の一覧位置を保ち、短い通知と触覚で完了を知らせる。削除は復元できる保存状態への変更とし、完全削除には確認を求める。

編集画面は任意のタイトルと本文を持ち、明示的な保存で確定する。入力領域を固定の高さへ押し込まず、ページ全体をスクロールする。閉じる操作で下書きを保持し、本体から再開できる。共有拡張でも同じ編集・保存処理を使う。

| 構成 | 責務と境界 |
| --- | --- |
| SwiftUIのView | 表示、フォーカス、シート、標準メニュー・スクロール・Dynamic Type |
| `LibraryModel` / `EditorModel` | MainActor上のUI状態、検索要求の世代管理、保存・復旧・通知 |
| `SnippetStore` actor | SQLite接続、検索、transaction、競合判定、下書きの順序、永続化。UIとは値型だけを渡す |
| `Snippet` / `Draft` | 原文、安定したUUID、保存revision、下書きsequence |
| Share Extension | 選択されたテキストまたはURLを読み、利用者の保存操作で同じストアに登録 |
| URL / 標準のShortcuts | 一覧・作成のナビゲーション。本文や削除指示をURLに含めない |

Swift language modeは6、strict concurrencyはcomplete、default isolationはnonisolatedとする。UIをMainActorへ明示隔離し、SQLite処理は専用actor内で実行する。transactionは中断点を持たない。

## 保存と検索

Apple同梱SQLiteを使用する。`group.dev.nibble.app`のApp Group領域に本体と共有拡張のデータベースを置き、各プロセスのactorが個別の接続を持つ。WAL、`synchronous=FULL`、2秒のbusy timeoutを指定し、書込競合やI/O失敗をUIへ返す。保存エラー時に空のストアへ切り替えたり、既存DBを削除したりしない。

schema version 1は`snippets`と`drafts`で構成する。起動時は`user_version`を検査し、未知の新しい版を拒否する。将来の変更ではtransaction内の明示migrationと旧版fixtureを用意する。

| データ | 契約 |
| --- | --- |
| スニペット | UUID、任意タイトル、本文、pin、revision、更新日時、削除状態 |
| 原文 | 保存・コピーでは空白、改行、タブ、Unicodeをそのまま保持する |
| 検索 | タイトルと本文からNFC・日本語localeのcase/width foldingを生成して保存。1文字からの部分一致。`%`や`_`はワイルドカードにしない。かな/カナ、清音/濁音は区別 |
| 一覧 | ピン留め優先、更新日時降順、UUIDで同順時の順序を固定。最初の100件と180文字のプレビューを取得し、必要に応じ100件ずつ増やす |
| 編集競合 | 読込revisionに一致する更新だけを許可。異なる場合は下書きを保持し、新しい項目として保存できる |
| 下書き | 各編集のUUIDとsequenceを持つ。古いsequenceの書込を拒否。保存・破棄後の遅れた書込で下書きを再生成しない |
| 削除 | 一覧・通常検索・コピーから除外し、専用画面から復元。自動消去なし。完全削除は該当下書きも除去する |
| 入力上限 | タイトル512 UTF-8 bytes、本文1,000,000 bytes。空白だけの本文は保存しない。失敗時は編集内容を保持 |

検索キーの生成は保存時に行い、入力のたびに全本文を正規化しない。検索はactor内で実行し、UIには制限した行だけを渡す。古い検索結果が遅れて返っても、最新の要求を上書きしない。

## 比較候補と採用理由

| 選択 | 比較と理由 | 見直す条件 |
| --- | --- | --- |
| SwiftUI + Observation | 一覧・入力・シート・アクセシビリティを標準部品で組み合わせられる。UIKit全面実装より状態更新と表示の記述を小さく保つ。共有拡張の入口だけUIKitを使う | IME・フォーカス・表示に標準部品では解決できない問題がある場合 |
| SQLite | 本体と共有拡張の書込、revision付き更新、下書きとのatomicな確定、短い日本語検索を単一の明示transactionで表現できる。SwiftData/Core Dataに比べSQLとmigrationの保守は必要だが、共有・競合の境界を直接検査できる | ストア規模、同期、migrationの複雑さが増えた場合 |
| 保存済み検索キー + `instr` | trigram MATCHの1〜2文字制約を避け、原文保持と単純な部分一致を両立する。FTSの派生index管理を持たない | 想定件数で検索の遅延が増える、ランキングや高度な検索が必要になる場合 |
| Share Extension | 共有を提供するアプリから、本体へ移動せず内容を保存できる | 対象hostの共有形式や必要な取り込み機能が増える場合 |
| ショートカットの標準URLアクション | 本体の一覧・作成へのナビゲーションを提供する。AppShortcutsProviderによる自動登録は26.5 Simulatorで実行エラーを観測したためMVPでは採用しない。アプリ起動時にシステム側の登録更新を待たない | App Intentsの実行・登録を安定して検証できる場合 |
| ローカル保存 | アカウント・通信待ち・同期競合を日常操作の前提にしない | 複数端末の利用が製品価値に必要と判断された場合 |

研究の比較結果は[保存・検索・復旧](../../research/experiments/ios-26-5-validation.md)、公開APIの根拠は[呼び出し導線](../../research/01-invocation-and-platform.md)を参照する。研究用の全件MainActor処理や画面配置は製品の実装に含めない。

## 保護と運用

保存先ディレクトリとDBにはData Protectionのcompleteを指定する。コピーには`localOnly`を指定する。アプリは利用者の指示なしにpasteboardを読み取らず、入力時は標準のPasteButtonを使う。本文をログ・検索公開・analyticsへ送らない。データ収集・tracking・第三者SDKなしのPrivacy Manifestを本体と共有拡張に含める。

Data Protectionの実機ロック時の挙動、Handoff、実機の応答・描画、署名配布と審査は今回の検証対象に含めない。Simulatorで得た測定値を実機性能の保証にしない。配布時は本体と共有拡張に同じDeveloper TeamとApp Groupを設定し、配布物に含むAPI・宣言・署名を点検する。

補助ツールはリポジトリのNix環境を使用する。アプリ依存の追加はなく、Apple SDKのみでビルドする。共通検査はUbuntu CI、ビルド・テスト・操作・撮影はローカルMacで実行する。[MVPの操作と検証](../mvp.md)に設定・コマンド・証跡を記録する。
